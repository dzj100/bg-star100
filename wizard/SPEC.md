# 《巫师牌》Wizard — SPEC

3~6 人吃墩预判桌游。每轮先看手牌与王牌**预判**自己会赢几墩，再逐墩争夺——
说得准比赢得多更值钱。

当前版本：**人机版**（1 名真人 + 2~5 名 AI，总人数 3~6 可选）。
后续规划：联机版（复用 `online-boilerplate/`，见 §11）。

---

## 1. 组件与编码

| 组件 | 数量 |
|---|---|
| 红 / 黄 / 蓝 / 绿 各 1~13 | 52 |
| 巫师（Wizard） | 4 |
| 小丑（Jester） | 4 |
| **合计** | **60** |

- **卡牌编码**（`game.js` 单一来源，序列化紧凑、可排序）：
  `0..51` = 彩色（`c = id / 13 | 0`，`r = id % 13 + 1`）、`52..55` = 巫师、`56..59` = 小丑。
- **色盲冗余**：四色各配一枚形符（**红 ◆ / 黄 ★ / 蓝 ▲ / 绿 ■**），牌面、王牌横幅、
  座位徽章、日志文案一律「色名 + 形符」成对出现，绝不只靠颜色。
  红用**菱形**而不是圆点——象牙白牌面上一个红圆点会读成日本国旗。
- 每轮结束后**全部 60 张回收重洗**，轮与轮之间没有残留状态（指示牌也收回）。

## 2. 轮次表

每轮每人发**轮次号**张手牌，因此一局的最大轮数由 60 张整除决定：

| 人数 | 轮数 | 每轮手牌 1..R | 全局总墩数 |
|---|---|---|---|
| 3 | 20 | 1..20 | 210 |
| 4 | 15 | 1..15 | 120 |
| 5 | 12 | 1..12 | 78 |
| 6 | 10 | 1..10 | 55 |

**最后一轮**（3 人第 20 轮 / 4 人第 15 轮 / 5 人第 12 轮 / 6 人第 10 轮）60 张全部发完，
牌堆为空 → **没有指示牌 → 本轮无王牌**。

## 3. 规则

### 3.1 每轮流程

```
重洗 60 张 → 每人发 k 张（k = 轮次号）→ 剩余 60 − N×k 张
      → 从剩余牌堆顶翻 1 张指示牌（剩余为 0 时不翻）
      → 【指示牌裁定】彩色 → 该色为王牌
                     巫师 → 先手看完手牌后指定一色（必须红黄蓝绿）
                     小丑 → 本轮无王牌
      → 全员预判（0..k，公开）→ 打 k 个回合 → 本轮计分
```

- **发牌在前、翻牌在后**：指示牌是巫师时必须「先手看完自己手牌之后」选色，
  所以手牌必须先到手（见 §3.6 决策记录）。
- 轮内**不再摸牌**，手牌只会被打出。
- 预判宣布顺序：**从先手起、沿座位序顺时针**依次公开（后宣布的人能听到前面的数字）。

### 3.2 先手

| 时机 | 先手是谁 |
|---|---|
| 第 1 轮第一回合 | **随机**一名玩家（发牌后即定，因为选色需要） |
| 第 r 轮（r ≥ 2）第一回合 | **上一轮最后一墩的赢家** |
| 轮内后续回合 | **上一墩的赢家** |

### 3.3 出牌与跟色

- 先手：任意打出一张手牌（允许巫师 / 小丑）。
- 跟牌：**手牌有先手色 ⇔ 必须跟先手色**（跟哪张不限）；没有该色则可出任意牌。
- **巫师与小丑永远可出**，不受跟色义务约束（有先手色时也可以直接甩巫师 / 小丑）。
- 先手打的是巫师 / 小丑 → 所有人**任意**出牌。

### 3.4 得墩判定（严格依序）

1. 场上有**巫师** → **第一个**打出巫师者赢。
2. 场上无巫师、有**王牌色**的牌 → 王牌中**数字最大**者赢。
3. 无巫师、无王牌：先手是彩色牌 → **先手色中数字最大**者赢（先手自己必在集合内）。
4. 无巫师、无王牌：先手是**小丑** → 其后**第一张彩色牌的颜色**成为本墩跟色，
   该色中数字最大者赢；若**全是小丑** → **第一个**小丑（即先手）赢。

- 小丑**永不赢**（唯一例外：全小丑）。
- 按 1→4 短路，前一条命中就停：有巫师时不看王牌，有王牌时不看跟色。

### 3.5 计分

- **墩** = 本轮实际赢下的回合数（0..k）。
- 预判**精确命中**：`20 + 10 × 墩`（预判 0 且赢 0 墩也是 +20）。
- 预判**未命中**：`−10 × |预判 − 墩|`（可为负，累加后总分可为负）。
- 全局排名按总分降序；并列同名次。

### 3.6 决策记录

| 议题 | 裁定 | 来源 |
|---|---|---|
| 第 2 轮起的先手 | **上一轮最后一墩的赢家** | 用户确认 |
| 先手小丑、无巫师无王牌、场上有彩色牌 | **第一张彩色牌定跟色，该色最大者赢** | 用户确认 |
| AI 难度 | 先做**一档「正常」**，分档留到后续迭代 | 用户确认 |
| 发牌 / 翻指示牌顺序 | **先发牌、再翻牌**（巫师指示牌要求先手先看手牌） | 推定（用户原文「每轮开始前翻开」按此落地） |
| 第 1 轮先手确定时机 | **发牌后立即随机**（不晚于翻牌——巫师指示牌要先手选色） | 推定 |
| 轮内每墩先手 | **上一墩赢家**（吃墩惯例） | 推定 |
| 每轮是否重洗 | **重洗全部 60 张**（官方规则；「最后一轮全部发完」必然先回收） | 推定 |
| 预判范围 | `0..k` 闭区间，所有人可见 | 用户文档 |

## 4. 对局流程状态机

```
menu ──开始──▶ setup ──开桌──▶ ┌─ round ─────────────────────────────────┐
                               │ deal → trump（翻牌/选色）→ bid           │
                               │      → ( play → trickResolve ) × k       │
                               │      → roundSummary ──确认──┐            │
                               └─────────────────────────────┘  r < R 重进
                                          │ r == R（或全员看完成绩）
                                          ▼
                                        over（排名 + 冠军演出）
```

- `phase`：`deal | trump | bid | play | trick | rshow | over`（引擎侧），
  存档 `stage` 额外区分 `setup | game | over`（见 §8.5）。
- 结算演出与「确认」闸门沿用仓库惯例：**结果先落盘、演出后开演**；
  `roundSummary` 卡片不吃「点背景关闭」，确认是流程的一半（同 ticket-collector）。

## 5. 版面与视觉

### 5.1 世界坐标与缩放

- 虚拟世界 `360 × 640`（纵向）。`#stage` 尺寸由 `fitStage()` 按
  `k = min(wrapW/360, wrapH/640)` 写死，等比内缩、居中留边；`--wu` = `k` px。
- 台外界面（顶栏 / 手牌操作条 / 弹层 / 结算页）不进世界坐标，直接 CSS 像素排版。
- **两条可读性地板**（沿用仓库铁律）：
  - 台内（吃 `--wu` 的世界元素）：字号 **≥ 6.4 世界单位**；
  - 台外（CSS 层）：字号 **≥ 12px**。
- 桌面宽屏：舞台照旧居中，两侧以黑蓝岩底填充；窄至 320px 宽仍等比缩放。

### 5.2 椭圆环座位

- 玩家 `i`（0 = 真人，1..N−1 = AI）在环上的参数角：
  `φ_i = 90° + i × 360°/N`（屏幕坐标 y 向下）。
  `pos_i = 环心 + (rx·cosφ, ry·sinφ)`，起点色值（实现期可微调）：
  环心 `(180, 296)`、`rx = 138`、`ry = 148`。
- 由此得到顺时针座位序：**下（你）→ 左 → 左上 → 上 → 右上 → 右**，
  即「下家在你的左手边」，与出牌方向一致。
- 中心是**黑曜石椭圆桌**（金 × 红双滚边，取自盒面配色；桌面中央铺一块
  发光的青蓝色石面，照盒面「发光的青蓝色地面」调），trick 槽位在：
  `slot_i = 环心 + 0.42 × (rx·cosφ, ry·sinφ)`。
  打出的牌**一律正立**放在各自槽位里（不再按座位旋转——上家视角的倒立牌
  在手机上只会读反），数字字号保证手机上一眼可读。
- 舞台**左上角是道具角**（桌面之外）：**牌库**（左位，发牌/翻牌动效起点）与**指示牌**
  （紧邻牌库右侧：上方「指示牌」小签、下方状态药丸「王牌 红 ◆」/「无王牌」/「先手正在选色…」），
  翻牌动效即「从牌库顶翻开、落在旁边」。桌面只留中央 trick 区，不再摆道具。

### 5.3 卡牌

| 用途 | 尺寸（世界单位） | 说明 |
|---|---|---|
| 手牌 | 46 × 64 | 底部扇形，点选抬起 |
| Trick 牌 | 40 × 56 | 环心四周各自的槽位 |
| 指示牌 | 40 × 56 | 舞台左上道具角常驻（牌库右侧） |
| 牌库 | 40 × 56 × 3 张叠 | 道具角左位；实体卡背朝上（与对手手牌同一套画法）+ 剩余数徽章，见底时整摞淡出 |
| 对手牌背 | 20 × 28 × 3 张叠 | 加「×k」计数徽章 |

- 牌面：暖象牙底 + 深墨字；左上角「数字 + 形符」双编码，正中大号数字；
  彩色牌描边取色。
- **巫师牌**：墨黑底 + 金纹 + 白描边（暗桌上保证可辨），巫师帽 + 星点；
  **小丑牌**：玫红底，小丑帽 + 铃铛。两种特殊牌在 trick 区另有金/铃铛角标，暗场也一眼可辨。
- **手牌压叠**：`step = min(30, (300 − 46) / (n − 1))`，最多 20 张（3 人第 20 轮）；
  每张微旋转排成扇形（总摆幅 ≤ ±24°）。点选 → 抬起 14 单位 + 放大 1.12 + 金晕，
  同屏在手牌上方浮出**预览条**（选中牌放大渲染 + 出牌 / 取消按钮）。
  **外圈封边**：旋转轴在底边中点，倾角 θ 使最低角比牌底再低 `(46/2)·sinθ`（±22° 时 ≈ 8.6 单位）——
  边缘下压量 `edge²·7` 以此为上限，大牌量（n ≥ 10）时外角不许被 `#stage` 的 overflow 裁掉。
- **打出后收拢**：一张牌打出后，剩余手牌**立刻重排**（按新的 n 重新等距展开并居中），
  靠 `.hc` 自带的 `transform` 过渡滑向新位——原来那张的坑不留空位。
- **合法性可视化**：轮到你时——合法牌全亮（金晕 + 浮起微动效）；
  非法牌**不压暗**（保牌面可读），只是不可抬起（光标 not-allowed）；
  若因「必须跟色」被锁住，手牌旁亮一枚「必须跟 红 ◆」提示条；
  点击非法牌 → 这张牌**飞向椭圆桌面再弹回手里** + 台词气泡。
  先手轮次（任意出）不出现跟色提示。
- 手牌自动排序：小丑 → 红/黄/蓝/绿各按 1..13 → 巫师。

### 5.4 座位芯片（HUD）

每个座位一枚玻璃质感胶囊，随座位锚定（上方座位挂头顶、左右座位挂外侧）：

```
[头像帽] 名字            ← 小巫帽头像（座位色）
  预 2  ·  墩 1          ← 两枚大徽章：本轮预判 / 本轮已赢（0..k，实时）
  总分 120               ← 实时总分
```

- **预判徽章**（用户要求显眼）：宣布后点亮显示数字；未宣布显示「…」；
  无王牌轮整枚外套一圈哑灰环（这轮没有王牌可依，更难拿）。
- **已赢徽章**（用户要求显眼）：每收一墩 +1（punch + 小光点从 trick 区飘来）；
  三态配色——未达标（白）/ **恰好达标（金，命中反馈）** / 超标（哑灰，每多 1 墩都是 −10）。
- **轮到的玩家**：芯片金边呼吸光；**本轮先手**：芯片角上一枚小皇冠。
- 分数变化用滚动计数；预判/已赢/总分三个数字的字号是芯片里最大的三档（先于装饰）。
- 3 人第 20 轮 k = 20 时两枚徽章仍是两位数（不换布局，只换字宽）。

### 5.5 配色（对照实体盒面）

整体语言取自实体盒：**黑蓝图底 + 蓝钢结构滚边 + 橙红行动色 + 中央青蓝发光石面 + 白字红描边标题 + 四色符号点缀**。

界面（首页 / 配置页 / 弹窗）统一走**黑蓝红**：红 = 行动色（主按钮 / 选中 / 焦点 / 当前行），
蓝 = 结构色（弹层滚边 / 面板底 / 次级按钮）；**金只留给牌面与「命中」语义**（命中徽章 / +分 / 赢牌金光），
界面滚边不再用金。

**扁平铁律：界面壳一律纯色填充**（顶栏 / HUD / 弹层卡片 / 按钮 / 行条都用 solid，不用 `linear-gradient`）；

### 5.6 计分榜（表格，用户指定新增）

**一张表格记满每一轮**。数据源唯一：`WZ.scoreTable(S)`（由 `S.hist` + 实时总分现算，
不另存副本——账目对不上时就说明有一处写错了）。

```
        你     学徒   术士   占星
第 1 轮  +20   +30    −10    +30
第 2 轮  +40     0    −20    +20
…
总分    120    90    −10    150
```

- **打开方式**：顶栏「计分榜」按钮 → 弹层（随时可开，含对局中）；每轮结算卡的底部
  与终局页内嵌**同一张表**（结算卡是缩略版：只带本轮行与总分行，行逐行亮分完才揭）。
- 行 = 轮次 1..R，列 = 玩家（座位序）。
- **单元格 = 得分 + 预判数 + 实际数**：得分是主角（大字，正绿 / 负红 / 0 灰，
  **命中时用金色**代替绿色——命中与否一眼扫出来，不再单独点印）；
  下方一行小字「预 2 · 实 2」（窄屏 320px 上自动折成上下两行，字号守 12px 地板，得分永远最大）。
- 底行「总分」加粗大字 + 金底，实时更新；当前轮高亮行，弹层打开时自动滚到它。
- 3 人 20 轮时表体滚动、表头吸附；6 人局窄屏按列均分。

## 6. 演出与音效

### 6.1 事件分级

| 事件 | 分级 | trauma | hitStop | 组合 |
|---|---|---|---|---|
| 发牌 | small × N·k | — | — | 逐张飞牌（stagger 预算 2.2s 封顶）+ 落桌轻响 |
| 翻指示牌 | medium | 0.18 | 40 | 3D 翻面 + 彩色 = 桌面色光晕漫开 / 巫师 = 金闪 / 小丑 = 铃铛颤音 |
| 选色（巫师指示） | medium | — | — | 先手座位金光 + 四色转盘（真人）/ 气泡宣布（AI） |
| 预判宣布 | small × N | — | — | 气泡 pop + 芯片数字更新；精确命中历史可回看 |
| 出牌 | small × N | 巫师 0.16 | 30 | 弧线飞牌 280ms + 落桌 squash 微弹 + 一记顶帧；出巫师加金色星屑与琶音，出小丑铃铛颤音 |
| 得墩 | medium | — | — | 赢牌金晕浮起、其余压暗后退 → 收拢成墩飞向赢家 + 「+1 墩」数字跳 |
| 本轮结算 | large | — | — | 逐行亮分（预判 vs 实际）：行依次淡入 + 分数滚动 → 行满后揭计分榜 |
| 最后一轮 | large | 0.45 | — | 「无王牌 · 决战轮」横幅 + 熔岩闪屏 |
| 终局排名 | large | 冠军 0.35 | — | 逐名揭晓（行淡入 + 分数滚动）+ 冠军金屑 / 「冠军」浮字 / 闪屏 / 横幅 |

### 6.2 节奏三旋钮（沿用仓库约定，别合并）

- `PACE`：演出基础节奏；结算四步（得墩收拢 / 本轮结算 / 终局）走慢放档 `SLOW = 0.4`。
- `SPEED`：顶栏「快进」×3，跨轮保留。
- `rate()` 统一乘进 `fxClock`（`vdt / fxWait / bubble` 同一把尺子），
  玩家一按快进立即夺回控制权。
- `hitStop` 是**真实毫秒**的一记顶帧（`fxHold` 乘过 `rate()` 补偿）：不管 0.4 慢放还是 ×3 快进，
  冻的都是 30 / 40 / 45ms 的真实时间 —— 曾经不补偿，SLOW 档下 45ms 会冻成 112ms 的真卡顿。
- `prefers-reduced-motion` → `fxOn = false`：发牌 / 翻牌 / 飞行全部折成立即到位，
  只剩状态更新与数字滚动。
- 音频：WebAudio 合成、缺上下文按需补建（续玩不经过菜单也要有声）、挂起唤醒补发、同名限流（同 ticket-collector 的 `SFX` 契约）。

### 6.3 音效清单（合成器）

发牌轻响 · 翻牌 whoosh · 气泡 pop · 出牌 slap · 得墩上行双音 · 巫师高频琶音 ·
小丑铃铛 · 非法操作低鸣 · 本轮结算短号 · 终局长号 · 按钮点按。

## 7. AI 设计（normal 档）

AI **只读公开信息**（自己的手牌、已打出的牌、公开预判、座位/轮次），rng 注入保证可复现。

### 7.1 预判（估算 + 公开修正）

```
牌力表（估「期望赢墩」，逐张累加）:
  巫师                      +1.00 / 张
  王牌色 r ≥ 11             +0.90
  王牌色 r 8..10            +0.65
  王牌色 r 4..7             +0.45
  王牌色 r 1..3             +0.30
  非王牌 A(13)（该色长度≥3） +0.55 ；长度≤2 时 +0.45
  非王牌 12                 +0.40
  非王牌 11                 +0.30
  短套加成：每个「非王牌色且该色 ≤1 张」+0.20（唯一的空门 / 单张可王吃）
  小丑                       0（弃牌垫子）
无王牌轮（小丑指示 / 最后一轮）:
  去掉王牌行；非王牌 13 → +0.70、12 → +0.50、11 → +0.35
整数化: est 距 x.5 超过 0.15 时四舍五入；落在边缘带时 rng 决定进/退
公开修正: 轮到自己宣布时，已公布预判合计 S：
          if S + est > k + 0.5 且 est ≥ 1 → est − = 1（避免总和明显溢出）
落盘: clamp(round(est), 0, k)
```

### 7.2 王牌照选色（AI 是先手且翻出巫师时）

对四色打分：`count(色) + 0.5 × count(该色 r ≥ 10) + 0.3 × (巫师数 × 0.5)`，
取最高；并列取「该色数字和」更大的颜色。选色后亮气泡宣布「王牌 → 蓝 ▲」。

### 7.3 出牌策略

三种模式由 `need = 预判 − 已赢墩`、`remain = 剩余回合数（含当前）` 决定：

| 模式 | 条件 | 策略 |
|---|---|---|
| MUST | `need ≥ remain` | 必须全赢：能压就压——出「恰好能赢的最低牌」；压不过 → 出最低合法牌保留火力 |
| DUCK | `need ≤ 0` | 已达标：出**不会赢**的最低合法牌（小丑优先，其次小牌）；若所有合法牌都会赢 → 出最低 |
| NEUTRAL | 其余 | 便宜能赢就赢（赢的代价 ≤ 阈值），否则放水 |

- 领出：MUST 出最强（王牌 A / 巫师按需）；DUCK 出最低非巫师牌；NEUTRAL 出最长非王牌色的最小牌。
- 跟牌：在合法集合内按「当前 trick 场上最佳」实时判定（谁能赢这一墩）；
  王牌计数（13 − 已见 − 指示牌）用于判断「我这张王牌现在最大吗」。
- **记牌（normal 级）**：维护公开牌史（每墩每人的出牌），只用于两项判断——
  剩余王牌数量、跟色色里还没出现的高牌。
- 非法零容忍：非法决策一律断言失败（引擎兜底 + 测试全量模拟）。

## 8. 技术方案

### 8.1 文件结构与依赖方向

```
wizard/
  SPEC.md       本文件
  index.html    三屏骨架（封面 / 设置 / 对局）+ 弹层 + 手牌操作条
  style.css     全部样式
  game.js       纯规则引擎 + 版面几何    → window.WZ + module.exports（不碰 DOM、无 Math.random）
  ai.js         AI 策略（只读引擎状态 + 公开牌史）→ window.WZAI + module.exports
  render.js     UI + fx 引擎 + 演出编排  → window.WZUI
  audio.js      WebAudio 合成音效        → window.WZSFX
  test-core.js  node 无头：规则边界 + AI 合法率 + 全量模拟
  test-shot.js  Playwright 390×844 走查 + 截图
  shots/        截图存档
```

依赖方向严格单向：`game.js ← ai.js ← render.js`；`audio.js` 独立。

### 8.2 引擎接口（`WZ`）

```js
WZ.COLORS / WZ.CN / WZ.GLYPH             // 色名、中文、形符
WZ.card(id) -> { id, kind:'color'|'wizard'|'jester', color?, rank? }
WZ.label(id) -> '红 7' | '巫师' | '小丑'
WZ.roundsFor(N) -> 20|15|12|10
WZ.newGame({ N, humanName, humanAvatar, seed }) -> S
WZ.startRound(S, rng) -> ev   // 发牌 + 翻指示牌（发牌在前）
WZ.chooseTrump(S, pid, color) -> ev     // 指示牌为巫师时（先手）
WZ.placeBid(S, pid, n) -> ev            // 0..k
WZ.legalPlays(S, pid) -> [id]
WZ.isLegal(S, pid, id) -> bool
WZ.playCard(S, pid, id) -> ev           // 非法即抛（调用前必须过 legalPlays）
WZ.trickWinner(S) -> { pid, kind }      // 纯函数，§3.4 的唯一实现
WZ.resolveTrick(S) -> ev                // 收墩、计数、定下一墩先手
WZ.endRound(S) -> ev                    // 计分 rows + totals + 下一轮先手
WZ.checkEnd(S) -> bool
WZ.rank(S) -> [{ pid, total, place, tied }]
WZ.scoreTable(S) -> { rounds:[{ r, pts:[..], totals:[..] }] }   // 计分榜唯一数据源（§5.6）
WZ.validate(S) -> { ok, errs }          // 牌数守恒 / 手牌+桌面+牌堆=60 等不变量
WZ.seeded(seed)                          // mulberry32（state/set 存取档，同仓库约定）
```

**事件表**（演出层只消费事件，不重算规则）：

```js
startRound  → { k, leader, deal:[{pid, n}], indicator: id|null,
                trump: {mode:'color',color} | {mode:'none'} | {mode:'choose'} }
chooseTrump → { pid, color, trump:{mode:'color',color} }
placeBid    → { pid, n }
playCard    → { pid, card }
resolveTrick→ { plays:[{pid,card}], winner, kind:'wizard'|'trump'|'led'|'jesterLed'|'jesterAll' }
endRound    → { rows:[{pid,bid,won,pts,exact}], totals:[{pid,score}], leaderNext }
```

### 8.3 状态结构

```js
S = {
  v:1, N, rounds, round, k, phase,        // 'deal'|'trump'|'bid'|'play'|'trick'|'rshow'|'over'
  players: [{ pid, name, ai, avatar, hand:[id], bid:null, won:0, score:0 }],
  leader, turn, trumps:{ mode:'color'|'none'|'choose', color:null },
  indicator: id|null, deck: [id],          // deck = 发牌与翻指示牌后的剩余
  table: [{ pid, card }],                  // 本墩已出的牌（按顺序）
  bidQueue: [pid],                         // 待宣布预判的顺序
  played: [[id]],                          // 公开牌史（逐墩、逐张），AI 与复盘共用
  hist: [{ round, rows, tricks }],         // 已完成轮次存档
}
```

- 牌一律存 **id 数组**（60 张守恒易验证、序列化紧凑），不展开成对象。
- 随机只经 rng；存档存 rng **内部状态**而非种子（同仓库约定，避免读档后随机流重播）。

### 8.4 性能预算

1. 稳态节点 ≈ 桌 + 6 座位 + 手牌 ≤ 20 + trick ≤ 6 + 牌背叠 18 + 指示牌 + fx ≤ 24，
   峰值在发牌（60 张同时飞上限）→ 发牌用 `chunked(list, 4)` 排队。
2. 只动 `transform / opacity`；`left/top` 仅在 `spawn` 写一次；禁 `filter / backdrop-filter` 动画。
3. `#table` 静态层只建一次；结算 / 弹层全在 CSS 层。
4. 死锁红线、补间锚点红线、`clearFx` 落点红线 —— 沿用仓库 §7.6 三条（同一套 fx 引擎契约）。
5. 走位/飞行速度与 `rate()` 解耦：时长参数只吃演出毫秒，传入前不再除一次 `rate()`。

### 8.5 存档 / 日志 / 设置

- **存档**：`localStorage` 单键 `wz.save.v1`：
  `{ v:1, t, stage:'setup'|'game'|'over', seed, rng, speed, sfx, S, draft, log }`。
  - `stage:'game'` 的档在任意 phase 读回；**结算先落盘再演出**（同仓库惯例）。
  - 读档恢复：手牌、桌面、预判、分数原样；轮到谁就从谁继续；AI 思考不重演。
  - 写盘时机：每次发牌 / 预判 / 出牌 / 收墩 / 结算；失败静默吞。
  - 逃生口：日志面板底部「清空存档并回到封面」。
- **日志**：环形缓冲 300 条，类型 `sys/deal/trump/bid/play/trick/round/err`，
  支持倒序查看 + 复制（`HH:MM:SS [R3/play] 你：出 红 7`）。
  **隐私无碍**（单人 vs AI），出牌即记，不需延迟。
  顶栏下方常驻一条**最新日志横条**（时间 + 正文，随类型着色），点它开日志面板。
- **设置**：音效开关、快进档（1×/3×）在顶栏；动画跟随系统 `prefers-reduced-motion`。
- **弹层**：规则 / 日志 / 本轮明细点背景关；**总结算卡片不吃点背景关闭**（它是流程的一半）；
  **预判面板可收起**（面板外暗底 / 「先看桌面」按钮），收起后点底部提示条再展开。
- **顶栏**：`第 r/R 轮` + 王牌小徽章 + 「规则 / 计分榜 / 快进」，下方日志横条。
  （轮次号即每人张数，不再单列「每人 k 张」小字；该信息在预判面板副题里仍有。）
  **单行铁律**：390px 下最宽一刻（两位数轮次 + 彩色药丸）五件合计 ≈ 321px
  （`gap 3` + 按钮内边距 8），折行即挤掉舞台 —— 顶栏高度一变，舞台由 ResizeObserver 跟着重新适配。

### 8.6 测试

**`node test-core.js`** —— 纯逻辑：

- 牌堆守恒：60 张、四色齐全、8 张特殊牌；`validate` 往返。
- 轮次：`roundsFor` 20/15/12/10；每轮发牌张数 = N·k；最后一轮 `indicator === null`。
- 得墩判定全案例：巫师优先（多巫师取第一）、王牌压跟色、跟色内比大小、
  **先手小丑 + 第一张彩色定色**、**全小丑取先手**、先手彩色无人跟色（先手赢）、
  王牌色 = 跟色同色、小丑永不赢。
- 合法性：有跟色必须跟；巫师 / 小丑豁免；先手巫师 / 小丑 → 全合法；无跟色任意。
- 计分：精确命中（含 0 预判 +20）、未命中正负差、总分可负、并列名次。
- 先手链：第 1 轮随机（seeded 可复现）、第 2 轮起 = 上一轮最后一墩赢家、轮内逐墩传递。
- **全量模拟**：N=3..6 × 每档 ≥ 20 个种子，AI 全自动跑完整局——
  每墩恰 N 张、全场出牌数 = 60·…、每人每轮 `won ≤ k`、无非法出牌（引擎断言 + AI 自检）、
  同种子完全可复现（含 AI 决策）。
- AI 统计 sanity：命中率落在 30%~70%（实测 ≈ 44%）；**座位均分对称**（对称策略不应有「先手位优势」，
  实测 20 种子下极差 ≤ 60）。注意均分本身不是 0 —— 精确命中 +20 是正和结构（4~6 人局全 AI 均分为正），
  3 人局因 k 大、罚分重为负；预判分布无 0..k 越界。

**`node test-shot.js`** —— Playwright 390×844：

## 9. AI 与演出的公平性红线

- AI 任何时刻**不得读取**真人手牌；决策只喂 `S.players[me].hand + played + 公开预判`。
- 演出层不得在「真人还没预判」时展示 AI 的预判（先手起顺时针宣布，轮到你才 unlock 输入）。
- 日志 / 结算明细不含任何未公开信息（本作无隐藏信息，除手牌）。

## 10. 交互细节备忘（实现时逐条落地）

1. 你的回合进场：座位光晕 + 手牌「可选高亮」+ 合法牌浮起 2 单位微动效（一次性，不常驻）。
2. 双击 / 再次点选已抬起的牌 = 快速出牌（省一次确认）；预览条也有「出牌」大按钮。
3. 预判面板：**纯素面**——只有 0..k 的数字芯片（两行内自适应）与确认按钮，
   不显示已宣布合计、不给建议值（用户已确认；与实体桌一致）。
   **面板可收起看桌面**（点「先看桌面」或面板外暗底），收起后点底部
   「轮到你预判 · 点这里继续」提示条再展开。
4. 全 AI 宣布期间允许点「快进」；宣布事件串行但可被加速度吞并。
5. 收墩后：赢家芯片徽章 punch + 小气团（2~3 个 CSS 点）从墩位飘向赢家。
6. 本轮结算行：`预判 2 · 实际 2 · +40 ✓` / `预判 3 · 实际 1 · −20 ✗`，
   ✓ 行金边金分、✗ 行素面（图标 + 颜色双编码，无盖章演出）；卡片底部内嵌**小计分榜**
   （本轮行 + 总分行，见 §5.6），行逐行亮分完才揭；终局页摊开完整表。
7. 终局排名行：名次大数字 + 名字 + 总分；冠军行金底 + 逐名揭晓时的冠军演出
   （金屑 / 「冠军」浮字 / 闪屏 / 横幅）。
8. 文案风格：术语统一「预判 / 墩 / 王牌 / 先手」；不用「庄家」。
9. 全部界面文案中文；段与段之间不出现英文（除标题 Wizard）。
