# 《夺狗囧事》桌游助手 - 产品规格说明书

## 1. 项目概述
纯单文件 HTML 实现的《夺狗囧事》桌游流程助手，替代实体卡牌，管理游戏状态、引导回合流程、自动判定胜负。

- **技术形态**：单文件 `index.html`（内联 CSS + JS），零依赖，双击即可运行
- **适配**：移动端优先，支持竖屏操作；桌面端兼容
- **存储**：localStorage 已暂时禁用（每次刷新从初始状态开始）

---

## 2. 核心规则

### 2.1 游戏目标
- 累计获得 **2次成功** 即可获胜
- 累计 **3次失败** 则出局
- 多人同时达成2次成功则 **共同获胜**
- 仅剩1名玩家未出局时，该玩家获胜

### 2.2 玩家数量
2~5人

### 2.3 卡牌
- 每位玩家持有5张牌，编号1~5
- 三态：背面 / 🐶 / ❌️
- ⭐️ 不是卡牌状态，是独立的领袖标记，显示在玩家行标签旁

### 2.4 游戏流程循环

#### 阶段一：藏狗
1. 按玩家序号依次行动
2. 每位玩家秘密将🐶藏在5张牌中的1张，其余为❌️
3. 点击【玩家X行动】按钮后弹出藏狗弹窗
4. 选中牌显示🐶，其余显示❌️，可切换选择
5. 点击【确认】后回到桌面阵容，底部按钮切换为下一位玩家
6. 最后一人确认后，进入搜查阶段

#### 阶段二：搜查
1. 显示桌面阵容 + 门栏（5扇门，编号1~5）+ 底部【玩家X行动】按钮
2. 当前领袖行高亮 + ⭐️标记
3. **领袖首次行动**：必须选择1扇门打开（强制选门弹窗）
4. **后续所有玩家行动**（包括领袖再次轮到时）均为4选1：

| 操作 | 效果 |
|------|------|
| OK | 记录该非领袖玩家当前操作为OK（若后续选择其他操作则OK记录被移除），传递到下一位玩家 |
| 再开一扇 | 从未开启的门中选1扇打开，并夺取⭐️领袖标记，okPlayers全部清空 |
| 重新开门 | 关闭当前所有已开门，重开(原数量+1)扇新门；若剩余未开门数 < 原数量+1 则禁用；夺取⭐️，okPlayers全部清空 |
| 揭发领袖 | 翻开当前领袖区域1张本轮未被翻开过的牌（领袖自己不可揭发自己） |

5. 高亮跟随当前行动玩家（activePlayerIndex），⭐️始终标记领袖
6. **非OK操作不消耗回合**：揭发❌️/再开一扇/重新开门后，传递给下一位玩家或回到领袖，游戏循环继续
7. **只有全员OK或揭发中🐶才触发结算**：当所有非领袖玩家均已各自选择过OK时，触发全员OK结算；否则领袖获得再次行动机会，循环继续

#### 阶段三：轮次终了

**触发条件A：揭发领袖翻出🐶**
- 立即结算
- 翻开所有玩家的牌（玩家优先，从领袖开始按门号顺序）
- 被揭发者（领袖）：失败+1
- 揭发者：面前翻开≥2张❌️ → 成功+1
- 其他玩家：面前翻开≥3张❌️ → 成功+1
- 失败与成功同时统计，不因先判定失败而遗漏其他玩家的成功

**触发条件B：全员OK**
- 所有非领袖玩家都选择了OK（okCount >= 非领袖总人数）
- 从领袖开始，每位玩家依次翻开所有已开门对应的牌
- 翻出🐶立即终止后续玩家翻牌，该玩家失败+1
- 同时统计其他已翻开≥3张❌️的玩家成功+1
- 无人翻出🐶时，面前翻开≥3张❌️的玩家成功+1

**触发条件C：领袖面前已有3张❌️被翻开**
- 在搜查阶段任意时刻，若领袖面前已被翻开3张及以上❌️（通过揭发等操作累积），立即进入终了结算
- 结算逻辑与触发条件B（全员OK）完全相同：从领袖开始按玩家优先翻牌，翻出🐶则失败+1并终止，同时统计其他玩家成功
- 一个玩家不会同时成功又失败，成功的前提是未被翻出🐶

#### 阶段四：结算与新一轮
- 弹窗展示本轮结算信息
- 新轮次：所有卡牌重置为背面；保留上轮领袖；跳过已出局玩家
- 从藏狗阶段重新开始

### 2.5 揭发规则细节
- 每轮内已被翻开的牌不可再次被揭发
- 新一轮所有卡牌重置为背面，可以被翻
- 揭发对象始终是当前持有⭐️的领袖（通过 leaderIdxOverride 参数锁定，防止状态漂移）

### 2.6 重新开门可用性
```
canReopen = (openDoors.length > 0) 
  && ((5 - openDoors.length) >= (openDoors.length + 1))
即：剩余未开门数 >= 当前已开门数+1
```

## 4. 状态管理

### 4.1 核心数据结构
```js
{
  playerCount: number,        // 2-5
  players: [
    {
      id: number,             // 0-indexed
      wins: number,           // 累计成功次数
      losses: number,         // 累计失败次数
      isOut: boolean,         // 是否出局
      cards: ['back'|'dog'|'cross', ...],  // 长度5
      revealedThisRound: boolean[],        // 长度5，本轮是否已被翻开
    }
  ],
  phase: 'setup'|'hiding-ready'|'hiding'|'searching-ready'|'searching'|'settlement'|'gameover',
  leaderIndex: number,        // 当前领袖玩家索引
  activePlayerIndex: number,  // 当前行动玩家索引
  openDoors: number[],        // 已开启的门编号(1-5)
  roundNumber: number,
  hidingProgress: number,     // 藏狗阶段已完成人数
  okPlayers: number[],         // 当前最后一次操作为OK的非领袖玩家id列表（选择其他操作后移除）
  settlementInfo: object|null,
}
```

### 4.2 Phase 流转
```
setup → hiding-ready → hiding → searching-ready → searching → settlement → hiding-ready → ...
                                                        ↓
                                                     gameover
```

- `hiding-ready`：显示桌面阵容 + 【玩家X行动】按钮
- `hiding`：藏狗弹窗打开中
- `searching-ready`：显示桌面阵容 + 门栏 + 【玩家X行动】按钮
- `searching`：行动弹窗打开中
- `settlement`：结算弹窗
- `gameover`：终局弹窗

## 5. 关键实现细节

### 5.1 揭发领袖的 leaderIndex 锁定
揭发弹窗创建时捕获当前 `leaderIndex`，通过 `leaderIdxOverride` 参数传递给 `nonLeaderAction`，确保即使中间状态变化，揭发对象仍然是正确的领袖。

### 5.2 搜查阶段循环流转
- OK操作将当前非领袖玩家id加入 `okPlayers`；若该玩家后续选择揭发，则从 `okPlayers` 中移除（保留最后一次操作为OK的语义）
- 再开一扇/重新开门发生时，无论是否换领袖，`okPlayers` 全部清空
- 当所有存活非领袖玩家均在 `okPlayers` 中时触发全员OK结算
- 当轮回到领袖时（`nextPid === currentLeader`），领袖获得再次行动机会
- 揭发中🐶 → 立即结算（不受okPlayers影响）

### 5.3 passToNextOrLeader
统一的下一玩家传递逻辑：
- 找到下一个存活玩家
- 如果是领袖 → 领袖再次行动（searching-ready）
- 如果是非领袖 → 该玩家行动（searching-ready）
- 如果无人可传 → fallback到领袖

### 5.4 领袖后续行动
- 领袖首次行动强制选门（`openDoors.length === 0`）
- 领袖后续轮到时与其他玩家一样4选1
- 领袖不可揭发自己（canAccuse = false when isLeader）
