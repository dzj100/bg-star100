## 4. 规则

### 4.1 赛季开始

1. 重洗全部 60 张，按 §2 发牌。
2. 清空桌上所有力量标志与强弱关系。
3. 确定主持人（第一回合首家）：
   - 第 1 赛季：单机版随机一名玩家（规则书原意「最后看过职业摔跤的人」，线上无法判定）；
   - 第 2 赛季起：**上一赛季的最后一名**。
4. 回合数归 1，主持人先出 1 张。

### 4.2 回合流程

```
主持人出 1 张（任意颜色）
  → 顺时针依次行动：出牌 或 跳过
  → 只剩 1 名「仍有手牌且未跳过」的玩家时，回合结束
  → 本回合打出的牌全部移出场外（本季不再使用）
  → 最后出牌者成为下一回合主持人
```

- 出牌顺序沿座位顺时针（座位 0 → 1 → … → N−1 → 0）。
- 已跳过、已完成（手牌为空）的玩家轮到时直接跳过。
- 主持人必须出牌，不能跳过；其他玩家可随时主动跳过（即使有牌可出）。

### 4.3 出牌合法性（核心）

设上一手为：颜色 `P`、张数 `Pk`；当前想出：颜色 `C`、张数 `K`。

**首家（本回合第一手）**
- 必须恰好出 **1 张**，颜色任意（手中有即可）。

**非首家**
1. `C` 不能等于上一手颜色 `P`（同色视为不更强，禁止）。
2. 查强弱关系（**传递闭包**，见 §4.4）：
   - **C 已知强于 P** → 必须恰好出 `K = Pk` 张（不能多、不能少）。
   - **C 与 P 强弱未定**（含从未出现的颜色）→ 必须恰好出 `K = Pk + 1` 张，并由此**确立 C > P**。
   - **C 已知弱于 P** → 不允许出该颜色。
3. `K ≤ 3`（一手最多 3 张）。因此上一手已是 3 张时，无法再「出道 / 确立新关系」，只能出已知更强的颜色（同样 3 张）或跳过。
4. 手中 `C` 色张数必须 ≥ `K`。
5. 一手只能出**同一种颜色**，张数恰好为 `K`。

> 派生结论：回合内张数只增不减（1 → 2 → 3，之后停留在 3），直到回合结束。因此一个回合最多只会出现 2 个新颜色（1 张、2 张、3 张）。

### 4.4 力量关系与力量标志

#### 关系模型
- 6 色两两之间是**偏序**：`stronger[a][b] = true` 表示「a 已知强于 b」。
- 关系**可传递**：若 A > B 且 B > C，则 A > C 也视为已知（规则书明确认可）。
- 合法性判断、AI 判断、提示文案全部使用传递闭包，而不是只看同列相邻。

#### 标志列（桌面展示）
标志按「列」摆放，同列从上到下 = 从强到弱；不同列之间默认不可比（除非经传递可得）。

- 某颜色**首次出现**时放置该色标志（当家首家的 1 张也算出道，放 1 枚标志，单独成列）。
- 「已知更强」的同张数出牌：**不新增标志**（关系已存在）。
- 「未定强弱」的 +1 张出牌：新增关系 `C > P`，然后放置 `C` 的标志：
  1. 找到 `P` 所在的**所有**列（不只第一列）。
  2. 对每一列，若 `C` 与该列中 `P` 上方的所有颜色**都可比**，则把 `C` 插到唯一确定的空位（每插入一列消耗 `C` 1 枚标志）。
  3. 只有在**没有任何一列**可插入时，才**新建一列**：新列 = `[C, P]`（消耗 `C` 1 枚 + 复制 `P` 1 枚），表示 C > P；`P` 下方更弱的颜色不必复制（传递已隐含）。
- 电子版**不限制每色标志数**；每次插入都是实心标志，不再有幽灵标志。
- 同一个新关系会同时补进所有能容纳它的列。例如 `C > P` 确认时，所有包含 `P` 且 `C` 能与该列上方颜色共存的列，都会在 `P` 上方出现 `C`。
- **列只是可视化**；真正的判定依据始终是关系闭包。为防止玩家误判，界面提供可折叠的「关系表」（6×6：行 > 列）。

#### 举例（对应规则书）
1. 首家出 蓝×1 → 蓝标志单独成列。
2. 出 红×2（未定）→ 红 > 蓝，列：红 / 蓝。
3. 出 绿×3（未定）→ 绿 > 红 > 蓝，列：绿 / 红 / 蓝。
4. 新一轮中 橙 压 红（未定 +1）→ 橙 > 红；但橙与绿不可比，不能同列 → 新建第二列：橙 / 红。
   - 此时橙 > 蓝 虽未画在同一列，但由传递可确定（橙 > 红 > 蓝）。

### 4.5 跳过

- 跳过立即公开，本回合内不可再出牌。
- 完成（手牌为空）的玩家同样不再参与本回合。
- 若轮到你时没有任何合法出牌，只能跳过（UI 只亮「跳过」）。

### 4.6 回合结束

- 条件：本回合「仍有手牌且未跳过」的玩家 ≤ 1。
- 本回合打出的所有牌移出场外（进入本季弃牌区，不再回到任何人手中）。
- 下一回合主持人：
  1. 优先 = **本回合最后出牌者**；
  2. 若其已打空手牌，则由其顺时针下一名**仍有手牌**的玩家担任。
- 所有人跳过状态清空（已完成者除外），开始新回合，主持人出 1 张。

### 4.7 赛季结束与计分

- 某玩家打空手牌 → 立即记为第 1 名、第 2 名……退出本季。
- 当**只剩 1 名玩家还有手牌**时，赛季立即结束；该玩家为最后一名（剩余手牌不再打出）。
- 计分（每赛季各发 1 枚）：

| 名次 | 得分 | 腰带 |
|---|---|---|
| 第 1 名 | **+2** | 金腰带 |
| 第 2 名 | **+1** | 银腰带 |
| 最后一名 | **−1** | 黑腰带 |
| 其余（仅 5~6 人局） | 0 | — |

- 下一赛季主持人 = 本赛季最后一名。
- 回收全部 60 张、清空关系与标志、重新发牌。

### 4.8 游戏结束

- **3~6 人局**：完成 **4 个赛季**，总分最高者获胜。
  - 平分裁决：① +2 金腰带更多者（= 赢得赛季更多）；② 最后一个赛季的赢家；③ 仍平则并列。
- **2 人局**：没有固定赛季数，**先赢 3 个赛季者获胜**（每赛季必有一人第 1、一人最后）。得分与腰带仍展示，但不作为胜负依据。

### 4.9 边界裁定（数字版补充）

| 场景 | 裁定 |
|---|---|
| 最后出牌者已打空，回合仍需继续 | 顺时针下一名有手牌者担任下回合主持人 |
| 打空者导致本回合「活跃玩家 = 0」 | 回合正常结束，按相同规则找下任主持人 |
| 只剩 1 人还有手牌 | 赛季立即结束，该人最后一名 |
| 上家已出到 3 张 | 未定强弱无法再出（需 4 张 > 上限），只能出已知更强 3 张或跳过 |
| 玩家主动跳过但仍有牌 | 允许；本回合不再行动 |
| 力量标志数量 | 电子版不限量，全部实心；关系照常记录 |
| 赛季结束瞬间有人恰好打空 | 名次以打空瞬间排序，剩余唯一有牌者最后 |
| 存档发生在 AI 回合中 | 恢复后 AI 继续行动 |

### 4.10 规则书歧义与解释

| 原文 | 解释 |
|---|---|
| 「每个赛季只能打出完手牌的玩家将获得最多积分」 | 赛季第一个打空手牌者得 +2 |
| 「在每张新回合开始之前都要这样（发牌）」 | 实为**每个新赛季**开始前发牌（官方英文规则同） |
| 「最多可以放置 3 张牌」 | 单次出牌最多 3 张 |
| 「赢得最后一回合的玩家」成为平局裁决 | 按**最后一个赛季的赢家**理解 |
| 「最后一个观看职业摔跤比赛的玩家」 | 单机版第 1 赛季随机主持人 |
| 「第二名完成的玩家获得 +1 分」 | 5~6 人局其余中间名次 0 分 |

## 5. 对局状态机

```
menu ──▶ setup ──▶ seasonStart ──▶ roundStart ──▶ turn* ──▶ roundEnd ──┐
                        ▲                                              │
                        │                   赛季未结束 ◀────────────────┘
                        │
                        └──────── seasonEnd（结算/颁奖）──▶ 下一赛季
                                                   │
                                                   ▼
                                                gameEnd
```

- `turn`：当前玩家 = 真人（等待输入）或 AI（短暂思考后自动行动）。
- `roundEnd`：播放收牌动画 → 自动进入 `roundStart`。
- `seasonEnd`：弹窗展示名次/腰带/总分 → 玩家点「下一赛季」。
- `gameEnd`：终局排名 + 重开入口。

## 6. 数据结构（引擎）

```js
Maskmen.state = {
  phase: 'playing' | 'seasonEnd' | 'gameEnd',
  seed: number,
  rngState: number,            // 可存档，保证重开后随机流一致
  playerCount: 2..6,
  handSize: 15 | 12 | 10,
  players: [{
    id, name, isAI, difficulty,
    hand: [n0, n1, n2, n3, n4, n5],   // 6 色手牌张数
    score: number,
    belts: { gold: n, silver: n, black: n },
    finishRank: 0,             // 0 = 未完成；1..N
    passed: false,
    out: false                 // 已完成/本季退出
  }],
  season: 1,
  seasonWins: [0, 0, ...],     // 2 人局用
  round: 1,
  leader: idx,
  turn: idx,
  prevPlay: null | { player: idx, color: 0..5, count: 1..3 },
  trickPlays: [{ player, color, count }],
  discards: [n0..n5],          // 本季已移出场外的牌（公开）
  relation: [[bool x6] x6],    // 传递闭包：stronger[a][b] = a 已知强于 b
  columns: [[color, ...], ...],// 仅用于展示，顶 = 最强
  markerUse: [0..0],           // 每色已用标志数（仅统计，不设上限）
  log: [],
  lastSeasonWinner: idx | null,
  result: ...,
}
```

- **牌不需要独立 id**：同色完全等价，手牌用 6 个计数表示，渲染时再展开成卡面。
- 每色总数 10。`unseen[c] = 10 − 自己手牌[c] − discards[c]`（含他人手牌 + 本季扣置牌），AI 只据此估计。
- 所有随机（洗牌、AI 抖动、AI 采样）走注入的 seeded RNG（mulberry32），保证可复现、可存档、可联机。

## 7. 核心算法

### 7.1 合法出牌枚举

```
if (prevPlay == null)                       // 首家
  返回所有 hand[c] > 0 的颜色，张数固定 1
else
  for c in 0..5:
    if (c == prevPlay.color || hand[c] == 0) continue
    rel = compare(c, prevPlay.color)        // 1 强 / -1 弱 / 0 未定
    if (rel == -1) continue
    need = rel == 1 ? prevPlay.count : prevPlay.count + 1
    if (need > 3 || hand[c] < need) continue
    返回 { color: c, count: need }
```

### 7.2 关系更新

- 出牌且 `rel == 0` 时：加入边 `C > P`，重算传递闭包（6×6，Floyd 或 BFS 即可）。
- 因出牌前已确认 `C` 不弱于 `P`，新边不可能成环。

### 7.3 标志列更新（见 §4.4）

```
placeMarker(C, P):
  placed = false
  对 P 所在每列（旧→新）:
      above = P 该列上方的颜色
      if C 与该列中 above 每个颜色都可比:
          按关系找到插入位，插入 C；消耗 C 1 枚
          placed = true
  if !placed:
      新建列 [C, P]；消耗 C 1 枚 + P 1 枚（复制）
```

### 7.4 赛季结算

```
ranking = 按 finishRank 升序的已完成玩家 + 剩余唯一有牌者（最后）
award: rank1 +2/gold, rank2 +1/silver, last -1/black
seasonWins[rank1]++
if 2人局 && seasonWins[rank1] == 3 → gameEnd
if 3~6人局 && season == 4 → gameEnd
else → seasonStart(leader = lastPlace)
```

## 8. AI 设计

### 8.1 信息边界（硬性）

- AI 只能通过 `Maskmen.viewFor(state, idx)` 获取：自己的手牌计数、公开信息（他人家手牌数、跳过/完成、分数、弃牌、关系、上一手、回合/赛季）、`unseen` 池。
- **绝不读取**他人手牌分布、扣置牌颜色、洗牌顺序。
- 用注入 rng；同一视图 + 同一 rng 序列 → 同一决策。

### 8.2 决策框架

> 2026-11-25 按 2~6 人自对弈标定后定稿；关系收益若作为主权重会显著变弱，只保留为「同张数」的次级排序。

1. **首家**：从手中颜色里选 1 张。
   - 主排序：出手牌数**最少**的花色。单张最难脱手；大色组留给后续多张出牌。
   - 同数量：优先 `unseen` 多的花色——对手更可能攥着它，压住该色等于废掉对手的牌。
   - 仅用 seeded 随机打破极接近的平局。
2. **非首家**：
   - 枚举合法出牌；**跳过只在没有合法出牌时使用**。跳过会整轮永久退出并留下手牌，标定中几乎总是劣势。
   - 主排序：出牌张数最大。进度优先，能一把打空自然会被选中。
   - 同张数次级排序：a) 优先能打空一个色组的花色；b) 若都要建立新关系，优先强化已强势的颜色。
   - 不做跨回合推演；`C > P` 的关系收益/损害只影响同张数时的选择。
3. **不做**：搜索整局、读取隐藏信息、针对真人的「作弊」策略。

### 8.3 难度档

**本期只做一档「标准」**（用户确认）：上述完整启发式，不做采样推演，不加随机失误，仅在同分时用 seeded 随机打破平局。

- 玩家对象保留 `difficulty: 'normal'` 字段；`LEVEL` 参数表保留，后续加「轻松 / 凶悍」不需要改引擎与存档格式。
- 凶悍档的未来方向：对未知牌做一致性采样（估计对手持色与完赛顺序），并推演下家可压的颜色。
- 标定参考：2 人局对随机约 89% 胜率（200 局）；4~6 人混合局第一率显著高于随机基线。

### 8.4 节奏

- AI 思考 500~900ms（凶悍档可到 1200ms），期间回合条显示「思考中…」。
- 连续 AI 回合之间保留 400ms 间隔，避免瞬间刷屏。

## 9. UI / UX

### 9.1 界面清单

1. **封面**：标题、面具主视觉、1~5 AI 说明、开始 / 继续上局 / 规则、战绩。
2. **设置**：玩家名（默认「你」）、AI 数量（1~5）、难度、经纪人名单、开始。
3. **对局**：顶栏（赛季/回合/主持/规则/日志/声音/退出）、力量列、当前回合、玩家席位、手牌、操作区。
4. **赛季结算**：名次、腰带、得分、下一赛季。
5. **终局**：排名、冠军、腰带墙、再来一局 / 调整人数 / 返回首页。
6. **弹窗**：规则、关系表、日志、计分、确认退出/重开。

### 9.2 对局主界面（移动端）

```
+--------------------------------------+
| 🎭 面具摔跤手   第2/4赛季 · 第3回合   |
| [规则] [日志] [🔊] [退出]             |
+--------------------------------------+
| 力量关系                [关系表 ▾]    |
|   列1        列2                      |
|   [绿▲]      [橙★]                   |
|   [红◆]      [红◆]                   |
|   [蓝●]                               |
|   （越上越强 · 不同列默认不可比）      |
+--------------------------------------+
| 上一手：橙★ ×3  · 蓝电                |
| 提示：需出「已知更强」同 3 张，或未定  |
|       颜色 4 张（超过上限，不可）      |
+--------------------------------------+
| 席位：你(经纪人) 5张 · 铁面 7张 跳过 · |
|       旋风 3张 · 银钩 已完成 第1名      |
+--------------------------------------+
| 你的手牌（点颜色直接出牌）             |
|  [红◆ ×3]  [蓝● ×1]  [绿▲ ×4]         |
|  [橙★ ×0]  [紫■ ×2]  [灰✚ ×0]        |
+--------------------------------------+
| [跳过本回合]        [关系表] [规则]    |
+--------------------------------------+
```

- 手牌**按颜色分组**展示（同色等价），每色显示张数与合法状态：
  - `可出 2 张`（已知更强）
  - `未定 · 需 3 张`
  - `弱于 橙★ · 不可出`
  - `张数不足 / 超过 3 张上限`
- 点击合法颜色 → 自动打出规则要求的张数（玩家无需选张数，也没有张数选择空间）。
- 非法颜色点击 → 抖动 + 气泡说明原因。
- 首家回合：提示「你是主持人，出 1 张」。
- 你已经跳过 / 已完成：手牌区置灰并显示「本回合已跳过」。

### 9.3 力量关系可视化

- 官方风格的列 + 标志；新增关系时标志下落、列重排。
- 上一手颜色高亮；悬停/点按某颜色，**高亮所有「已知更强 / 已知更弱」的颜色**（传递闭包），避免误判。
- 「关系表」弹窗：6×6 矩阵，行 > 列：`✓ 已知强`、`✗ 已知弱`、`? 未定`、`— 自己`。
- 图例：「同列越靠上越强；不在同列且无传递关系 = 未定」。

### 9.4 对局信息

- 席位卡：图标（原创随身物件，不使用摔跤手面具）、名字、手牌数、跳过印章、完成名次、总分、腰带。
- 回合时间线：本回合每次出牌的小记录（颜色×张数 + 玩家），上一手放大突出。
- 日志：按回合计，「未定 → 确立 绿 > 红」等关键事件单独标色。
- 赛季结算：名次表 + 腰带飞入 + 总分变化（+2/+1/−1）。

### 9.5 交互细节

- 键盘：`1~6` 选色出牌，`P / 空格` 跳过，`R` 规则，`L` 日志，`Esc` 关闭弹窗。
- 只有合法操作可点；不可用按钮有原因提示。
- 所有状态变化 `aria-live` 播报（轮到谁、出了什么、谁跳过）。
- 动效遵循 `prefers-reduced-motion`。

## 10. 视觉设计

### 10.1 主题

**Oink 波普摔跤海报**：奶油纸底、粗墨线、大色块、轻微旋转的贴纸感；像一张 70 年代 lucha libre 海报，热闹但不刺眼。

| 角色 | 色值 |
|---|---|
| 纸底 | `#FBF3E2` |
| 墨线 / 文字 | `#201B16` |
| 擂台垫 | `#2E7D5B`（墨绿） |
| 强调黄 | `#FFD84D` |
| 金 / 银 / 黑腰带 | `#F2C230` / `#C9CFD6` / `#2B2723` |
| 六色 | 见 §1.1 |

- 字体：系统重黑体（`font-weight: 900`），标题大字距；数字用等宽。
- 卡面：米白卡纸 + 墨线边框 + 该色原创面具 SVG + 左上角形符 + 底部色名；同色牌可叠放显示。
- 席位图标：原创经纪人随身物件（礼帽/胡子/烟斗/墨镜/拳套/耳机），与摔跤手面具严格分离；面具只用于卡面、力量标志和品牌主视觉。
- 力量标志：圆形筹码，中心形符，边缘虚线；电子版全部实心，不设每色 5 枚上限。
- 腰带：金色/银色/黑色三条原创腰带 SVG。
- 桌面：墨绿垫 + 米色网格，力量列用「钉子 + 绳」的擂台围绳意象。
- 全部 SVG 内联，离线可用。

### 10.2 版式

- 移动端优先 390×844；桌面最大宽 1200，三栏（席位 / 牌桌 / 信息）。
- 横屏手机：力量列与手牌并排，席位收成横条。
- 安全区适配（`viewport-fit=cover`）。

## 11. 动效与音效

| 事件 | 动效 | 音效 |
|---|---|---|
| 发牌 | 手牌从牌堆滑入、扇形展开 | 纸牌轻响 |
| 出牌 | 卡牌拍桌：下压 + squash & stretch + 微震屏 + 灰尘 | 拍击 + 低频 thud |
| 确立新关系 | 标志落入列、弹跳、列重排 | 筹码叮 |
| 跳过 | 「跳过」印章旋转盖下 | 沉闷盖章 |
| 回合结束 | 本回合牌扫向场外弃牌堆 | 扫牌声 |
| 赛季结束 | 幕布/纸带切换 + 腰带飞入 + 彩带 | 颁奖小号 |
| 终局 | 冠军腰带 + 彩带雨 | 胜利号角 |
| 非法操作 | 卡牌左右抖 + 红色气泡 | 短促错误音 |

- WebAudio 合成，无外部音频；提供静音开关，记忆设置。
- 动效全部可中断、不阻塞状态机；`prefers-reduced-motion` 下仅保留淡入淡出。

## 14. 测试计划

### 14.1 规则单测（`node maskmen/test-core.js`）

- 牌组：6×10，发牌数符合 §2，未发牌数正确。

- 2 人局：先赢 3 季即终局；3~6 人局 4 季终局。

- 存档/恢复：序列化往返后状态一致，rng 接续一致。
- AI：任意视图下返回的决策必合法；200 局 × 2/3/4/5/6 人自对弈无死循环、无非法出牌、必定终局。
