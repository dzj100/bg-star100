# 流冰航路 The Frozen Passage — 单人 + 联机模式规格说明

移动优先的单页 HTML 桌游，纯前端、零框架、无外部依赖（沿用本仓库现有游戏的技术基线）。
包含 **1 人解谜模式** 与 **2~4 人联机合作模式**；两者共用同一套规则引擎，联机通过 Supabase Realtime 同步房间状态。

- 官方中文名：**《流冰航路》**
- 英文名：**The Frozen Passage**
- 目录：`frozen-passage/`
- 目标：在倒三角的 15 个位置上放下 15 张冰山卡牌，全部填满即胜利。
- 联机：2~4 人合作，共用一个棋盘、供应堆与物品池；每人独立手牌，当前玩家行动，全队共享胜负。

---

## 1. 组件与牌组

| 组件 | 数量 | 说明 |
|---|---|---|
| 冰山卡牌 | 27 | 3 色（蓝 / 红 / 黑）× 数字 1~9，每个“颜色+数字”组合唯一 |
| 目标卡牌 | 6 | 3 色 × 2 张；只有颜色和建筑插画，没有数字 |
| 起始卡牌 | 1 | 冰山图案；无颜色、无数字 |
| 牌架 | 4 | 实体用于展示手牌；数字版仅作为信息展示 |
| 物品标记 | 12 | 6 类 × 2 个；单人与联机都从池中随机抽 3 个（见 §7） |

- 牌背可见信息：**颜色**；手牌立在牌架上时，其他玩家还能看到手牌的**相对大小**（联机用）。
- 冰山卡牌无重复，任意两张牌不会同色同数字。
- 目标卡牌/起始卡牌不占 15 张冰山卡名额，它们只是底层支撑与颜色提示。

## 2. 游戏设置

1. **目标卡**：6 张洗混，随机抽 5 张，正面朝下排成第 5 行；剩余 1 张放回盒中。
2. **难度**（翻开目标卡的数量）：
   - **新手**：5 张全部正面朝下。
   - **中等**：翻开两端和中间，共 3 张（位置 1 / 3 / 5）。
   - **专家**：5 张全部正面朝上。
3. **起始卡**：正面朝上，放在目标行下方约 5 张牌距离处；数字版中即第 1 行的位置。
4. **发手牌**：冰山卡洗混后发牌。单人 / 2 人局手牌 4 张，3~4 人局 3 张。手牌按数字升序排列，同数字任意顺序；只有本人能看到正面。
5. **抽牌堆与供应堆**：剩余冰山卡作抽牌堆。取抽牌堆顶 3 张作供应堆（实体规则为 2 张放旁边 + 抽牌堆顶 1 张，共 3 张正面朝下）。供应堆只显示牌背颜色，不显示数字。
6. **物品**：单人从 6 个标记（因纽特智慧 ×2、狗拉雪橇 ×2、航海日志 ×2）中随机抽 3 个；联机从 12 张物品卡（6 类 ×2）中随机抽 3 张作为共享物品。均正面朝上，每张可用一次。
7. **先手**：单人由玩家先手；联机由种子随机决定先手座位，并在开局日志中公布。

单人开局数量校验：27 张冰山卡 = 手牌 4 + 供应堆 3 + 抽牌堆 20。

联机开局数量校验：

| 人数 | 每人手牌 | 手牌合计 | 供应堆 | 抽牌堆 |
|---|---|---|---|---|
| 2 人 | 4 | 8 | 3 | 16 |
| 3 人 | 3 | 9 | 3 | 15 |
| 4 人 | 3 | 12 | 3 | 12 |

## 3. 棋盘与位置

15 个位置 = 第 1~5 行，第 r 行有 r 个位置，从下往上排列：

```
第5行:  1 2 5 8 9      ← 5 张目标卡在这 5 个位置下方
第4行:   3 4 5 7
第3行:    5 6 9
第2行:     6 7
第1行:      4          ← 起始卡在这个位置下方
```

- 位置 ID：`r{row}-{index}`，`index` 从左到右为 1..row。
- 第 5 行位置 i 下方是对应的目标卡 i；第 1 行位置下方是起始卡。
- **支撑关系**：
  - 第 1 行：直接放在起始卡上，无其他支撑要求。
  - 第 r 行（r≥2）最左端（index=1）：需要下方 `(r-1,1)` 有牌。
  - 第 r 行最右端（index=r）：需要下方 `(r-1,r-1)` 有牌。
  - 中间位置：需要下方 `(r-1,index-1)` 和 `(r-1,index)` 两张都有牌。
- 允许某一行未填满就先往上叠，只要支撑满足；不要求按行顺序完成。
- 第 5 行的目标卡正面朝上时，该位置的冰山卡颜色受规则④约束（见 §5）。

## 4. 回合流程

当前玩家按顺序执行。单人模式当前玩家固定为本人；联机模式按座位顺时针轮转（座位 0 → 1 → … → N-1 → 0），只有当前玩家可以放置、补牌与使用共享物品。

### (1) 使用物品（可选，放置前）

- 本回合放置前可以使用任意未翻面的物品；每个标记只能用一次，用后翻面。同一回合可以使用多个不同物品。
- **因纽特智慧必须在放置前使用**：使用后本回合的这次放置获得“紧邻同数字”豁免（见规则③）；放置完成后效果立即结束，不跨回合。
- 狗拉雪橇 / 航海日志可在放置前使用，也可在“卡住”时用于解救（见 §8）。
- 若当前没有任何“仅靠因纽特智慧豁免才合法”的落点，不能使用因纽特智慧（避免浪费物品）。

### (2) 放置一张卡牌并创造一条航线

- 打出 1 张手牌，放在任意合法空位。
- 第一张打出的牌覆盖在起始卡上，成为第 1 行；起始卡无颜色，因此第一张牌颜色任意。
- 从第 2 行开始，必须满足 §5 的四条放置规则（因纽特智慧只放宽规则③的紧邻同数字比较）。
- 放置后从手牌移除该牌；若填满 15 个位置，立即胜利，不再补牌。

### (3) 补充手牌

- 从供应堆选择 1 张卡牌加入手牌；按数字升序重新排列。
- 若取走的是供应堆中的牌（非抽牌堆顶），从抽牌堆顶补 1 张正面朝下到供应堆，保持 3 张可选。
- 抽牌堆为空时不再补充，继续游戏。
- 供应堆为空时跳过补牌。

### 回合结束

- 单人即进入下一回合；联机把当前座位交给下一位玩家，`turn` +1。
- 因纽特智慧效果不延续。
- 不能主动跳过回合；只有“罐头食品”物品可以跳过（单人不可用）。
- 当前玩家无法放置卡牌时，团队失败；失败前允许使用物品尝试解救（见 §8）。联机中当前玩家可以先用罐头食品把回合交给下一位，或使用其他物品自救。

## 5. 四条放置规则

### 规则① 支撑

- 一个位置只有在其下方所需卡牌都已放置时才能放牌。
- 中间位置需要下方两张卡牌；一行的两端各只需要下方一张卡牌。
- 不允许“悬空”或只靠一张牌支撑中间位置。

### 规则② 颜色 / 航线

- 颜色判定以**下方一行**为准：下方每张卡牌，在它上方的两个相邻位置中，至少要有 1 张与它**同色（相连）**。
- 也就是说，两张上方牌里接上 1 张即可；两张下方卡中，只要需要的那 1 张被接续，另一张可以不同色。
- 若另一张上方牌尚未放置，颜色义务**延后**：等那张牌落下时再校验。两张上方牌都落定后，若都与下方牌不同色，则该次放置非法。
- 新牌与下方所有卡都不同色时，仅当下方每张牌的另一个上方位置已由同色牌接续（或为空、义务延后）才允许落下，视为**另起一条新颜色航线**；该颜色必须继续向上接续，直到第 5 行（逐层判定自动保证）。
- 第 1 行没有下方卡牌，颜色任意。
- 书中示例“右边已经放置了红色卡牌，所以这里只能放置黑色卡牌”为硬规则：蓝 2 已由同排蓝 5 接续，而黑 5 上方只有红 8，因此空位必须补黑色。

### 规则③ 数字

- **同一行内**，已放置卡牌的数字从左到右必须严格递增。
- 判定新牌时，只与同一行内**最近的左邻和右邻**比较：`左邻 < 新牌 < 右邻`；中间的空位不影响比较。
- 同一行内相同数字不能相邻（严格递增已覆盖）。
- **不同行之间允许相同数字相邻**（例如第 5 行红 5 与第 4 行黑 5 斜向相邻是合法的，书中胜利牌型即如此）。
- **因纽特智慧**：本回合放置前使用后，本次放置的牌可以与**紧邻（同一行左右相邻，index ±1）**的已放置卡牌数字相同。例如第 3 行左边蓝 3、右边黑 5，中间空位通常只能放 4；使用后 3、4、5 都可以。
  - 豁免仅限“紧邻”的一侧：隔着空位的同数字仍然不允许（否则空位将无牌可放）。
  - 不参与豁免的另一侧仍按严格不等式判定；规则①、②、④也不受影响。
  - 航海日志换牌不享受此豁免。

### 规则④ 目标卡

- 第 5 行每个**正面朝上**的目标卡上，所放卡牌颜色必须与目标卡同色。
- 目标卡背面朝上时不约束。
- 新手：全部背面 → 规则④不生效。
- 中等：位置 1 / 3 / 5 正面 → 这 3 个位置受约束。
- 专家：5 张全部正面 → 5 个位置全部受约束。

## 6. 合法落子判定（伪代码）

```js
function supports(slot) {
  if (slot.row === 1) return [];
  if (slot.index === 1) return [slotAt(slot.row - 1, 1)];
  if (slot.index === slot.row) return [slotAt(slot.row - 1, slot.row - 1)];
  return [slotAt(slot.row - 1, slot.index - 1), slotAt(slot.row - 1, slot.index)];
}

// 每张下方牌恰好对应两个上方位置
function above(slot) {
  return [slotAt(slot.row + 1, slot.index), slotAt(slot.row + 1, slot.index + 1)]
    .filter(Boolean);
}

function canPlace(state, card, slot, opts = {}) {
  if (slot.cardId) return false;

  // 规则①：支撑
  const below = supports(slot);
  if (below.some(s => !s.cardId)) return false;

  // 规则②：下方每张牌，上方两张里至少一张同色；另一张上方未放时延后
  for (const s of below) {
    const belowCard = cardAt(s);
    if (belowCard.color === card.color) continue;
    const sibling = above(s).find(x => x.id !== slot.id);
    if (!sibling || !sibling.cardId) continue;
    if (cardAt(sibling).color === belowCard.color) continue;
    return false;
  }
  const colorMatches = below.filter(s => cardAt(s).color === card.color);
  const newRoute = below.length > 0 && colorMatches.length === 0;

  // 规则④：第 5 行正面目标卡颜色
  if (slot.row === 5) {
    const goal = goalAt(slot.index);
    if (goal.faceUp && goal.color !== card.color) return false;
  }

  // 规则③：同行最近左邻 / 右邻严格递增；因纽特智慧仅豁免紧邻同数字
  const wisdom = opts.wisdom != null ? !!opts.wisdom : !!state.wisdom;
  const left = nearestOccupiedInRow(state, slot.row, slot.index, -1);
  const right = nearestOccupiedInRow(state, slot.row, slot.index, +1);
  if (left) {
    const sameAdjacentLeft = wisdom && left.index === slot.index - 1 &&
      card.number === cardAt(left).number;
    if (!sameAdjacentLeft && card.number <= cardAt(left).number) return false;
  }
  if (right) {
    const sameAdjacentRight = wisdom && right.index === slot.index + 1 &&
      card.number === cardAt(right).number;
    if (!sameAdjacentRight && card.number >= cardAt(right).number) return false;
  }

  return { ok: true, colorMatches, newRoute };
}
```

- 空格不参与数字比较，但新牌必须落在最近左右邻之间（或按紧邻豁免相等），保证最终每行严格递增。
- 规则②由下方牌驱动颜色接续：两张上方牌都落定后义务必须完成，因此满盘时每条颜色航线都自动连到第 5 行；`newRoute` 仅用于 UI 提示（新牌与下方都不同色）。
- `state.wisdom` 是本回合因纽特智慧生效标记；`opts.wisdom` 可显式覆盖，航海日志的 `logOptions` / `useLog` 固定传 `wisdom: false`，因此换牌不享受豁免。
- `inuitPlacements(state)` 返回“仅在 `wisdom: true` 下合法、严格规则下非法”的落点，用于判断物品能否使用与 UI 提示；没有此类落点时不消耗物品。

## 7. 物品

物品使用规则：所有玩家讨论并一致后，正面朝上的物品可随时使用；每个标记只能用一次，用后翻面。单人由玩家决定；联机中仅**当前回合玩家**可以点击并使用共享物品（救生艇使用后由全员参与选牌）。

| 物品 | 效果 | 单人 | 联机 |
|---|---|---|---|
| 因纽特智慧 | 本回合放置前使用；本次放置可将手牌放在已放置卡牌的紧邻位置，即使**数字相同** | ✅ | ✅ |
| 狗拉雪橇 | 将 1 张手牌放回抽牌堆**底部**，从供应堆拿 1 张 | ✅ | ✅ |
| 航海日志 | 将 1 张已放置卡牌与 1 张手牌互换；换上的牌必须满足 4 项放置规则 | ✅ | ✅ |
| 无线电广播 | 补手牌时改为从另一位玩家处获得 1 张；给出者选择并立即补牌 | ❌ | ✅ |
| 救生艇 | 每位玩家同时将 1 张手牌传给左手边玩家 | ❌ | ✅ |
| 罐头食品 | 跳过你的回合 | ❌ | ✅ |

### 单人实现细节

- **物品池**：从 6 个标记（因纽特智慧、狗拉雪橇、航海日志各 2 个）随机抽 3 个，**允许出现重复类型**（因为抽的是实体标记）。
- **因纽特智慧**：
  - 触发时机：本回合**放置前**；使用后效果持续到本回合这次放置完成，不跨回合。
  - 效果：本次放置的牌可以与同一行**紧邻（左右相邻）**的已放置卡牌数字相同；隔着空位的同数字仍然不允许。例如左 3 右 5 时，中间 3、4、5 均可。
  - 仍只放 1 张、只补 1 张；规则①、②、④不变，航海日志换牌不享受豁免。
  - 仅当存在“没有豁免就非法”的落点时才可使用；否则 UI 禁用并说明原因（避免浪费物品）。
  - “卡住”时若存在此类落点，可作为解救手段之一。
- **狗拉雪橇**：
  - 选择 1 张手牌放回抽牌堆底部，再选择供应堆 1 张加入手牌。
  - 供应堆按 §4 的补牌规则从抽牌堆补足到 3 张（抽牌堆空则减少）。
  - 可用于放置前，或“卡住”时尝试换牌。
- **航海日志**：
  - 选择一张已放置卡牌与一张手牌互换；换上的牌按该位置重新校验规则①~④（规则②看该位置下方支撑；规则④看第 5 行目标卡）。
  - 换下的牌进入手牌并重排。
  - 换上的牌还必须向上接续已放置的航路：该位置上方两张牌都已放置时，至少要有一张与新牌同色，否则不允许替换；上方还有空位时，颜色义务延后到那张牌落下时校验。
  - 例如起点 1-1 上方是蓝 1 与黑 7 时，1-1 只能换成蓝色或黑色牌，红色牌不允许。
- 物品使用后不可撤销；使用前弹出确认层，写明效果与目标。

### 联机实现细节

- **共享物品池**：开局从 12 张物品卡（6 类 ×2）中随机抽 3 张，正面朝上；界面每张单独显示（同类型抽到 2 张时显示 2 个物品标记，不合并），各自可用 1 次。仅当前回合玩家可以发起使用。
- **因纽特智慧 / 狗拉雪橇 / 航海日志**：与单人规则相同，只作用于当前玩家手牌；航海日志换牌不享受因纽特豁免。
- **无线电广播**（只能在**补牌阶段**使用）：
  1. 当前玩家 A 选择另一位手牌非空的玩家 B，并从 B 的手牌中**由 A 自选 1 张**（A 只看到 B 的牌背颜色与升序位置，不知道数字）。
  2. 该牌进入 A 的手牌并重排；B 的手牌减少 1 张。
  3. 随后由 **B 自己**从共享供应堆选择 1 张补入手牌（供应堆按正常规则从抽牌堆补足）。
  4. B 补牌完成后，A 的回合结束，轮到下一位玩家。
  - 使用前提：供应堆非空、至少一位其他玩家手牌非空。
  - 交叉状态：`phase='radio'`、`pending={type:'radio', fromSeat:A, toSeat:B, cardId, stage:'supply'}`，此阶段只有 B 可以操作。
- **救生艇**（放置阶段或卡住时使用）：
  1. 当前玩家发起后进入 `phase='lifeboat'`，所有玩家同时从自己的手牌中暗选 1 张。
  2. 界面只显示“已选 / 未选”，不公布具体牌；全部玩家就绪后，每人的牌同时传给左手边玩家（`seat+1 mod N`）。
  3. 传牌完成后由当前玩家继续本回合（可以放置，仍未脱困则保持卡住）。
  - 使用前提：所有玩家手牌均非空。
  - 交叉状态：`pending={type:'lifeboat', picks:{seat: cardId|null}}`；所有玩家都可以修改自己的选择。由**当前玩家**在收齐全员选择后执行最终交换，避免多端重复交换。
- **罐头食品**（放置阶段或卡住时使用）：立即消耗 1 个罐头，当前玩家的回合直接结束，轮到下一位；不放置、不补牌。卡住时使用罐头属于合法自救。
- **卡住**：当前玩家可依次尝试可用物品；若没有任何可用物品或玩家放弃，可宣告全队失败。救生艇与罐头可以把机会交给下一位玩家。
- **物品操作权**：除救生艇的“全员选牌”外，非当前玩家只能观看，不能点击物品或供应堆。

## 8. 胜负

- **胜利**：第 5 行及以下 15 个位置全部放满立即胜利；不再补牌。因纽特智慧只放宽数字判定，不增加放置张数。
- **失败**：轮到当前玩家，无法放置任何手牌（在考虑可用物品后）即失败。
  - 单人：进入 `stuck` 状态，UI 提供可用物品（因纽特智慧 / 狗拉雪橇 / 航海日志）与“宣告失败”；若手牌为空且无可用物品，直接失败。
  - 联机：当前玩家进入 `stuck`，可使用共享物品自救，或用罐头食品跳过；若仍无法放置且放弃，则全队失败。
- 没有平局。

```js
  seed: 123456,
  rng: 123456,                     // 可复现的 PRNG 状态
  mode: 'solo',
  difficulty: 'novice' | 'medium' | 'expert',

  phase: 'place' | 'refill' | 'stuck' | 'won' | 'lost',
  turn: 1,

  board: {
    slots: [                       // 15 个
      { id: 'r1-1', row: 1, index: 1, cardId: 'blue-4', goalId: null },
      // ...
      { id: 'r5-1', row: 5, index: 1, cardId: null, goalId: 'goal-blue-1' }
    ],
    goals: [                       // 5 张
      { id: 'goal-blue-1', color: 'blue', faceUp: false, slotId: 'r5-1' }
    ],
    starter: { slotId: 'r1-1' }
  },

  hand: ['blue-5', 'red-2', 'black-9', 'blue-1'],   // 按数字升序
  supply: ['red-7', 'black-3', 'blue-8'],            // 最多 3 张，牌背可见颜色
  draw: ['red-1', /* ... */ 'black-6'],              // 底 → 顶，顶部为末尾

  items: [
    { id: 'item-1', type: 'inuit', used: false },
    { id: 'item-2', type: 'sled', used: false },
    { id: 'item-3', type: 'log', used: false }
  ],

  wisdom: false,                   // 本回合因纽特智慧是否生效；放置后/回合结束重置
  log: [                           // 操作日志：UI 可查看，也用于复盘/测试
    { turn: 1, type: 'place', cardId: 'blue-4', slotId: 'r1-1', newRoute: false }
  ],
  lastAction: null
}
```

- `cardId = '{color}-{number}'`，如 `blue-5`、`red-9`、`black-1`。
- `goalId = 'goal-{color}-{n}'`，同色两张用 n=1/2 区分。
- 单人没有隐藏信息；联机时手牌/抽牌堆会对其他玩家隐藏，状态结构保持不变。
- 所有随机（洗牌、抽目标卡、抽物品）使用种子 PRNG；相同 seed + 相同操作序列必须复现同一局。

```js
  pending: null,                    // 无线电 / 救生艇交叉状态，见 §16.4
```

### 游戏页（移动端 390×844 基准）

- **顶栏**：难度、回合数、剩余位置数、规则按钮、菜单（重开/规则提示开关/统计）。联机模式显示“联机 · N 人 · 第 X 回合”和退出按钮。
- **联机玩家条**：信息栏下方新增队友手牌区。每位队友显示座位色点、昵称、手牌张数与一排**升序缩略牌背**（只显示颜色，从左到右数字由小到大）；当前回合玩家高亮。自己不在该条中重复展示，手牌区顶部显示“你的手牌 · N/上限”。
- **回合门禁**：非当前玩家的手牌、棋盘、供应堆、物品均置灰；信息条显示“等待 XX 行动”。无线电补牌阶段只有目标玩家能选择供应堆；救生艇阶段全员可以选自己的牌。
- **棋盘**：倒三角 5 行；冰川蓝底，卡片为带斜切角的六边形风格。
  - 第 5 行目标卡：正面显示颜色/建筑图标；背面显示深色冰纹。
  - 第 1 行起始卡：显示冰山图标。
  - 空位：虚线轮廓；已放置：颜色+数字+颜色形状图标。
  - 选中手牌后：合法空位高亮；非法空位点击显示原因（Toast 或底部说明条）。
  - 高亮支撑卡与颜色连线；新颜色航线用虚线提示“需连到第 5 行”。
- **信息条**：当前选中牌、可放位置数、最近操作提示（如“与下方蓝 3 相连”“另起黑色航线”）；因纽特智慧生效时显示专属标记。点按信息栏（或右侧时钟按钮）打开操作记录抽屉，按时间倒序展示放置、补牌、物品使用与胜负，相同回合分组显示，最新一条带标记。
- **供应堆**：3 张背面牌，显示颜色背纹；补牌阶段脉冲提示“选择 1 张”。
- **手牌**：底部横向排列，按数字升序；点击选中/取消；选中后上浮。联机只显示自己的牌面，队友只显示牌背。
- **物品**：单人显示抽到的 3 个标记；联机同样每张物品卡单独显示为 1 个物品标记（同类型不合并），用后该标记置灰。因纽特智慧点击打开使用层（说明本回合豁免并列出可用落点），确认后立即生效且不消耗放置次数；狗拉雪橇/航海日志/无线电广播/救生艇/罐头食品点击打开效果确认层。
- **联机物品交互层**：
  - 无线电广播：当前玩家选队友 → 从队友的升序牌背中点选 1 张 → 目标队友选择供应堆 1 张补牌 → 回合结束。
  - 救生艇：全员弹层选 1 张并显示“已选/未选”，全部就绪后同时传给左手边；当前玩家继续本回合。
  - 罐头食品：确认后直接跳过当前回合。
- **放置确认层**：显示“将 蓝 5 放到 第 3 行第 2 位？”，列出支撑、颜色判定、数字判定、目标卡判定；因纽特智慧生效时注明“允许与紧邻卡牌同数字”；确认后不可撤销。
- **补牌层**：展示 3 张供应堆牌背（颜色），必须选择 1 张；选择后手牌重排并进入下一回合。
- **卡住层**：显示“当前没有可放置的卡牌”，列出可用物品；可“宣告失败”。
- **结算层**：胜利/失败、回合数、最终棋盘、再来一局/返回设置。
- **规则层**：四个标签页（流程 / 四条规则 / 物品 / 胜负），用原创 SVG 小图示意，不复刻原画。

### 交互与可用性

- 颜色 + 形状双重编码：蓝=圆形/波浪，红=三角形/火焰，黑=菱形/山形；合法/非法原因用文字说明，不仅靠颜色。
- 全按钮 `aria-label`，焦点可见；支持键盘（Tab/Enter/Esc）。
- `prefers-reduced-motion` 下关闭翻牌/连线动画。
- 响应式：320×568、390×844、768×1024、844×390、1280×800；横屏/桌面时棋盘与操作面板左右分栏。
- 不横向溢出；棋盘用 `clamp()` 与容器比例缩放。
- 视觉：原创明亮冷色调北极风（白/浅灰冰面、冰川蓝、红帆点缀）与海图氛围（网格、同心圆航线、罗盘线稿），不使用 OINK 原插画/Logo。

## 12. 测试

### 单元测试（`node test-core.js`）

1. **设置**：27 张唯一冰山卡；5 张目标卡；单人 4 张手牌；供应堆 3；抽牌堆 20；单人物品 3 个且类型允许重复。
2. **难度**：新手 0 张目标卡正面；中等位置 1/3/5 正面；专家 5 张正面。
3. **规则①**：第 1 行可放；第 2 行左右端各需下方 1 张；第 3 行中间需下方 2 张；缺支撑时非法。
4. **规则②**：下方每张牌的上方两张至少一张同色；另一张上方为空时义务延后；书中示例（蓝 2 已由蓝 5 接续、黑 5 上方只有红 8 → 空位必须补黑）；黑 9 不得压在没有蓝色接续的蓝 9 上。
5. **规则③**：同行严格递增；空格插入需落在最近左右邻之间；同行相等非法；不同行相等合法；因纽特智慧仅对紧邻同数字允许相等（3/5 之间 3、4、5 均可），隔空同数字非法；航海日志不享受豁免。
6. **规则④**：正面目标卡颜色强制；背面不强制；新手全不强制；中等仅 1/3/5；专家全部。
7. **回合/补牌**：放置→补牌→下一回合；手牌数恒定；抽牌堆非空时供应堆保持 3；抽牌堆空则供应堆减少；有供应堆时必须补牌。
8. **胜利**：填满 15 位立即胜利，不执行补牌。
9. **卡住/失败**：无合法落子进入 `stuck`；物品可解救；宣告失败进入 `lost`。
10. **物品**：因纽特智慧使用后本回合可与紧邻卡牌同数字、放置后效果结束且只补 1 张；无豁免落点时不可使用；卡住时可解救；狗拉雪橇回底+取供应堆+补供应堆；航海日志换牌校验且不吃因纽特豁免；已用物品不可再用；单人池不含无线电/救生艇/罐头食品。
11. **种子复现**：相同 seed + 相同操作序列 → 相同 `stateHash`。
12. **书中胜利牌型**：按第 5 行 `1,2,5,8,9`、第 4 行 `3,4,5,7`、第 3 行 `5,6,9`、第 2 行 `6,7`、第 1 行 `4`，颜色按规则④示例（蓝,蓝,红,黑,红 / 蓝,红,黑,红 / 蓝,黑,黑 / 蓝,黑 / 蓝），目标卡颜色（蓝,蓝,红,黑,红）从下往上放置，引擎应全部接受。
13. **规则②回归**：用户截图残局（r4-4 黑 9 压在 r3-3 蓝 9 上、左侧红 8，蓝 9 上方无蓝色接续）必须被拒绝；两侧上方为空时允许先放新颜色，后续补验。
14. **联机发牌**：2 人各 4 张、3/4 人各 3 张；27 张总数 = 手牌 + 供应 3 + 抽牌堆；每人手牌升序；随机先手由种子复现。
15. **联机轮转**：放置 → 补牌 → 下一座位；`turn` 只在回合完成时 +1；罐头食品跳过回合；手牌为空轮到该玩家时判负。
16. **联机物品**：因纽特/雪橇/日志只作用于当前玩家；无线电为“当前玩家选队友的 1 张牌 → 队友从供应堆补 1 张 → 回合结束”；救生艇全员暗选后同时传给左手边，只有当前玩家能结算；罐头可在放置或卡住时跳过。
17. **联机权限**：非当前玩家不能放置/补牌/使用物品；无线电补牌阶段只有目标玩家能选供应堆；救生艇阶段每位玩家只能修改自己的选择。
18. **联机共享**：棋盘、供应堆、抽牌堆、抽出的 3 张物品全队共享；队友手牌只暴露颜色与升序位置。
19. **联机新鲜度**：每次成功操作 `rev` 递增；救生艇并发选牌合并后不丢选择。

## 14. 待确认 / 假设

1. **规则②示例（已确认）**：书中“右边已经放置红色卡牌，所以这里只能放置黑色卡牌”为硬规则，按“下方每张牌的上方两张至少一张同色”实现；另一张上方为空时义务延后。用户截图的黑 9 残局已作为回归用例。
2. **颜色必须连到第 5 行**：作为提示/航线状态，还是作为硬性终局条件？MVP 不作为额外失败条件（胜负只看“填满 / 无法放置”），只显示未连到第 5 行的颜色提醒。
3. **供应堆牌背信息**：MVP 只显示颜色，不显示数字/相对值；如实体牌背显示更多，可调整。
4. **因纽特智慧的“旁边”（已确认）**：只允许同一行左右紧邻（index ±1）的同数字；隔空同数字不允许，否则中间空位将无牌可放。是否允许跨行斜邻暂不开放。
5. **物品时机**：狗拉雪橇/航海日志可在放置前或“卡住”时使用；因纽特智慧在**放置前**使用、本回合生效，放置完成即结束；无线电广播只在补牌阶段使用；救生艇在放置/卡住时使用；罐头食品在放置/卡住时使用。
6. **物品抽取**：单人与联机都随机抽 3 个/张，允许重复类型（联机池为 6 类 ×2 共 12 张）。
7. **中等难度翻开位置**：两端 + 中间 = 1/3/5。
8. **15 个位置全部是冰山卡**；起始卡/目标卡在底层，不计入 15 张。
9. **联机无线电（已确认）**：由当前玩家自选目标队友的 1 张牌，目标队友再从供应堆自选 1 张补回；当前玩家只看到目标手牌的牌背，不查看数字。
10. **联机物品操作权（已确认）**：仅当前回合玩家可发起物品；救生艇发起后全员参与选牌。
11. **联机信任模式**：与炸弹克星一致，完整手牌随房间状态广播，客户端只负责不渲染他人牌面；不实现服务端隐藏信息。

## 16. 联机模式详细规格

### 16.1 房间与流程

- 2~4 人，至少 2 人才能开始；房间号 4 位数字，数据库 ID 前缀 `frozen-`。
- 流程：设置页「联机模式」→ 创建/加入房间 → 等候室（房主选难度）→ 房主开始 → 发牌与随机先手 → 对局 → 全队结算 → 房主可回到房间再来一局。
- 房主是房间创建者（座位 0）；成员按 `join_room` RPC 分配座位，并发加入不会拿到重复座位。
- 成员在等候室退出只移除席位；对局中任意成员退出，本局无法继续，由房主解散房间。
- 观看/重连：刷新页面后通过 `localStorage['frozen-online']` 找回房间与座位，应用房间最新快照；不重新占座。

### 16.2 发牌与先手

- 冰山卡洗混，按座位轮流发牌：2 人各 4 张，3/4 人各 3 张；每人手牌升序。
- 供应堆 3 张；其余进抽牌堆。
- 先手座位由种子 PRNG 随机决定，写入 `currentSeat` 与开局日志；同一 seed 可复现。
- 目标卡、难度由房主在等候室确定；成员端只读。

### 16.3 回合与操作权

- `currentSeat` 是当前回合玩家；`turn` 在该玩家完成“放置 → 补牌”或被罐头跳过后 +1，座位顺时针轮转。
- `activeSeat` 表示当前真正可操作的人：
  - 普通阶段 = `currentSeat`；
  - 无线电补牌阶段 = `pending.toSeat`；
  - 救生艇阶段 = `-1`（全员都可选自己的牌）。
- 引擎 `canSeatAct(state, seat)` 统一判定操作权；渲染、online 推送与操作校验都使用它。
- 非当前玩家不能放置、补牌、使用物品，也不能替别人选牌。

### 16.4 交叉状态

```js
// 无线电：A 已取走 B 的 cardId，等待 B 从供应堆补 1 张
pending = {
  type: 'radio',
  fromSeat: 0,
  toSeat: 2,
  cardId: 'red-5',
  stage: 'supply'
}

// 救生艇：全员暗选，picks[seat] 为 null 表示尚未选择
pending = {
  type: 'lifeboat',
  picks: { 0: 'blue-2', 1: null, 2: 'black-4' }
}
```

- 交叉状态随房间快照同步；进入交叉状态时 `rev` +1。
- 无线电：`fromSeat` 已结束操作，只有 `toSeat` 能继续；完成后清空 `pending` 并轮转。
- 救生艇：所有玩家可反复修改自己的选择；收齐全员选择后，由 `currentSeat` 客户端调用 `completeLifeboat` 执行交换并清空 `pending`。其他客户端只合并不结算。
- 任何交叉状态下棋盘、物品面板保持只读（救生艇自己的手牌选择除外）。

### 16.5 联机同步与健壮性

- 复用炸弹克星方案：等待室 2.5s / 对局 5s 轮询兜底、频道故障自动重订阅、`visibilitychange` / `online` / `pageshow` 恢复重同步、推送串行化、未确认推送补发。
- 新鲜度：状态 `rev` 单调递增；在线层优先比较 `rev`，`_ts` 兜底，拒绝明显过期/重复快照。
- 推送 ID：`座位-时间戳-序号`，随状态快照附带 `_pushId`、`_src`、`_ts`。
- 行动者推送：当前可操作者（`canSeatAct`）可推送；救生艇阶段全员可推送。非行动者收到状态后只应用与渲染。
- 救生艇并发：各端收到 `pending.type='lifeboat'` 时，将远端 `picks` 与本地 `picks` 求并集（同一座位优先保留非空值）；若本地选择被远端覆盖为空，延迟重推合并后的状态。只有 `currentSeat` 在收齐全员选择后结算，避免重复传牌。
- 结算：终局状态随房间广播；各端展示结算层。房主可回到等候室，成员等待房主；对局中退出走「退出房间」。
- 断线期间的事件不重放，因此每次订阅成功、回到前台、网络恢复都必须主动拉取房间最新状态。

### 16.6 联机 UI 细节

- 大厅沿用流冰航路视觉：冰面背景、蓝红航线渐变；创建房间、4 位房间号输入、昵称输入、座位列表（色点 + 昵称 + 房主/座位标签）。
- 等候室：房主可见三张难度卡并切换，成员只读；开始按钮显示 `开始游戏 (N/4人)`，少于 2 人禁用。
- 对局顶栏：`联机 · N 人 · 第 X 回合`；信息条显示当前玩家/等待对象。
- 队友条：每位队友一行，`色点 + 昵称 + N张 + 缩略牌背`；缩略牌背按升序排列，只显示颜色。当前玩家/正在补牌的目标玩家高亮。
- 手牌区顶部标注“你的手牌 · N/上限”；非自己回合置灰但保持可见。
- 供应堆：共享；补牌阶段当前玩家可选；无线电补牌阶段只有目标玩家可选；其他时候只读。
- 物品面板：逐张显示抽到的 3 张共享物品，同类型显示多个物品标记；非当前玩家置灰。
- 联机菜单：规则、操作记录、退出房间；不显示“重开/清除存档”。
- 结算层：全队胜利/失败、回合数、最终棋盘；房主显示“回到房间”，成员显示“等待房主”；均可退出房间。

### 16.7 联机边界

- 手牌为空且轮到该玩家：全队失败（`lossReason='no-hand'`）。
- 供应堆为空：正常补牌阶段直接进入下一位；无线电不可用（需要目标从供应堆补牌）。
- 抽牌堆为空：供应堆只减不补；发牌与物品仍可继续。
- 救生艇要求全员手牌非空；否则按钮禁用并说明。
- 罐头食品用尽后，卡住玩家只能使用其他物品或宣告失败。
- 2 人局救生艇传给唯一的另一名玩家，等价于互相交换 1 张。
- 任何客户端都不能代其他玩家操作；房主也不代操作。
