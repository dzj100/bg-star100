# 同词相遇 (Same Word) — 联机默契猜词 规格说明

移动优先的单页 HTML 联机桌游，接入本站 Supabase 房间体系。
2 人玩「同心小径」，3~4 人玩「营地同频」；各写一个词、同时揭晓，看谁和谁能想到一起。

- 项目目录：`same-word/`
- 房间前缀：`sameword-`（用户可见 4 位房间号）
- 视觉主题：户外 / 大自然 / 活力 / 运动（营地徽章 + 山野日光）
- 目标：行为与文案完整对齐参考站 <https://zhuangci.pages.dev/>，底层改用本站的房间与同步方案

---

## 1. 参考站实现拆解（已读源码）

参考站「撞词了吗？」由 `core.js / home.js / play.js / classic.js / crowd.js` 五个脚本组成，
服务端为自建 RPC + WebSocket（`/api/v3`），客户端只持有服务端过滤后的视图。

### 1.1 技术结构

- 房间：6 位房间号，2~4 人；创建/加入/查看走 HTTP，对局操作走 WebSocket，HTTP 3 秒轮询兜底。
- 状态：服务端权威，每次操作返回完整视图 `v`（含 `version / me / phase / players / history / my_word / deadline` 等），客户端按 `screenKey` 重建页面，`updaters` 做局部刷新。
- 阶段：`lobby → playing → reveal → finished`。
- 秘密词只由服务端下发自己的词；揭晓后进入 `history`。
- 图片分享：Canvas 手绘长图，导出 PNG/JPEG，弹层内长按保存。
- 动画：3D 翻牌（逐个 230ms）、撞词彩带、结算弹层、倒计时环、按钮防连点。
- 断线：WebSocket 心跳 + 轮询 + 页面回前台重连。

### 1.2 两套玩法

| | 「撞词了吗？」（2 人） | 「众里寻TA」（3~4 人） |
|---|---|---|
| 轮次 | 不限，直到撞上/双方认证/放弃 | 10/15/20/自定义 5~50 局 |
| 每轮提示 | 第 1 轮自由想；之后以上一轮两人的词为起点继续联想 | 每局自由想，可看历史 |
| 得分 | 无分数，按第几轮撞上给「默契称号」 | 每撞上一对，两人各 +1；个人分 = 参与对数 |
| 额外判定 | 两人都可选「意思一样」，双方都选即成功 | 可单方发起「和我意思一样」，对方回点才成对；也可自动同词成对 |
| 结束 | 同词 / 双方认证 / 放弃 | 全员同词立即结束；打满局数；房主提前结束 |
| 结算 | 轮数 + 称号 + 脑回路轨迹 | CP 榜 + 个人默契分 + 名次称号 + 每局词表 |

### 1.3 本站保留与替换

保留：全部规则、文案、判定优先级、称号表、历史展示、分享长图结构、房主控制权。

替换：
- 6 位房间号 + 自建服务端 → 本站 4 位房间号 + Supabase `rooms` 表 + Realtime（`net.js` / `online.js`）。
- 服务端权威 → 房主权威 + 按座位字段所有权 + `rev` 乐观锁合并（见 §6）。
- WebSocket 主动推送 → Realtime UPDATE + 定时轮询兜底。
- 参考站糖果色 → 户外自然运动主题（见 §7）。
- 参考站「历史词不可重复」的校验删除：本作**允许任意重复词**（产品决策）；重复词仍正常参与撞词/认证。

> 注：参考站服务端 RPC 未公开，本文只依据客户端可观察行为拆解。涉及服务端的细节（如 allmatch 的成对计分、双人「一方同意一方下一轮」是否即时推进）按客户端文案推断，并在 §3 中明确定义为本作规则，不追求与参考站字节级一致。

## 2. 产品范围

### 2.1 本期做

- 联机创建/加入房间（4 位房间号、邀请链接、复制/分享）。
- 2 人模式「同心小径」（`mode: 'duel'`）。
- 3~4 人模式「营地同频」（`mode: 'party'`）。
- **允许重复词**：同一词可在不同轮次、由不同玩家反复使用。
- **英文判同不区分大小写**（全半角、标点/空白同样不计入判同）。
- 每轮限时（不限 / 15 / 30 / 60 秒）、草稿自动提交、撤回重写。
- 同词/互认判定、计分、称号、完整历史、分享长图、再来一局。
- 刷新重连、断线补拉、房主强制推进、成员离席处理。

### 2.2 不做

- 单人/AI 练习、观战席、聊天/语音、排行榜持久化。
- 服务端权威反作弊：词会随共享状态广播，采用本站既有的「朋友间信任模式」，UI 只渲染自己的词（与手牌同策略）。
- 参考站的免费额度/备用入口逻辑。

## 3. 规则模型

### 3.1 通用

- 昵称：1~12 字；存 `localStorage`（`sameword-name`），下次预填。允许重名，以座位区分。
- 词：1~10 个 Unicode 码点（`Array.from` 计数），首尾去空白、内部连续空白折叠为 1 个空格。
- 判同归一化：`NFKC（全角/半角统一）→ 小写（英文不区分大小写）→ 去除空白与标点（\p{P}、~～·…）`。
  - 展示保留原文；判同用归一化结果。
  - 例：`Hello` / `hello` / `HELLO` / `ｈｅｌｌｏ` 判同；`hello!` 与 `hello` 判同；`苹 果` 与 `苹果` 判同。
  - **已确认**：标点、空格、全半角一律忽略；仅当归一化后为空（纯符号）才拒绝：「不能只有符号哦」。
- **允许重复词**：同一词可在不同轮次、由不同玩家反复使用；重复出现仍可正常触发撞词/认证。不做历史词池校验，不提示「前面出现过了」。
- 每轮所有人同时写、互相不可见；全部提交或倒计时结束才揭晓。
- 倒计时最后一刻（剩余 ≤350ms）若输入框有合法草稿，客户端自动提交；不合法或为空按超时未写处理。
- 揭晓前可「撤回重写」；揭晓后撤回返回 `TOO_LATE`（前端禁用）。
- 超时未写：该轮词为空，显示「超时」；双人模式下本轮不可「意思一样」，多人模式下该玩家本轮不可发起/接受认证。
- 限时由房主在开局前设定：`0（不限时）/ 15 / 30 / 60` 秒，逐轮重置。

### 3.2 双人「同心小径」（duel）

1. 第 1 轮自由想一个词。
2. 第 2 轮起，以上一轮两人的词为联想起点：「从这两个词出发，想一个能把它们连起来的词」。空词位显示「超时」，不参与联想提示。
3. 揭晓：
   - 两个词归一化后相同 → **match**，进入撞词庆祝页（彩带 + 盖章），自动进入结算。
   - 不同 → 每人可表态：
     - 「🤝 我认为意思一样」→ 记 `same`；
     - 「进入下一轮 →」→ 记 `next`。
     - **双方都完成表态后才推进**：双方都选 `same` → **agree** 结算；否则（任一方选 `next`）→ **进入下一轮**。
     - 任一方未表态前都不推进；已表态方界面提示「已表态，等 XX 也表态后才推进」。
     - 本轮有超时空词时，「意思一样」按钮禁用，只能下一轮。
4. 放弃：任一玩家可「想不到了？放弃，看结算」，二次确认后 → **giveup** 结算。
5. 结束条件：match / agree / giveup。

### 3.3 多人「营地同频」（party）

- 人数：3~4；总局数 10 / 15 / 20 / 自定义 5~50；可看完整历史。
- 每局全员各写一个词，同时揭晓。
- 成对与计分（每对两人各 +1，一局最多 `C(n,2)` 对）：
  1. **撞词对（exact）**：两人归一化后同词，自动成对，不可取消。
  2. **认证对（agree）**：A 点 B 的「🤝 和我意思一样」发起；B 回点 A 才成对。
     - 单方发起显示「已认证，等 TA 确认」；被发起方显示「TA 说和你一样，确认？」。
     - 可在本轮推进前取消自己的发起。
     - 任一方本轮空词 → 该对不可发起/接受。
     - 已撞词对显示「✓ 撞上了」，按钮禁用。
- 全员写同一个词 → **allmatch**：立即结束，该局按所有两两组合计分，庆祝后结算。
- 推进：
  - 每人可点「准备好了，下一局 →」/「准备好了，看结算 →」，可取消；**全员 ready 自动推进**。
  - 房主可「不等了，直接下一局 / 直接看结算」强制推进。
  - 房主可「提前结束，看结算」（二次确认）→ **giveup** 结算。
  - 打满最后一局且未全员同词 → **limit** 结算。
- 已离席玩家视为自动 ready、不可被认证、不参与分数与称号。

### 3.4 判定优先级与结束

- 双人：
  1. 两词归一化后相同 → **match** → 撞词庆祝页（2.7s）→ 自动结算（不再投票）。
  2. 不同 → 双方分别投票：「意思一样 / 下一轮」。
     - **双方都完成表态后才推进**。
     - 双方都选「意思一样」→ **agree** → 进入结算。
     - 否则（任一方选「下一轮」）→ 继续下一轮，不结算。
     - 一方未表态 → 等待；房主可「不等了，下一轮」强制推进作为失联兜底。
- 多人：
  - 单个撞词对/认证对只加分，**不结束本局**。
  - 全员同词 → **allmatch** → 庆祝页 → 立即结算。
  - 否则打满局数 → **limit** 结算；房主提前结束 → **giveup** 结算。
- 所有结算入口只执行一次：先把 `phase` 锁到 `finished` 并写入 `result`，再推送给各端；避免重复弹结算/重复计分。

### 3.5 结算与称号

**双人**：按 `history.length` 取称号。

| 轮数 | 称号 | 文案 |
|---|---|---|
| 1 | 灵魂双胞胎 | 第一轮就撞上？你们是不是共用一个脑子！ |
| 2 | 脑电波同频 | 只绕了一个弯就会合，这默契可以上综艺了 |
| 3 | 心有灵犀 | 一点就通，好搭子认证 ✓ |
| 4~5 | 默契搭子 | 绕了点路，但终究想到一块儿去了 |
| 6~8 | 渐入佳境 | 兜兜转转，最后还是想到了一起 |
| 9~12 | 脑内环游 | 你们的脑回路绕了地球一圈才碰头 |
| 13+ | 平行宇宙重逢 | 跨越了 N 轮，终于在同一个宇宙相遇 |
| giveup | 信号失联 | 今天的脑电波没对上频道，换个时间再战！ |

- 主标题：match →「你们在第 N 轮想到了同一个词！」；agree →「达成「意思一样」认证 🤝」；giveup →「一起坚持了 N 轮 / 这局还没开始就结束了」。
- 展示完整「脑回路轨迹」：轮次 | 两人词 | 命中标记；agree 行加「🤝 双方认证意思一样」。

**多人**：
- 个人分 = 其参与的所有对数之和；CP 榜 = 每对在全场累计对数，降序（同分按座位 a、b 升序）。
- 名次：`rank = 1 + 分数更高的人数`；同分同名次且占位（5,5,2 → 1,1,3）。

| 人数 | 第 1 / 2 / 3 / 4 名称号 |
|---|---|
| 3 | 万人迷 / 比较标准的脑回路 / 独立寒秋的脑回路 |
| 4 | 万人迷 / 比较标准的脑回路 / 有点特色的脑回路 / 独立寒秋的脑回路 |

- 全员同分且 >0 → 三胞胎（3 人）/ 四胞胎（4 人），注「可以去驾驶EVA了」。
- 全员 0 分 → 各自美丽，注「都这样了还能做朋友吗！？」。
- 最强 CP 称号（按最高对数）：≥6 天选 CP；≥4 默契老夫老妻；≥2 心有灵犀 CP；1 一撞钟情。
- 结算页：主视觉（几局 / 结局）、最强 CP、我的最佳 CP（"还在寻找中…"空态）、CP 榜条形图、个人默契分与称号、每局词表（黄底=撞上、🤝/💥 注记）。

### 3.6 再来一局与离席

- 再来一局需**所有在座玩家**确认；有人确认后按钮显示「XX 想再来一局，冲！」；已确认者显示等待。全员确认 → 同座位、同设置开新局（`gameNo+1`，清空历史/计分/词池）。
- 结算页允许离席；剩余人不足最低人数时不可再开。
- 游戏中成员离开：标记 `departed`，本轮按空词处理，后续轮次自动超时，认证/准备自动跳过；房主可强制推进。
- 房主离开：房间解散；对局中先弹出当前结果提示，再回首页。

## 4. 流程与页面

### 4.1 首页（着陆）

```
┌────────────────────────────┐
│                    📜 规则 │
│      ⛰️ 山野插画 / 帐篷     │
│         同 词 相 遇         │
│         SAME WORD          │
│   2~4 人 · 默契猜词        │
│  各写一个词，同时揭晓，     │
│  看谁和谁能想到一起          │
│  [ 创建房间 ]               │
│  [ 加入房间 ]               │
│  @imStar100                │
└────────────────────────────┘
```

- 创建房间弹层：昵称、玩法（同心小径 2 人 / 营地同频 3~4 人）、限时、总局数（仅多人）、创建。
- 加入房间：4 位房间号 + 昵称；也可从邀请链接 `?room=1234` 直达加入页。
- 规则弹层：两套玩法说明、计分、称号、隐私说明。

### 4.2 等候室

- 大字 4 位房间号 + 邀请链接 +「复制邀请」「分享邀请」。
- 座位卡：号码布头像（1~4）、昵称、房主标记、已就位/等待加入；双人模式固定 2 席，多人模式 4 席（第 4 席可选）。
- 顶部显示玩法、限时、局数；房主可在开局前修改限时/局数（同步到成员端）。
- 房主：人数达到最低（2 / 3）后「开始游戏！」；成员：「等 XX 开始游戏…」。
- 离开房间二次确认。

### 4.3 出词

```
第 3 轮 / 共 10 局        ⏱ 23s
● 阿山 已提交   ○ 小湖 思考中   ○ 阿岩 离线
┌────────────────────────────┐
│ 上一轮大家写的是            │
│ [西瓜] + [空调]  （双人）    │
│ 或 [西瓜][夏天][空调]       │
│ 💡 从这些词出发，想一个…     │
└────────────────────────────┘
┌────────────────────────────┐
│ 写下你想到的词   4/10       │
│ [________________________] │
│ [       提交，盖住！       ] │
└────────────────────────────┘
```

- 已提交：显示蜡封卡（自己的词）+「等 XX 写完」+「撤回重写」。
- 双人模式第 1 轮文案「第一轮，随便想一个词！」。
- 多人模式可展开「完整历史（N 局）」表格，命中词高亮。
- 双人模式底部「想不到了？放弃，看结算」；多人模式仅房主「提前结束，看结算」。
- 倒计时环：橙色，≤5s 变红并脉冲；超时文案「时间到，等待揭晓…」。

### 4.4 揭晓

- 词卡按座位顺序逐个 3D 翻牌（250ms 起、每张 +230ms）；同一 `roundKey` 只播一次（sessionStorage 标记，刷新不重播）。
- 双人：标题「差一点点！」/「撞上啦！！」；两张词卡；表态区（见 §3.2）。
- 多人：标题「这局没人撞上～ / 有人撞上啦！/ 撞上了 N 对！」；每张他人词卡下挂认证按钮；「本局得分」列表；准备按钮 + 已准备人数；房主强制推进/提前结束。
- 撞词庆祝：进入独立全屏页（词卡 + 盖章「撞上啦/全员同频」+ 彩带），2.7s 后自动进结算。

### 4.5 结算

- 双人：主视觉（第 N 轮 / 称号 / 文案）、脑回路轨迹、再来一局、生成分享图、回到首页。
- 多人：主视觉、最强 CP、我的最佳 CP、CP 榜、个人默契分与名次、每局大家写了什么、再来一局、分享图、回到首页。
- 分享图：Canvas 900px 宽动态长图；>3000px 导出 JPEG(0.9)，否则 PNG；弹层内「下载图片」+ 长按提示。

### 4.6 状态页

- 房间不存在/已过期、房间已满、游戏已开始、连接失败，均给「自己开一局 / 重试」。

## 5. 状态结构

共享状态（`rooms.state`，随 Realtime 同步）：

```js
S = {
  schema: 1,
  mode: 'duel' | 'party',
  settings: {
    timeLimit: 0 | 15 | 30 | 60,
    roundLimit: 10 | 15 | 20 | 3..50,   // 仅 party，duel 忽略
  },
  seatNames: ['阿山', '小海', '橙子', '紫苏'],  // 开局快照；离开者仍可显示
  phase: 'playing' | 'reveal' | 'finished',
  gameNo: 1,
  round: 1,

  subs: {                      // 本轮提交；只由该座位本人写（房主超时可代填空）
    0: { word: '西瓜', at: 1710000000000, done: true, round: 1 },
    // at：该座位本地时钟，仅与同座位旧值比较
  },
  deadline: 1710000015000,     // 房主时钟；0 不限时为 null
  hostNow: 1710000000000,      // 房主写状态时的 Date.now()，用于各端时钟对齐
  history: [{
    round: 1,
    words: ['西瓜', '空调', '夏天'],        // 空串 = 超时
    pairs: [{ a: 0, b: 2, kind: 'exact' | 'agree' }],
    all: false,
  }],

  decisions: { 0: { value: 'same' | 'next', at }, ... },   // duel 揭晓
  claims: { 0: { 1: { on: true, at } }, ... },             // party 有向认证 from→to
  ready: { 0: { on: true, at }, ... },                     // party
  rematch: { 0: { on: true, at }, ... },

  result: null | 'match' | 'agree' | 'giveup' | 'limit' | 'allmatch',
  resultBy: 0 | null,
  departed: [2],

  // 同步元数据（见 §6）
  rev: 12,
  _ts: 1710000000000,
  _pushId: '0-1710000000000-12',
};
```

本地（不共享）：

```js
L = {
  mySeat, mode, roomCode, token, name,
  draft: '', draftRoundKey: null,
  pendingFields: { ... },      // 未确认的己方字段，重连/合并后补发
  screenKey, lastRev, lastEventKey,
  timerOffset,                 // hostNow - Date.now()，用 hostNow 校准倒计时
  shareImage, sheetOpen, ...
};
```

## 6. 联机架构

复用 `net.js`（Supabase 房间 CRUD + Realtime + `cache:'no-store'`）与 `online.js`（等候室、席位、重连、轮询、推送串行化）。
在此基础上增加下列规则。

### 6.1 房间与权限

- `ROOM_PREFIX = 'sameword-'`，`MAX_PLAYERS = 4`；用户输入 4 位数字。
- 房主 = 座位 0；`status: waiting | playing | finished`。
- 加入仅限 `waiting`；玩法在创建时固定。双人模式满 2 人即锁定，多人模式 3 人可开、第 4 人可中途加入等候室。
- 开始游戏、轮次推进、超时结算、强制推进、提前结束：**仅房主**写 `phase / round / history / deadline / result`。
- 提交词、表态、认证、准备、再来一局：**仅本人**写自己座位字段（与 take-time 的「仅当前回合玩家可推」不同，见 §6.6）。

### 6.2 并发提交：字段所有权 + rev 乐观锁

多人同时提交会竞态（Supabase 整行 UPDATE 是后写覆盖）。方案：

1. 每个可写字段按座位归属（`subs[seat]`、`decisions[seat]`、`claims[seat]`、`ready[seat]`、`rematch[seat]`），写前先拉最新房间状态，合并后再写。
2. 同座位字段带 `at`：合并时只保留 `at` 更大的值（跨设备时钟不参与不同座位比较）。
3. `state.rev` 每次写入 +1；`netUpdateGameState` 增加 `expectRev`，用 PostgREST 条件 `.eq('state->>rev', expectRev)` 更新；
   影响行数为 0 表示被抢写 → 重新拉取、重合并、重试（最多 3 次，指数退避 200/500/1000ms）。
4. 收到推送时：`rev <= lastRev` 丢弃；`rev` 跳号仍接受（Realtime 可能合并事件）。
5. 客户端写状态后 600ms 复核一次；若发现自己提交的轮次/字段被旧快照覆盖，自动补发。
6. 房主在 `playing` 期间每 1.2s 合并一次全房提交（拉取 + 比较），发现全员完成立即推进；超时统一代填空词后推进。
7. 若 PostgREST 不支持 `state->>rev` 过滤（M1 联调验证），降级为：读-改-写 + 写后 600ms 复核 + 房主 1.2s 对账，语义不变、仅冲突窗口从 0 变为约 1 个网络往返。

> 效果：任何一次写入都不会丢失其他座位的字段；最坏情况是重试一次。`rev` 在房间生命周期内单调，不因新局清零。

### 6.3 倒计时

- 房主开局/新轮写入 `deadline = hostNow + timeLimit*1000`（不限时为 `null`）。
- 各端 `timerOffset = hostNow - Date.now()`；显示剩余 = `deadline - 1000 - (Date.now()+timerOffset)`（留 1s 网络缓冲）。
- 非不限时：剩余 ≤350ms 自动提交草稿（每位玩家各自提交自己的）。
- 房主在 `deadline + 800ms` 宽限期后仍未收齐，代未交者写入空词并推进揭晓。
- 房主设备休眠导致推进延迟：任何成员在 `deadline+8s` 后看到仍未推进，可显示「房主暂时离线，等待恢复…」；不做成员代推进（避免双权威）。

### 6.4 推送与恢复（沿用 take-time 在产方案）

- 推送串行化 `_pushInFlight/_pushQueued`；未确认推送保留快照，收到同 `rev` 后清除。
- 定时轮询：等候室 2.5s、对局中 2.5s（15s 短轮次需要更快兜底；后台不跳过）；Realtime 状态异常 2s 重订阅；`visibilitychange / online / pageshow` 重建频道并强制拉取。
- 快照防护：`rev` + `_ts`（3s 容差）+ `_pushId` 去重；重同步时 `force` 应用权威状态。
- 刷新重连：`localStorage['sameword-online'] = { room, token, seat, name, at }`；同 token 回原座位；对局中恢复未提交草稿与未确认字段。
- 座位跟踪：漏收离开事件时以房间 `seats` 为准；成员离开标记 `departed` 并推送。
- 房主离开：`status=finished` + 提示后解散。

### 6.5 信任模型

词随共享状态广播，理论上可通过开发者工具偷看。与本站手牌策略一致：
UI 只渲染自己的词，揭晓前不提供任何他人词入口；不做加密/服务端过滤。
规则弹层与 SPEC 明确「朋友间信任模式」。

### 6.6 与 take-time 联机模板的复用结论

| 能力 | take-time 现状 | 本作处理 | 难度 |
|---|---|---|---|
| 断线/刷新/僵尸连接 | 成熟：重订阅 + 轮询 + force 重拉 + 未确认补发 | 直接复用，只改 `SESSION_KEY`、轮询节奏、合并钩子 | 低 |
| 离席 | 房主接管离席座位（回合制可代打） | **不接管**：本轮空词、后续自动空词、不能认证、自动 ready；房主强制推进 | 低（更简单） |
| 倒计时 | 无 | 新增：`deadline + hostNow` 校时 + 各端自动提交 + 房主宽限收口 | 中 |
| 推送守卫 | 仅当前回合玩家可推；本人操作时忽略远端 | 改为：本人可推自己的字段、房主推阶段；**移除「本人操作忽略远端」**，始终按 rev 合并 | 中（主要改造点） |
| 轮询节奏 | 等候 2.5s / 对局 5s | 等候 2.5s / 对局 2.5s | 低 |
| 并发写 | 单写者（当前玩家） | 多写者：按座位字段所有权 + rev 乐观锁 + 房主 1.2s 对账 | 中 |

结论：**断线最好处理，直接复用；离席改语义后更简单；倒计时是新做但风险可控。真正需要重写的是推送守卫与并发合并，不是这三项。**

## 7. 视觉规范：户外 · 自然 · 活力 · 运动

### 7.1 设计语言

- 意象：白天的山野步道、营地徽章、号码布、路标、等高线地图。
- 关键词：日光、松林、湖蓝、陶土橙、奶油纸、细描边、户外手册/营地徽章、轻微旋转。

### 7.2 色板（CSS 变量）

`body` 背景：天空渐变 `--sky-1 → --sky-2` + 底部两层山脊（CSS `clip-path`/内联 SVG）+ 5% 透明等高线噪声。

### 7.3 字体与比例

- `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`，标题 700，正文 500~600。

- 大数字（轮数/分数）使用重体 + 微斜，像成绩牌；数字统一 `font-variant-numeric: tabular-nums`，倒计时不跳位。
- 字号下限：次要信息 ≥12.5px；正文 13.5~14.5px；倒计时/轮次/得分 ≥17px；结算大数字 38~50px。
- 触控目标 ≥44×44px；输入框 ≥16px 字号防 iOS 自动放大。

### 7.4 界面层级（每屏一个主行动）

| 屏幕 | L1 视觉焦点 | L2 次级 | L3 折叠/弹层 |

### 7.6 动效编排（feedback tiers）

每个事件只叠 2~3 个反馈通道；短暂、可回落，不改变常态。

| 级别 | 事件 | 反馈组合 | 时长/缓动 |
|---|---|---|---|
| S | 按钮按下 | 下沉 2px + 阴影收 1px + 缩放 .98 | 80ms ease-out |
| S | 提交成功 | 蜡封卡 squash（1.06/0.94 → 1）+ 勾选弹入 + 触觉 10ms | 160ms back-out |
| S | 认证/取消 | 按钮态切换 + 对勾/减号弹入 + 分值 pop | 180ms back-out |
| M | 翻牌 | rotateY 180° + 上浮 4px 回落；逐张错峰 230ms | 450ms cubic-bezier(.2,.8,.2,1) |
| M | 词卡/蜡封入场 | 缩放 .92 → 1 + 淡入 | 220ms ease-out |
| M | 弹层 | 底部滑入 + 遮罩淡入 | 240ms ease-out |
| M | 分数/CP 条 | 数字与宽度过渡 | 400ms ease-out |
| L | 撞词/全员同频 | 盖章（1.6→1，-14°→-8°）+ 彩带 80 片 + 容器 2px 位移 120ms + 触觉 [10,30,10] | 320ms back-out；彩带 2~3.5s |
| L | 结算入场 | 主视觉 .94→1 + 上浮 12px + 称号徽章延迟 120ms 弹入 | 420ms back-out |
| L | 胜利光晕 | 词卡外圈湖蓝/日光黄呼吸 2 次后静止 | 1.2s ease-in-out |

规则：

- 同一时刻只允许一个 L 级；L 级不阻塞输入（先结算状态，再播动画）。
- 位移只作用于视觉容器，文字不抖动；不用逐帧随机抖动。
- 关键信息必须有静态兜底（撞词同时显示标题 + 印章，不只靠彩带）。
- `prefers-reduced-motion: reduce`：翻牌改淡入、盖章直接显示、彩带关闭、位移归零，保留颜色/文字反馈。
- 可选音效（M4）：提交「嗒」、翻牌「唰」、撞词「叮咚」、结算「哨声」；WebAudio 合成、无素材文件，提供静音开关。

### 7.7 可读性与无障碍约束

- 固定 HUD 全部位于 `safe-area-inset-*` 内，不倒贴屏幕四角。
- HUD 文本带 2px 对比描边/阴影，保证在山野背景上可读。
- 触控目标 ≥44px、间距 ≥8px；键盘 `:focus-visible` 有 3px 高对比描边。
- 颜色 + 图标/文字双编码，不只靠红绿区分「撞上/没撞上」。
- 对比度：松墨 `#22301F` 对奶油 `#FBF7EC` ≥4.5:1；森林绿按钮上的奶油字 ≥4.5:1。
- 倒计时最后 5 秒：变色 + 脉冲，不抖动数字位置。
- 规则弹层可滚动、可关闭；弹层内焦点不逃逸（Tab 循环）。

### 7.8 布局（移动优先）

- 内容宽 `min(100%, 480px)` 居中，`padding: 12px 14px calc(20px + env(safe-area-inset-bottom))`。
- 单列主流程；结算页为可滚动的长页；底部主按钮固定时避开 safe-area。
- 三档回归：320 / 390 / 480px 无横向滚动；横屏不强制支持，但布局不崩。
- 输入框 16px；所有按钮/词卡可点区域 ≥44px。

## 9. 边界情况清单

1. 纯标点/空白词 → 拒绝。
2. **允许重复词**：跨轮、跨人均可复用；重复词仍参与撞词/认证，不提示「已用过」。
3. 英文判同不区分大小写；全半角、标点、空白不计入判同；展示保留原文。
4. 本轮多人同词 → 允许，用于撞词计分。
5. 限时到点自动提交草稿；无草稿/非法草稿 → 空词。
6. 全部提交立即揭晓，不等满时长。
7. 撤回后本轮回到未完成；重新提交或到点收尾。
8. 双人双方都超时 → 揭晓只能下一轮；提示可放弃。
9. 双人双方都表态后，一方 `next` 一方 `same` → 下一轮；任一方未表态 → 等待。
10. 双人双方 `same` → agree；双方同词 → match（优先，直接结算）。
11. 多人三人全同词 → allmatch，三对均 +1，立即结算。
12. 多人单方认证不结对；双向认证才 +1；可取消自己的发起。
13. 多人任一方空词 → 本轮该玩家所有认证不可用。
14. 全员 ready → 自动下一局/结算；离席者视为 ready；房主可强制。
15. 最后一局打满 → limit 结算（非 allmatch）。
16. 房主提前结束 → giveup 结算，标明发起人。
17. 结算页全员确认才重开；人数不足时提示并禁用。
18. 游戏中离开 → 本轮空词、后续自动空词、认证/准备跳过；重连恢复原座位与草稿。
19. 房主离开 → 解散（对局中提示后回首页）。
20. 刷新/切后台 → 会话恢复；倒计时用 `hostNow` 校准，避免设备时钟偏差。
21. 并发提交 → rev 条件更新 + 重试；旧 rev 与旧轮次字段丢弃。
22. 非房主在非「当前回合」概念下也能推送自己的字段；房主阶段推送与成员提交合并互不覆盖。
23. 重复词连续两轮出现 → 仍可再次判同/计分（如双方连续写「西瓜」两次，第 2 轮仍判 match）。
24. 重复昵称 → 允许，用号码布区分。
25. 分享图超长 → 自动降采样并导出 JPEG，避免 iOS Canvas 上限。

## 10. 测试计划

### 10.1 单元测试（`node --check` + `test-core.js`）

- 归一化：英文大小写、全半角、标点/空白；字数；纯符号；**允许重复词**；草稿自动提交阈值。
- 双人：自由轮、链式提示、match/agree/next/giveup、称号边界 1/2/3/5/8/12/13、空词不可认证、重复词连续 match。
- 多人：exact/agree 配对、双向认证、取消、空词限制、allmatch、limit、giveup、个人分、CP 榜排序、同分并列、全 0/全同分特殊称号、重复词跨轮重复计分。
- 状态迁移：轮次推进/重置 `subs`、`deadline`、`gameNo`、再来一局清空。
- 合并协议：模拟两端并发写不同座位字段收敛；同座位 `at` 旧值被拒；旧 rev/旧轮次字段丢弃。
- 推送守卫：非房主可写自己的字段；房主阶段推送不覆盖成员刚提交的词；离席者自动空词/自动 ready/不计分。
- 倒计时：`hostNow` 校准、时钟偏差 ±30s 仍正确、房主宽限推进。

### 10.2 E2E（Playwright，移动视口）

- 双人全流程：建房 → 加入 → 出词（含限时自动提交）→ 揭晓 → next → 同词 → 庆祝 → 结算 → 重开。
- 双人认证：不同词 → 双方 `same` → agree；双方都表态后一方 `next` → 下一轮；单方表态不推进；撤回。
- 英文判同：A 写 `Hello`、B 写 `hello` → 直接 match 结算。
- 重复词：连续两轮双方都写 `西瓜` → 第二轮仍 match；多人跨轮重复词仍计分。
- 三人全流程：exact 撞词 + 双向认证 + 取消 + 全员 ready 自动推进 + 打满结算 + 称号/CP 榜。
- 三端同时提交：三个词都保留，不因并发写互相覆盖。
- 刷新重连：出词/揭晓/结算三处刷新，座位与草稿恢复，提交仍可同步。
- 离席：成员关闭页面 → 其余端显示离席 → 房主强制推进 → 结算不炸。
- 分享图：两种模式点击生成，Canvas 非空、弹层可打开。
- 视觉回归：320px / 390px / 480px 三档无横向滚动，safe-area 正常；`prefers-reduced-motion` 下无翻牌/彩带仍可完成流程。
