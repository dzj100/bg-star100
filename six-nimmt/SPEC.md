# 牛头王 6 nimmt! — 单机人机版规格说明（联机设计附录）

> 状态：**单机人机版已实现**；联机版列为后续阶段，本文第 3 节起保留联机设计参考。
> 目录：`six-nimmt/`
> 目标：在现有纯前端桌游平台内，新增一款支持 2~10 人规则的 6 nimmt! 卡牌游戏。当前版本先落地“1 名玩家 + 2~9 个 AI”的单机人机模式，后续再接入 Supabase Realtime 联机。

## 1. 游戏规则

### 1.1 组件

- 数字牌 1~104，共 104 张。
- 每张牌有“牛头值”（罚分）：

| 牌面 | 牛头值 |
|------|--------|
| 55 | **7** |
| 11、22、33、44、66、77、88、99（11 的倍数，55 除外） | 5 |
| 10、20、30、…、100（整十） | 3 |
| 5、15、25、35、45、65、75、85、95（个位为 5，55 除外） | 2 |
| 其余 | 1 |

判定优先级：55 → 11 的倍数 → 整十 → 个位 5 → 其余。任何牌至少 1 个牛头。

### 1.2 开局

1. 洗混全部 104 张。
2. 每位玩家发 10 张手牌（仅自己可见）。
3. 翻开 4 张牌，分别作为 4 行的第一张（行尾牌），4 行按行尾牌数值**升序**从左到右排列。
4. 本轮剩余未发的牌不使用，扣置一旁；**本轮没有摸牌堆**。

> 标准局每轮都会重新洗混全部 104 张并重新发牌，所以上一轮打出的牌会回到牌堆。

### 1.3 每局流程（共 10 墩）

1. 所有玩家同时从手牌中秘密选择 1 张，背面朝下。
2. 全部确认后，同时亮牌。
3. 按牌面数字**从小到大**依次放入场上。
4. 每张牌结算完，才处理下一张；放牌可能改变行尾，从而影响后续牌的去向。
5. 10 墩打完，所有手牌打空，本局结束，牛头总分最低者胜。

### 1.4 放牌判定

对一张打出的牌 `c`：

1. 在所有“行尾牌 < c”的行中，选择**行尾牌最大**的那一行（即最接近 c 的较小行尾）。
2. 若该行当前有 5 张牌：
   - 打出者收走这 5 张牌，计入牛头分；
   - 打出的 `c` 成为该行新的第一张（该行变为 1 张）。
3. 若该行不足 5 张：把 `c` 接在该行末尾。
4. 若 `c` 比**所有**行的行尾牌都小：
   - 打出者必须选择一行；
   - 收走该行**全部**牌（可能是 1~5 张），计入牛头分；
   - `c` 成为该行新的第一张。

> 关键：第 4 种情况不是“自动收最短行”，而是由打出者自己选。若同一墩有多人触发，按亮牌升序依次选择，前一个人的选择会改变后一个人的可选局面。

### 1.5 收牌与计分

- 收走的每张牌，把其牛头值**立即**加到自己的得分。
- 收走的牌进入自己的“收缴堆”，公开可见，便于核对。
- 打出的牌本身不收分；它要么接在行尾，要么成为新行首。
- 单局制不跨局累计分数；10 墩结束后直接按总分排名。

### 1.6 胜负

- 每局固定 10 墩，所有玩家手牌打空即结束。
- 牛头总分**最低**者获胜；并列最低则共享胜利（默认）。
- 当前版本不实现 66 分多轮制。

### 1.7 可选变体

| 变体 | 规则 | 当前版本 |
|------|------|----------|
| 标准单局 | 完整 104 张，每人 10 张，共 10 墩 | ✅ 已实现 |
| 战术局（Tactics） | 只使用 1 ~ (10 × 人数 + 4) 张牌 | 后续可选 |
| 66 分多轮制 | 累计 ≥ 66 后终局 | 后续可选 |
| 加时决平 | 最低分并列时再打一轮 | 后续可选 |

战术局用牌数：

| 人数 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 |
|------|---|---|---|---|---|---|---|---|----|
| 牌数 | 24 | 34 | 44 | 54 | 64 | 74 | 84 | 94 | 104 |

## 2. 数字版产品决策

1. **同时选牌**是核心。不能做成“轮流行动”，否则节奏和博弈感都会丢失。
2. **单机版采用本地权威**：页面内持有完整状态并驱动结算；AI 只读取 `SN.viewFor(seat)` 产出的安全视图，不接触其他人的手牌。
3. **不泄露手牌**是竞技公平性的关键。单机版本地即可做到 AI 视图隔离；联机版后续再加固网络层。
4. **动画可跳过**：高人数时一墩最多 10 次放牌；提供快速/减少动效路径，尊重 `prefers-reduced-motion`。
5. **移动端优先**：375×667（iPhone SE）竖屏下 4 行必须完整可见；压缩亮牌带与手牌区高度，桌面区域不滚动。10 张手牌保持扇形且不做整页横向滚动。

## 3. 联机架构（附录：后续阶段，当前未实现）

### 3.1 房间

- 复用共享 `rooms` 表与 `join_room` / `leave_room` RPC。
- 房号前缀：`sixnimmt-` + 4 位数字，例如 `sixnimmt-4821`。
- 最大座位：10；开局前可加入，开局后锁定座位。
- 座位号 0~9；创建者为 seat 0，即房主。
- 开始条件：≥ 2 人；推荐 5~7 人。
- 房主可在开局前踢出未准备的玩家（Phase 2，可选）。

### 3.2 权威模型

```
非房主客户端 ── action 广播 ──▶ 房主客户端
                                    │ 校验 + 结算
                                    ▼
                             rooms.state (rev+1)
                                    │ Realtime
                                    ▼
                              所有客户端渲染
```

- **只有房主写 `rooms.state`**；非房主不直接改状态。
- 动作通过 Supabase Broadcast 发送到 `sixnimmt-{roomId}-action`。
- 动作带 `actionId`（`seat-timestamp-seq`），房主去重；客户端每 2 秒重发未确认动作，直到状态 `rev` 前进或阶段变化。
- 房主对每个动作做完整校验：阶段、座位、是否轮到自己、牌是否在手、行号是否合法。
- 状态 `rev` 单调递增；客户端只接受 `rev` 更大的快照。

### 3.3 同步协议

客户端 → 房主：

```js
{ type: 'select',     seat, card,     actionId, ts }
{ type: 'chooseRow',  seat, rowIndex, actionId, ts }
{ type: 'nextRound',  seat,           actionId, ts }  // 仅房主
{ type: 'rematch',    seat,           actionId, ts }  // 仅房主
{ type: 'endGame',    seat,           actionId, ts }  // 仅房主
```

房主 → 所有人：完整 `state` 快照（写入 `rooms.state`，`status` 同步为 `playing` / `finished`）。

状态里额外携带：

- `rev`：快照版本号。
- `lastEvent`：最近一次结算事件，用于动画与日志。
- `lastActionId`：已处理的动作号，用于客户端确认重发。
- `deadline`：本墩选牌截止时间（毫秒时间戳），用于倒计时。

### 3.4 隐私模型

**Mode T（信任模式，MVP 默认）**

- `rooms.state` 包含所有玩家的手牌与已选牌。
- 前端只渲染自己的手牌，其他人的只显示“已选/未选”。
- 优点：与现有 `online.js` 模式一致，开发最快，刷新/重连最稳。
- 缺点：懂开发者工具的人可以直接看到所有人的手牌。

**Mode P（私有手牌，Phase 2）**

- 房主本地保存 `hands` 与 `selectedCard`。
- 公共 state 只包含 `handCount`、`selectedFlag`、分数、收缴堆、行、阶段。
- 发牌/每墩结束后，房主通过定向频道 `sixnimmt-{roomId}-seat-{seat}` 把该座位手牌发给对应客户端。
- 选牌动作只发给房主，公共 state 不出现牌面。
- 仍属于“防君子不防小人”：知道频道名仍可订阅，但需要主动作弊。
- 成本：约 +1~2 天，需要改 `net.js` / `online.js` 并增加重连补发逻辑。

> 默认按 Mode T 开发；若评审要求“手牌绝对不能出现在公共状态”，则直接按 Mode P 开发，不做两套并存。

### 3.5 断线、重连、房主

- 本地会话：`localStorage['six-nimmt-online'] = { roomId, seat, name, isHost }`。
- 刷新/断线重连：用最新 `rooms.state` 恢复；Mode T 下房主也可恢复。
- 非房主掉线：
  - 标记 `connected=false`；
  - 轮到其选牌时计时照常，超时自动锁最低牌；
  - 重连后恢复自己的手牌与已选状态。
- 房主掉线：
  - 游戏暂停在新状态，客户端提示“等待房主回来”；
  - 房主刷新后可恢复并继续；
  - 房主主动退出 / 超过 2 分钟未回：房间结束，提示“房主已离开”。
- 不做房主迁移（Phase 2 再考虑）。

### 3.6 计时器

- 每墩选牌默认 60 秒，房主可在开局前设置 30 / 60 / 120 / 关闭。
- 计时由房主裁决，`deadline` 随状态广播；客户端只做展示，不自行改状态。
- 超时未锁定的玩家：房主自动选择其手牌中**最小**的一张并锁定，日志记录“超时自动出牌”。
- 所有玩家锁定后，立即进入亮牌，不等待计时结束。
- 断线玩家同样适用超时代选，保证游戏不会卡死。

```js
S = {
  version: 1,
  mode: 'online',
  seed: 123456,                 // 可复现洗牌

       | 'selecting',
  round: 1,                     // 第几轮，从 1 开始

  settings: {
    targetScore: 66,

    singleRound: false,
    timerSec: 60,               // 0 = 关闭
    tieBreak: 'shared',         // shared | extraRound
    autoPick: 'lowest'
  },
  players: [
    {
      seat: 0,
      name: '玩家1',
      isHost: true,
      connected: true,
      score: 0,                 // 累计牛头分（含当前轮）
      roundScore: 0,            // 本轮已收牛头分
      hand: [12, 45, 77],       // Mode T 公共；Mode P 仅房主本地
      handCount: 10,
      selected: null,           // 已锁定的牌；Mode T 公共
      selectedFlag: false,      // 公共：是否已锁定
      taken: [3, 18, 55],       // 本轮收缴的牌，公共
      timeoutCount: 0
    }
  ],
  rows: [
    { index: 0, cards: [3, 17, 22, 41, 58] },
    { index: 1, cards: [8] },
    { index: 2, cards: [30, 66] },
    { index: 3, cards: [90, 101] }
  ],
  revealQueue: [                // 全部锁定后生成，按牌面升序
    { seat: 2, card: 12 },
    { seat: 0, card: 45 }
  ],
  revealIndex: 0,               // 已结算到第几张
  pendingChoice: null,          // { seat, card, options: [0,1,2,3] }
  lastEvent: {
    seq: 17,
    type: 'place',              // place | take | choose | roundEnd | gameEnd
    seat: 2,
    card: 12,
    rowIndex: 1,
    took: [3, 18],
    bulls: 4
  },
  lastActionId: '0-1710000000-3',
  log: [
    { round: 1, trick: 1, text: '玩家3 打出 12 → 第 2 行，收走 2 张，+4 牛头' }
  ],
  deadline: 0,                  // 选牌截止时间戳；无计时为 0
  rev: 0,
  createdAt: 0

```

说明：

- 4 行在开局时按行尾牌升序摆放；行编号固定 0~3，后续放牌/收牌都**不重排**，行位置保持不变。
- 单行长度永远 1~5；第 6 张会触发收走并重置为 1。
- `score` 在收牌时立即累加，便于实时展示；66 检查只在轮末做。
- `taken` 只作用于当前轮，下一轮清空。
- Mode P 下 `hand` 与 `selected` 不进入公共快照。

## 5. 规则引擎 API

`game.js` 为纯函数式规则引擎，UMD 导出 `window.SixNimmt` 与 `module.exports`，不依赖 DOM。

```js
createGame({ players, seed, settings })   // 初始化大厅/第一轮
startRound(S)                             // 洗牌、发牌、4 行起始
bullsOf(card)                             // 牛头值
selectCard(S, seat, card)                 // 锁定一张牌，返回新状态
allSelected(S)                            // 是否全部锁定
beginReveal(S)                            // 生成 revealQueue，进入 revealing
resolveNext(S)                            // 结算下一张；需要选行时返回 chooseRow
chooseRow(S, seat, rowIndex)              // 处理“比所有行尾都小”的选行
endRound(S)                               // 轮末结算、判断终局
nextRound(S)                              // 下一轮（或终局）
rankings(S)                               // 排名与并列处理
publicState(S, seat)                      // 对外快照（Mode P 剥离他人手牌）
serialize(S) / deserialize(str)
stateHash(S)
handForSeat(S, seat)
canSeatAct(S, seat)                       // 当前阶段该座位是否可操作
```

关键不变量：

- 每次操作返回**新状态**，不原地修改。
- 牌面 1~104 全局唯一。
- 所有手牌 + 所有行 + 所有收缴堆的牌集合互不相交。
- `revealQueue` 生成后不可变；`revealIndex` 单调递增。
- 只有 `pendingChoice.seat` 能在 `chooseRow` 阶段行动。
- 结算必须逐张进行，不能先算好所有结果再一次性应用。

### 5.1 结算伪代码

```js
function resolveNext(S) {
  if (S.phase !== 'revealing') return S;
  if (S.revealIndex >= S.revealQueue.length) return endRound(S);

  const { seat, card } = S.revealQueue[S.revealIndex];
  const candidates = S.rows.filter(r => last(r) < card);

  if (candidates.length === 0) {
    // 比所有行尾都小：进入选行阶段，暂停结算
    return { ...S, phase: 'chooseRow',
             pendingChoice: { seat, card, options: [0,1,2,3] } };
  }

  const row = candidates.reduce((a, b) => last(a) > last(b) ? a : b);
  return placeOnRow(S, seat, card, row);
}

function placeOnRow(S, seat, card, row) {
  if (row.cards.length === 5) {
    const took = row.cards.slice();
    const bulls = took.reduce((n, c) => n + bullsOf(c), 0);
    // 收走 5 张，card 成为新行首
    return applyTake(S, seat, card, row, took, bulls);
  }
  // 接到行尾
  return applyPlace(S, seat, card, row);
}

function chooseRow(S, seat, rowIndex) {
  const { card } = S.pendingChoice;
  const row = S.rows[rowIndex];
  const took = row.cards.slice();          // 可能是 1~5 张
  const bulls = took.reduce((n, c) => n + bullsOf(c), 0);
  return applyTake(S, seat, card, row, took, bulls);
}
```

`applyTake` 的要点：

- 打出者的 `score` / `roundScore` 增加 `bulls`；
- `taken` 追加 `took`；
- 该行重置为 `[card]`；
- `revealIndex++`，若还有牌则回到 `revealing`，否则轮末；
- `lastEvent` 记录 `take` 与收走的牌，供动画/日志使用。

### 5.2 轮末与终局

```js
function endRound(S) {
  const reached = S.players.some(p => p.score >= S.settings.targetScore);
  const gameOver = reached || S.settings.singleRound;
  // 保留本轮 taken/roundScore 供小结展示
  return { ...S, phase: gameOver ? 'gameEnd' : 'roundEnd' };
}
```

- `roundEnd`：展示本轮小结，房主点“下一轮” → `nextRound`。
- `gameEnd`：展示最终排名，房主点“再来一局” → 重置分数与轮次，保留座位。
- 并列最低：默认共享胜利；`tieBreak='extraRound'` 时追加一轮（Phase 2 可选）。

## 6. UI / UX

### 6.1 大厅

- 入口：根 `index.html` 增加“牛头王”卡片；游戏内 `index.html` 作为独立页面。
- 首页两个按钮：**创建房间** / **加入房间**。
- 创建：输入昵称 → 生成 4 位房号 → 进入房间。
- 加入：输入昵称 + 房号 → 入座。
- 房间页：
  - 房号大字 + 复制按钮；
  - 座位 0~9，显示昵称、房主标识、断线状态；
  - 人数提示：“推荐 5~7 人，2 人即可开始”；
  - 房主设置：计时（30/60/120/关）、战术局、单轮快局；
  - 房主“开始游戏”按钮。
- 分享文案：`牛头王联机局，房号 4821，打开 bg-star100.pages.dev/six-nimmt/`。


- 顶部：游戏名、轮/墩、设置、日志、退出。
- 分数条：昵称、总分、本轮 `+N`、手牌数、已选状态、断线点；最低分加“领先”标记。
- 行区：
  - 行头使用 A / B / C / D 标记，四行统一配色，并显示当前牛头合计；
  - 5 张时行头变红并提示“下一张将收走”。
- 手牌：
  - 按数字升序；
  - 点选抬起并显示勾选；再点取消；
  - 锁定后手牌区锁定，显示“等待其他玩家…”；
  - 390px 下 10 张牌建议两行 5 张，或单行横向滚动；优先保证牌面可读。
- 操作区：
  - 未选：“选择一张牌”；
  - 已选：“锁定出牌”；
  - 已锁定：“已锁定 · 等待 3 人”；
  - 倒计时 ≤10 秒变红。
- 亮牌区：全部锁定后，在行区上方出现“亮牌带”；按玩家座位固定槽位展示，结算过程中不重排、不消失，空位与已出牌位尺寸一致。
- 选行弹窗：仅触发者可见可点；展示 4 行的牌与牛头合计，点选后确认。
- 轮末/终局：得分表（本轮 + 总分），终局显示排名与“再来一局”。
- 日志抽屉：按墩记录放牌、收牌、超时代选；可选“只看关键事件”。

### 6.3 动效

- 亮牌：卡牌翻面 300ms。
- 放牌：从亮牌带飞向目标行，350ms；落到行尾后行头牛头数跳动。
- 收牌：整行闪红 200ms → 5 张牌飞向该玩家分数条 → `+N 牛头` 浮字。
- 选行：4 行高亮，悬停/点按显示“收走 X 张 / Y 牛头”。
- 轮末：分数条数字滚动。
- 设置里提供“减少动效”（跟随系统 `prefers-reduced-motion`），以及“快进结算”开关。
- 不做全屏特效，避免 10 人局节奏拖沓。

### 6.4 视觉

- 主题：原创“牛头牧场” × 美漫英雄原色。
- 色板：
  - 奶油纸面 `#F6EBD8`（红色半调网点背景）
  - 墨色文字 `#2F2D36`，线条 `#4A4752`
  - 英雄红 `#E5262B`（顶栏、主按钮、侧栏标题）
  - 牌桌蓝 `#2F5FC4`
  - 行头黄 `#FFD21E`
  - 辅助白 `#FFFFFF` / 浅蓝 `#F0F3FF`
- 漫画手法：1px 细描边、无投影、半调网点、粗体标题；保留原色对比但降低视觉重量。
- 封面徽章：红色圆形底 + 奶油色牛脸 + 金色牛角 + 粉色口鼻 + 金色鼻环，细描边，告别黑色剪影。
- 卡牌：按牛头数分色，牌面显示数字、中央牛头图案和牛头数；55 中央为 2-3-2 七牛，无额外角标。
- 行：黄色行头（A–D，四行统一配色）+ 虚线卡槽；满 5 张时卡槽变红。
- 图标：内联 SVG 牛头/牛角，不使用官方 AMIGO 素材、Logo、原画。
- 字体：系统字体栈；数字用等宽/粗体保证可读。

### 6.5 响应式与无障碍

- 320~1280px 均可用；≥ 900px 时改为左右布局：左侧行区，右侧手牌/分数/日志。
- 所有可点元素 ≥ 44×44。
- 卡牌为 `<button>`，`aria-label="数字 42，2 个牛头"`。
- 键盘：方向键移动手牌，Enter 选中/锁定，Esc 取消，数字键 1~4 选行（选行弹窗）。
- 牛头数同时用图标 + 数字表达，不只靠颜色。
- 对比度符合 WCAG AA；动效可关闭。
- 横屏时手牌与行区并排，不强制锁定方向。

## 7. 文件结构

当前（单机版）：

```
six-nimmt/
  index.html          # 页面骨架 + 菜单/设置/对局/弹窗
  style.css           # 主题、布局、卡牌、动效
  game.js             # 纯规则引擎（UMD，Node 可测）
  ai.js               # AI 决策（只读安全视图，注入 rng）
  render.js           # 对局控制器、DOM 渲染、动画编排
  test-core.js        # 规则引擎 / AI 单元测试（Node）
  test-e2e.js         # 单机浏览器 E2E（Playwright）
  SPEC.md
```

后续联机版再增加（当前未创建）：

```
  net.js              # Supabase 房间封装（基于 online-boilerplate/net.js）
  online.js           # 联机协调：房主权威、动作、重连、轮询
  supabase.min.js     # 与现有项目一致的本地依赖
  room-rpc.sql        # join_room / leave_room（共享函数，自包含一份）
```

与现有项目一致：

- 纯静态，无构建步骤；
- 根 `index.html` 与 `README.md` 已增加入口；
- 联机版后续复制 `online-boilerplate/` 的轮询、重订阅、`visibilitychange` / `online` / `pageshow` 重同步策略；
- 联机版 `ROOM_PREFIX = 'sixnimmt-'`，`MAX_PLAYERS = 10`。

### 7.1 联机版对现有 online.js 的改动（后续）

现有联机游戏是“当前玩家推状态”的合作模式。本项目需要：

- 增加 `HOST_AUTHORITATIVE` 分支：非房主只发 action，不写 `rooms.state`；
- 增加 action 广播/去重/重发；
- 增加 `deadline` 倒计时展示；
- 保留原有轮询兜底：2.5 秒（大厅）/ 5 秒（对局）；
- 频道重订阅、`rev` 新鲜度比较、push 序列化等逻辑直接复用。

为避免影响已上线游戏，优先在 `six-nimmt/online.js` 内实现，不回改 `online-boilerplate/`；稳定后再考虑抽公共模块。

## 8. 测试

### 8.1 规则 / AI 单元测试（`test-core.js`）

`node six-nimmt/test-core.js` 当前 **23 组全部通过**，覆盖：

1. 牛头值：1、5、10、11、55、100、104 全部正确。
2. 2~10 人发牌数：每人 10 张；4 行各 1 张；未使用牌数正确。
3. 初始 4 行按行尾升序；同一 seed 洗牌/发牌可复现。
4. 普通放牌：进入“行尾小于它且最大”的行。
5. 行满 5 张时第 6 张：收走 5 张、计分正确、新行首为该牌。
6. 比所有行尾都小：进入 `chooseRow`，只能由该座位选。
7. 选行收走 1~5 张：收全部、计分正确、新行首为该牌。
8. 多人同时触发选行：按升序依次处理，前一次选择影响后一次。
9. 升序结算影响后续：构造“先收行、后放牌”的场景，验证结果。
10. 10 墩后 `gameEnd`；最低分获胜，并列处理正确。
11. 状态不变量：手牌/行/收缴堆无重复、无丢牌；`validate` 能发现异常。
12. 序列化/反序列化后 `stateHash` 一致；非法动作被拒绝。
13. AI 出牌/选行合法；同 view + 同 rng 序列结果一致；`viewFor` 不含他人手牌、已选牌面或 unused。
14. 2~10 人全 AI 对局可完整跑完 10 墩。

### 8.2 单机 E2E（`test-e2e.js`）

- 菜单 → 设置（AI 2~9、三档难度）→ 开局。

- 分数、收牌堆、记分板、日志随结算更新。
