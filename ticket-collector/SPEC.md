# 《车票收藏家》Ticket Collector — SPEC

3~6 人线下聚会桌游助手。新线路开通，地铁公司在每节车厢放置纪念车票，收藏家们闻讯而来。

当前版本：**单机热座版**（多人线下游玩，通过传递手机各自操作自己的角色）。
后续规划：联机版（复用 `online-boilerplate/`）。

## 1. 组件清单

| 组件 | 数量 |
|---|---|
| 车票标记 · 红 | 18 |
| 车票标记 · 黄 | 18 |
| 车票标记 · 绿 | 18 |
| 车票标记 · 紫 | 6 |
| **票池合计** | **60** |

- 玩家角色：3~6 名，每人一个背包、一个储物柜。
- 列车车厢：`玩家数 - 1` 节（3 人 → 2 节，6 人 → 5 节）。

**色盲冗余**：车票除颜色外还带三重编码——形状（红 ◆ / 黄 ■ / 绿 ▲ / 紫 ★）、磁条点位数（1/2/3/4）、票面明度阶梯（黄最亮、紫最暗）。紫色另有双层描边。

## 2. 版面与坐标系

**纵向鸟瞰（近大远小）**。虚拟世界 `360 × 680`。`#stage` 的宽高由 `fitStage()` 写死为
`k = min(wrapW/360, wrapH/680)` 下的像素值（等比内缩、居中留边），`#scenery` 用
`viewBox="0 0 360 680"` 铺满 —— 于是 **1 世界单位 ≡ K px，无畸变**。

选择纵向的理由：**多节车厢竖着排，不费劲**。横向版 6 人局的 5 节车厢各只有 64 世界单位宽，
挤成一片；纵向版每节仍有 ≥86 世界单位宽，且车厢之间还能靠纵深自然分隔。

### 2.1 纵深投影

俯视角度的全部几何由三个纯函数决定（`game.js`，可单测）：

```
VP = { x:150, y:-900 }                            消失点在画面正上方很远
Y_FAR = 112, Y_NEAR = 672                         地面最远 / 最近处的荧幕 y

depthY(d)     = Y_FAR + (Y_NEAR-Y_FAR) * (0.75d + 0.25d²)    纵深 → 荧幕 y
depthAt(y)    = 0.25u²+0.75u−t=0 的正根                       荧幕 y → 纵深（反函数）
depthScale(d) = 0.62 + 0.38d                                 站在该纵深的东西的缩放
lean(xNear,y) = VP.x + (xNear−VP.x) * (y−VP.y)/(Y_NEAR−VP.y)  纵深线
```

- d=0 是最远（画面顶端），d=1 是最近（画面底端，贴着观众）。纵深用二次式而不是直线 ——
  远端才挤得密，这是「近大远小」的一半功劳。
- **纵深线 `lean`**：站台上每条「南北向」的线都朝消失点收敛，站台于是成为一个近宽远窄的梯形。
- **高度 = 向上的荧幕位移**：俯看时物体的高度不占纵深，而是把图元往上画；
  横向位置一律取**脚底所在纵深**的那条横向线 —— 这是鸟瞰图不穿帮的关键。
- 透视被烘进世界坐标里，所以「世界 → 视口」仍是统一的相似变换（`ORIG + w * K`），
  `toScreen` / `--wu` 计算串 / 仓库现成的视口坐标特效引擎（`spawn/fly/vanish`）全部原样可用。

### 2.2 走路（速度吃纵深）

```
WALK_V = 0.42                                     名义速度：世界单位 / 演出毫秒（近端 scale=1 处）
walkProfile(x0,y0,x1,y1,N=14) → { t[], total }    路程切 N 段，逐段 ds/(WALK_V·figScale(y)) 累加
```

- **实际速度 = `WALK_V × figScale(y)`**，走位时长 = 上面这张表的积分，演出层再用它把「时间进度」
  换成「路程进度」（`spaceOf(p)`），所以往远处走会与缩小同步地慢下来。
  既然速度与缩放同比例，**全场每秒走过的「身长」一致** —— 远景的人不会显得比近处的快。
- ⚠ 别退回「定长时长」：`clamp(dist*5.2, 150, 820)` 那种写法里，同一次入场 620ms 内最远的人要走 417 单位、
  最近的人只走 191，远处的人于是快得像被人推着走；写死的 `620 / 460 / 520` 这类 `dur` 是同一个病
  （用户的原话：「上面（远处）的移动速度快于下面（近处的）」）。
- 演出层只保留两个「不算走路」的定点跳跃用写死时长：翻车壁的小跳（`lift` 12）与夺冠三连跳（`lift` 16）——
  它们本来就该是一个固定的滞空感，与路程无关。
- **候车阶段的自由拖动走同一条律**：`lobbyTick` 的步长 = `LOBBY_V × figScale(f.wy) × dt`
  （`LOBBY_V = 150` 世界单位/秒，近端口径）。用户唯一亲手操控的移动就是这一段，
  曾经写成定值 150 单位/秒 —— 于是「拖到柜前那一带」比「站在站台前沿」快了 1.5 倍，
  正是那句「远（靠近储存柜的那边）的速度比较快」的来源。演出走位改对了、大厅没改，等于没改。
  验证见 `test-shot.js` 的「候车拖动速度律」：分两段量逐帧差商，两端都必须是
  `0.15 单位/毫秒 × figScale`，且远端的世界速度严格小于近端。

### 2.3 场地分区

```
TRAIN   = { nearIn:226, nearOut:352, locoD:0.13, maxCarD:0.26 }
PLAT    = { nearL:16, nearR:200 }                    站台左右缘（近端世界 x）
WALK    = { u0:-0.84, u1:0.78, d0:0.05, d1:0.93 }    自由活动边界（按站台比例内缩）
LOCKERS = { l:62, r:186, top:54, bot:110 }           储物柜柜体（世界 x/y 直标）
```

自上而下：隧道口 → 列车远端 → 车厢（号越大越远）→ 列车头 → 盲道/站台右缘 → 站台
→ 储物柜（远端墙上）→ 背包（沿左墙）。

- **列车**：贴站台右侧竖排，近端锚着列车头（`locoD = 0.13` 个纵深），`玩家数−1` 节车厢往远处排，
  每节最多 `maxCarD = 0.26` 纵深；**1 号车紧挨车头**，号越大越远（与用户手绘一致）。
  车厢少时不会拉长，省下的纵深让给隧道 —— 露出空轨与隧道口。
  车头在近端被画面切掉，只露出车顶与朝向观众的车头脸（风挡 + 红色腰带 + 通风口 + 排障器）。
- **列对齐**：背包贴左墙（`packSpot`，底边压在站台左缘、不占地面），储物柜在远端墙上一横排
  （`lockerSpot`）—— 两者各自随人数均分，不共用同一条竖线。
- **纵深交错**：`zIndex = 10 + (y/8|0)`（约 24..94）。越靠画面下方（越近）的角色越后画，
  于是走到柜前的角色压住柜体，而站在远处的角色会被近处的车厢压住。
  `#figs` 因此**绝不能**有 `z-index`/`opacity`/`transform`/`filter` —— 那会建立层叠上下文，
  把角色关进自己的笼子里，这套交织就不成立了。

### 2.4 车厢内部约定

- 车内**远端 30%** 摆车票筹码（`floor.at(d0 + (d1-d0)*0.30)`），**近端**站登车角色
  （`boardSpot` 脚落在 `y0 + 0.78h`）。一块地板要同时摊下筹码和站下人，所以内饰只放
  壁脚长凳带、地板拼缝、过道立柱，不给整排座椅留位置。
- 车内图元一律走 **SVG 用户单位**（每节车厢自己的 `viewBox` 就等于它的世界坐标盒子），
  深度缩放由 `art.js` 直接乘进数字里 —— 样式层只染颜色与线宽。
- **筹码大小只由「车厢宽度 ÷ 颜色数」与纵深决定，只有一种颜色也不放大**。
  单色车如果单独画大，等于把「这车只有一种票」写在脸上，比数字本身更早泄露情报；
  所以 `cw = min(pitch*0.86, 23*s)` 里的上限对所有颜色数一视同仁，两色三色都顶在这个上限上，
  只有四色为了塞得下才缩（`test-core.js`「车内筹码尺寸」把它钉住）。
- 车顶的「×号车 / 共×张」是 10 世界单位（用户指定），车里每一枚筹码下的 `×n`
  另有 **6.4 世界单位的地板**（`max(6.4, 7.6*s)`）—— 远端车厢的 `s` 只有 0.65，地板替它兜底。

### 2.5 字号（可读性地板）

**台上任何字号不得低于 6.4 世界单位**（最窄的手机上 ≈ 7px，肉眼可辨的下限）。
跟随纵深缩放的字一律写成两段的 `max()`，绝不写成裸的乘 `var(--fs)`：

```css
.pk-name  { font-size: max(calc(6.6 * var(--wu)), calc(8.4 * var(--wu) * var(--fs, 1))); }
```

- `max()` 里两项都对纵深单调不减，所以**地板只抬高远处那一端，绝不会把「近大远小」倒过来**。
- `--fs` 是**该处的纵深比本身**（JS 把 `packSpot(N,i).s` 写在 `.pack` 上）。
  曾经这里写的是 `1/s`（想「抵回常驻字号」），而包上的字并不吃包身的缩放，
  于是远处的名字反而比近处大 —— 用户的原话「近处的『玩家3』背包上的文字这么小，是不是搞反了？」
- 这些字是**外层 HTML 层**的（`#packs` 里的 `.pk-name`、徽章），不被 SVG 的 `viewBox` 缩放，
  所以「跟着包一起变大变小」这件事只能由 `--fs` 与 `max()` 显式做出来。
  包宽度只有 40 世界单位，基准 8.4 单位时「乘客 6」四字正好放得下（`test-shot.js` 六人局版面
  逐包断言 `scrollWidth ≤ clientWidth`）；想再大就得先加宽背包。
- **背包徽章锚在包身的上沿**（`bottom: calc(100% - 3px)`，压住一点上沿当「挂着」），
  而不是给一个负的 `top%`：徽章的高度和字一起随 `--fs` 缩（近端 ≈30px、最远 ≈23px），
  包名那一行却钉在 21% —— 同一个 `-20%` 在两种高度下让出来的缝不一样宽，近端算够、远端压字。
  锚在上沿以后，不管徽章多高都整只吊在包名之上（`test-shot.js` 在徽章亮着时断言 `clearName ≥ 0`，
  且不被舞台顶边裁掉）。**地板定 10 而不是 9**：`--wu` 跟着舞台一起缩，同一块版面在矮窗口 /
  窄窗口上会整体变小（390×844 上 `--wu` 1.03、徽章字实测 10.3px；320×640 上 `--wu` 只剩 0.66），
  地板留一点余量，字才不至于贴着 9px 的边。色点从固定 1.8 单位改成 `.3em`（吃徽章自己的字号），
  于是「字多大、点多大」永远同一档。
- **柜内陈列（SVG 里的 `.li-c`）分两套摆法，两套都吃 6.4 的地板**（见 `art.js` 的 `lockerInner`）：
  宽柜（N≤4，两列两行）数字压在票正下方（与车内筹码同一套语法）；窄柜（N≥5 一列最多四行，
  一行只有 12 单位高）压到票下会顶到底部总数行，于是改回「票在左、数字在右」并把票压窄让位。
  六人局柜子只有 20.7 世界单位宽，旧版一律挂在右边、字号被格宽压成 4.6 单位（≈4.7px）。
  **行距贴着内容算**（一节 = 票 + 票下那行数字；窄柜的数字在票右侧，一节就只有票），
  rows 节摞成一整块、在柜里居中 —— 摊满柜高会把两行拉到柜子的上下两头，中间空出一条
  和票一样宽的缝，开柜看一眼时最刺眼的就是这条缝（三行以上摞不下才回落到摊满）。

**台外界面（封面 / 名单 / 抽屉 / 顶栏 / 结算 / 日志）不跟纵深缩放**，另有一条更简单的规矩：
**一律 ≥ 12px**。它们直接在 CSS 像素里排版，不需要 `--wu`，但也没有纵深帮它们把字撑大 ——
11px 的日志元信息在 390px 手机上就是「要凑近看」的那一档，所以整层抬到 12px。
名单里那枚角色预览（`.pl-fig .fig`）同样在台外，尺寸也写死 24×40 CSS px：名单显示时游戏屏是
`display:none`，`--k` 要么是 CSS 初值 1、要么是上一局的残值，预览跟着它走就会时大时小。
两条地板由 `test-shot.js` 六人局版面一起守着：台内查世界单位（`/ --k`），
台外遍历 `#stage` 之外所有持文本的可见元素查 `fontSize ≥ 12`，顺带断言顶栏在 390px 不横向溢出。

### 2.6 HUD 与选择气泡

**「选车厢 / 顺走」的候选项是浮在 HUD 上方的一只气泡，绝不进文档流。**
摆回流里就是「点一次选车厢、HUD 多一排」：`#stagewrap` 是 `flex: 1`，跟着缩一截，
舞台整块上下跳一次 —— 用户看到的就是「样式被挤高了」。所以 `#hudList` 是
`position: absolute; bottom: calc(100% + 8px)`（基准是 `position: relative` 的 `#hud`）：

- **尖角跟着锚点走**：点开它的那颗按钮才是锚（`pickOne` 里 `anchor: cur.type === 'car' | 'swipe'`）。
  整只气泡随锚点平移（`--left-x`）并夹回 HUD 的内容框，尖角（`--tail-x`）再夹在圆角之内 ——
  只把气泡左边对齐（`left: var(--pad-x)`）、尖角也钉在圆角里的话，一颗筹码的「顺走」气泡
  （241px）够不着被推到右边那颗按钮的中心（按钮排一换行，锚点还会落到第二行去）。
- **滚动交给里层**（`#hudListIn`）：`overflow-y` 挂在气泡自己身上会把长在它下沿的尖角裁掉。
- 入场 160ms 的 `hudFloat` **不吃 `--fx-pace`**：气泡只在选择阶段出现，慢放窗口只包着结算四步。
- `z-index: 120` 要压过角色的 `10 + (y/8|0)`（最高 95，见 §2.3）；`#hud` 是 `relative` + `z: auto`，
  压不过舞台里 `z ≥ 1` 的层，所以气泡只能靠自己的 z 值出头。

**舞台尺寸认 `#stagewrap`，不认窗口**：窗口没动，HUD 也会长高 —— 按钮排一换行就是这样
（390×844 上不换：323 + 24 间距 = 347 ≤ 370 可用，HUD 96px；320 宽的窗口就换：按钮排
44 → 96px，HUD 96 → 143px）。此时只跑 resize 那套的话 `#stage` 还顶着开局写下的 inline px，
溢出的一截会压住顶栏和 HUD 的提示行。所以有一个 `ResizeObserver` 盯 `#stagewrap`，
尺寸一变就重 `fitStage()`（隐藏时是 0×0，**三条路径都跳过**：照 0 量会把 `--k` 钳到 0.2，
名单上的头像就缩成 1/5，而名单自己不重量、缩了回不来；写 `#stage` 不会反过来动 `stagewrap` ——
`flex: 1` + `min-height: 0`，尺寸不看内容）。窄窗实测：`#stage` 450 = `#stagewrap` 450，没溢出。

### 2.7 看一眼（点背包 / 点柜子）

**「选择行动前」点背包或柜子，出的是 HUD 上方的一张卡片，不是居中弹窗。**
弹窗得配遮罩、关按钮、暂停输入 —— 而这一步是**顺手一瞥**：看眼背包里几张、哪几色，
好决定这回合是上车、存放还是顺走。所以它复刻选择气泡那一整套（共用
`#hudList, #peek` 的皮肤与 `z-index: 120`）：

- **只在「你的回合」可点**（`pickLive` 由 `pickOne` 打开、`submit` 关上）：结算演出中途
  柜门正是动画在开的，不能抢；这一段也恰好就是「选择行动前」。
- **点柜子会把柜门卷上去**（`setLockerDoor(pid, true, true)`），收起时放下 —— 柜里那套陈列
  本来就画在柜里，卡片只是替它把字放大到读得清；背包没有「打开」这个动作，所以只出卡片。
- **点同一只收起、点另一只换过去、点空地也收起**：`#stage` 上的委托监听 `tapBoard` 接住一切。
  之所以点得到空地 —— `#scenery/#coach/#packs/#lockers/#figs` 全是 `pointer-events: none`，
  只有 `.pack / .locker / .fig / .coach-car / .loco` 收得到点，穿透下来的那一下正好当「收起」。
- **叠在选择气泡之上**（`--peek-b` = 8 + 气泡高 + 8）：「顺走」之前挨个翻背包，正是两只都要用的场景。
- 卡片不进文档流（`#hud` 宽高不变），也**不往 `#stage` 里塞** —— 舞台是整体缩放的，
  塞进去会被 `overflow: hidden` 裁掉，而远景那排柜子就贴在舞台顶边附近。

## 3. 开局

1. **注册**：逐位输入玩家名称，为自己的角色选择造型装扮——上衣 / 下装 / 鞋子 / 帽子 / 包包五个部位各自选色，或一键「随机配色」。
2. **入场**：确认后角色被渲染到站台，自动分散站位、互不重叠。
3. **候车自由活动**：传手机，每位玩家可以在站台上自由上下左右移动自己的角色（避障、不与他人重叠）。此阶段仅在开局前存在。
4. **开始游戏**：渲染 `玩家数 - 1` 节列车停靠在站台。

## 4. 回合流程

```
roundStart → 补票 → 选择（热座私密）→ 全员提交 → 【开始结算】闸门 → 揭晓 + 结算演出 → 本轮战报
                                                                                ↓ 点「确认」
                                                          回站台 → roundStart（下一轮，先补票）
                                                                                ↓ 票池已空
                                                                             结算排名
```

### 4.1 补票

遍历每节车厢：

- **空车**（车内没有车票）→ 补 **2** 枚
- **非空车**（车内还有剩余车票）→ 补 **1** 枚

车票从票池随机抽取（颜色按牌堆随机），扣减票池。

**票池不足时**：按车厢顺序依次满足，**前面的车厢优先补满**；票池见底后其余车厢挂一颗「车票已全部放置完」药丸。不超放、不倒欠。
药丸只是一句**通报**，约 3 秒就自己收掉（`.short-told`，`SHORT_TOLD = 3200` 墙钟，不跟 `--fx-pace`）——
它正落在车内筹码带上、摊着时筹码还压到 `.18`，一直不收就看不见「车里还剩什么票」，而「还剩什么票」
恰恰是玩法要读的信息（§4.4「没人选的车厢里的车票」）。收掉之后筹码回到原亮度，`.short` **状态类本身留着**——
屏幕上的类仍与 `S.cars[i].short` 逐轮一致（能摘掉它的只有下一轮补票）。

**最后一轮**：补票后若票池为空 → 本轮即为最后一轮，大字横幅提示；本轮结束即结算。

> 轮数预估（车票无积压时）：3 人 / 2 车 ≈ 15 轮；4 人 / 3 车 = 10 轮；5 人 / 4 车 ≈ 8 轮；6 人 / 5 车 = 6 轮。实际因车厢积压而更长。

### 4.2 选择（每回合一个动作：站台上三选一，柜前只有「回到站台」）

| 动作 | 条件 | 效果 |
|---|---|---|
| **选车厢** | 总是可选 | 结算时进入该车厢 |
| **存放** | 自己背包中有车票 | 把背包全部车票存入自己的储物柜 |
| **顺走** | 目标玩家背包中有车票 | 结算时去掏空该玩家的背包 |
| **回到站台** | 自己正站在储物柜前（唯一选项） | 结算第 0 步走回站台，本回合不能做别的 |

- 提交后不可更改；提交前可以反复重选。
- **全员提交后不自动开演**：最后一位交完，HUD 摆出一颗 `#btnSettle`【开始结算】按钮
  （提示「N 位乘客都已提交 · 确认后开始结算」），点了才进结算 —— 手机还在最后一位手里、
  桌面未必收拾好了，结算由人来开演，`waitSettle()` 不点就一直停在这一格。
  读档续玩走到这里同样会摆出它（全员都已提交时 `pickAll` 直接跳过，闸门照摆）。
  闸门数的是 `S.submitted.length` 而不是 `activePlayers`：那句提示说的是「交上来了几位」。
- 全部玩家提交前，**任何界面不得泄露他人的选择**（传手机遮罩）。
- `at === 'locker'`（上一回合存放过）的人**本轮仍然有回合**，但那个回合**只有「回到站台」一个动作**：
  HUD 只摆一颗按钮，点了就提交，`settleSegment` 之类的外部驱动也走「单按钮」这条分支。
  他**不会被自动跳过**，也不会被算成「没行动」—— 存放之所以是两个回合的承诺，正的这一半就在这儿。
  选择阶段他**站在柜前等**（`snapAll` 认 `at === 'locker'` 把他摆回柜前，而不是摆回家）。
- 判断「能不能动」与「站在哪儿」是两个问句：`canAct = atLocker || onPlatform`，
  而 `legalBoard / legalStore / legalSwipe` 一律要求 `onPlatform` —— 柜前的人只能提交 `return`。
- **选择前可以把背包 / 柜子端详一遍**（§2.7）：点背包或柜子出卡片，点柜子还会把门卷开。
  卡片上的内容与包上那枚徽章、柜里那套陈列**完全同源**（都是 `TC.total` + 分色计数）——
  它是一根放大镜，不是一份新情报，所以「谁看谁的」都不影响公平。

### 4.3 结算演出顺序（严格按此顺序）

1. **玩家存放 + 回站台**（两股人流在同一个慢放档里对着走）—— 存放者走到自己的储物柜前，开柜，背包车票逐枚飞入，**关柜后就留在柜前**；
   上一回合留在柜前的人（`ev.ret`）同时从柜子走回站台。两者互为镜像：一条往柜子去，一条从柜子来。
2. **无人车厢关门** —— 没人选的车厢**同一拍一起**双开门合拢、内饰熄灯，轻微震屏。
   逐节排队关门会把一拍拖成几条慢吞吞的队尾（最后一节还要再等一次震屏与等待），
   所以 `stepCloseCars` 用 `Promise.all` 把各节车的滑门同时发起，震屏与顿帧整拍只来一次。
   这一拍的门是**双倍速**（130 fx ms；别处的合拢走默认 260）：「啪」地扣上，不是慢慢合拢。
   车门合拢与车内熄灯是**本轮**的舞台效果，**车票不作废**（留在车内，下一轮该车算「非空」只补 1 枚），
   所以「共 N 张」药丸只压暗、不划掉，另挂一颗「本轮无人光顾」说明为什么这轮没人拿走 ——
   划一道红线会让人以为那几张票没了。
   **全场只有这一行字**：曾经另有一枚同字同址的 fx 印章（白底红字 `stampStop`），门扣上时与药丸同拍
   叠在一起，两行几乎同字，会被读成「无人光顾闪了两次」；印章已删，药丸因此也不带任何出场延迟
   （`.closed` 一挂就淡进来，摘掉就立刻熄）。
3. **顺走 + 玩家进车厢**（并行）—— 登车者分三段走：先走到车门正对的站台边（跨过盲道），
   再小跳翻过车壁落到车厢地板左缘，最后在车里走到自己的站位；顺走者走到目标背包前。
4. **玩家获得 / 未获得**
   - 某车厢**只有 1 名玩家**前往 → 该玩家获得车厢内**全部**车票（放进背包）。
   - 某车厢**多于 1 名玩家**前往 → 这些玩家**什么都没获得，原地旋转起来**。
   - 某玩家背包**只有 1 名玩家**顺走 → 拿走其背包**全部**车票。
     - 若该玩家本回合**进行了存放** → 顺走者什么都没获得，原地旋转起来。
   - 某玩家背包**多于 1 名玩家**顺走 → 这些玩家什么都没获得，原地旋转起来。

结算演完（车门合拢）**先摊出这张卡，人不急着散**：点「确认」之后上过车的人才走回站台 ——
**除了刚存放的那几位**，他们留在柜前（`sweepHome()` 里 `at === 'locker'` 直接 `Promise.resolve()` 跳过），
下一回合的选择阶段也从柜前开始。散场紧接着就是下一轮的补票（`playRound`）。

**本轮战报**（`waitSummary(rev)` / `roundRows(rev)`，z 40）：结算演出与散场之间的一格停留 ——
一人一行、按座位顺序，写清这一轮**谁得了、谁失了、谁白跑**，数据全部从结算事件表（`ev`）现算、
不另存一份（卡上说不清的地方，就是演出没讲清的地方）：

- 存放 → 「存放 N 张 · 收进储物柜」+ 分色票样；净额一栏写 **入柜**（不是 0：票没丢，也没进背包，
  只是换了个地方过夜）。
- 独得车厢 → 「独得 N 号车厢 M 张」，净额 `+M`；多人相争空手 → 「与 A、B 同抢 N 号车厢 · 空手」。
- 顺走 → 两边各一行（成功的「顺走 X 的 N 张」记 `+N`、被顺的「被 Y 顺走 N 张」记 `−N`；
  失败的一行写明原因：多人抢同一目标 / 对方已存放 / 对方背包已空）。
- 柜前的人 → 「从储物柜走回站台」，净额 0；这一轮什么都没参与的人写一行「—」。
- 卡底一行提示写清**确认之后才发生什么**（下一轮开补票 / 票池已空进排名），按钮就一颗「确认」。

**「确认」是流程的一半**：`#summary` 和 `#curtain` 一样**不吃「点背景关闭」**（点掉了就等于跳过一次补票），
卡片摊着的时候人还站在各自的位置上（车里 / 柜前 / 包边）——这一格也顺带成了停给玩家看的落点。
它不写进存档：`stage === 'show'` 的档里结算结果已经落盘，读档续玩直接 `snapAll` 进下一轮，
不重演演出也不重摊战报。

**节奏**：以上 4 步整体按 **40%（PACE = 0.4，即 2.5 倍时长）** 播放 —— 这是整局里最该看清的一段，
原速下开柜、飞票、抢空全是一晃而过；再慢（曾用过 20%）就成了等，40% 是「看得清」与「等得起」的折中。
**收尾的「全体回站台」不在慢放窗口内，照原速走**，而且它排在战报的「确认」之后 —— 卡片摊着的那段时间
既不是慢放窗口、也不是它的一部分。（柜前那条「回站台」动线在窗口内 —— 它属于第 1 步。）

**第 1 步（存放）内部并行**：所有选择存放的玩家同时走、同时开柜、同时飞票、同时关门，
不是一个人演完再换下一个 —— 6 个人排队存放会等到天荒地老。
出发是同一拍，**到柜的先后由路程决定**（家在前排的离柜子近，会先到、先开柜），不是谁在等谁。
回站台的人也挂在这条 `Promise.all` 上（`backs.concat(jobs)`）：这一轮**即便没人存放**，
只要有人在柜前，这一步照样得跑（`if (!ev.store.length && !ev.ret.length) return;`）——
闸门只认「两边都空」，漏掉 `ev.ret` 那条动线会在「只有人回站台」的轮次里整个消失。
飞票按人头摊预算（单轮封顶 16 枚）：6 人同时开柜时若各飞 8 枚就是 48 个提升层，
比等得久更伤低端机；少飞几张由「存放 N 张」气泡、徽章 punch 与柜内陈列补齐，看不出来。
每下关门的震动也按人头摊（`0.1 / 人数`），6 个人一起关还是 0.1，不会震出夺冠级的 0.6。

### 4.4 关键判定（决策表）

| 议题 | 决策 |
|---|---|
| 「空车 / 非空车」如何判定 | 空 = 车内**没有车票**；非空 = 车内**还有剩余车票**。与是否有角色 **、角色站在哪儿**都无关（每轮结算后进过车的人都回站台；只留在柜前的人压根没上过车） |
| 每回合能做几个动作 | **一个**，选车厢 / 存放 / 顺走 三选一；站在柜前的人一个 —— 只能是「回到站台」 |
| 谁按下「揭晓」那一下 | **人**：全员提交后 HUD 摆出 `#btnSettle`【开始结算】，点了才 `resolveRound`。曾经是第六个人一交就自动开演，最后一位还没把手机递回来、桌上还没安静，演出已经开跑了 |
| 演出之后到下一轮之间还有什么 | **本轮战报**（§4.3）：车门合拢后摊出一张卡（谁得了 / 谁失了 / 谁白跑 + 分色票样），点「确认」才散场 —— 上过车的人走回站台、存放的人留在柜前，随后才是下一轮的补票。`#summary` 不吃「点背景关闭」（与 `#curtain` 同理），确认是流程的一半 |
| 车厢内车票信息 | **完全公开**：数量与颜色都画在车厢里 |
| 没人选的车厢里的车票 | 留在车内，下一轮该车算「非空」只补 1 枚，形成滚雪球诱惑 |
| 多人争抢未获得的残票 | 留在车内，同上 |
| 存放的代价 | 当回合免疫顺走；**下一回合仍然轮到他，但那个回合只有「回到站台」一个动作**（选择阶段站在柜前等，第 0 步走回站台，演出在第 1 步），做不了别的，即存放是两个回合的承诺 |
| 存放后能否被顺走 | 不能。背包已空，且按动作 1 先执行的顺序，顺走者到达时包已空 → 什么都没获得；柜前的人也不能被选作目标（`legalSwipe` 要求目标此刻 `onPlatform`） |
| `at === 'locker'` 的兜底 | `resolveRound` 第 0 步**无条件**把柜前的人放回站台 —— 读档、异常退出之类的路径里哪怕没提交过 `return`，也没人会被永久锁在柜前 |
| 目标选择时机 | 顺走目标的可选性按**选择阶段开始时**的背包状态判定；结算时的落差（对方存放了）由玩家承担 |
| 背包 / 储物柜信息公开度 | 完全公开，时刻可见所有人的背包与储物柜数量与分值 |
| 关门是永久的吗 | **不是**。关门只表示「本轮没人上这趟车」，是本轮的舞台效果；下一轮该车照常参与补票与登车，车里的剩票也会照常被取走。`closed` / `short` 都是**本轮重算**的状态，屏幕上的类由 `refreshCar` 每轮重新盖一遍 |
| 「车票已全部放置完」要一直挂着吗 | **不**。它只是补票那一拍的通报：约 3 秒（`SHORT_TOLD`）后挂 `.short-told` —— 药丸淡出、筹码回原亮度，玩家这才看得见车里还剩哪种票。`.short` 状态类不受影响（`refreshCar` 的计时器只动 `short-told`），能摘掉它的只有下一轮补票 |
| 自由移动 | 仅开局前的候车阶段可用；开局后角色位置完全由演出驱动 |
| 台上文字多大 | **不得低于 6.4 世界单位的可读性地板**；跟纵深缩放的（背包名、徽章）写成 `max(地板, 基准 × --fs)`，保持近大远小。车厢的「×号车 / 共×张」是 10 世界单位（见 2.5）。台外界面（封面/名单/抽屉/顶栏/结算/日志）不跟纵深缩放，另有一条 12px 的地板 |
| 包名用什么色的字 | 包名墨色**跟着包身亮度走**（`inkOn`）：浅包（近白 / 黄 / 绿 / 橙 / 青）用深字 + 浅晕，暗包维持白字 + 深晕。阈值取两种墨色对比度相等的那一点（L ≈ 0.22），不是拍脑袋的「看着像深色」—— 全 10 色最差也有 3.9:1（白字压近白包只有 1.10:1，等于没写） |
| 车厢内只有一种票时 | **不放大**：筹码尺寸只由「车厢宽度 ÷ 颜色数」与纵深决定，单色与两三色同大小（见 2.4） |
| 柜子色条 / 榜单圆点用什么色 | **主人的衣服色**（`colors.top`）：柜门顶沿的色条与结算榜每行前的小圆点都读 `--cloth`，便于一眼对上「这柜子是谁的」「这一行是谁」。脚下那个身份椭圆仍用座位色 `--mark`（`MARK[i]`），两人撞衫时靠它分辨 |

## 5. 游戏结算

### 5.1 计分

```
紫票：  每枚 2 分
成套：  min(红, 黄, 绿) 套，每套 5 分
散票：  剩余红、黄、绿各自 floor(n / 2) × 2 分
```

玩家总分 = 把**背包和储物柜合成一池**后按上式算出的一个分。容器只决定「会不会被顺走」，
不参与计分：柜里 3 张散黄 + 包里 1 张散黄是一对（4 分），分开算则两边各剩单张、都是 0 分；
红黄绿分在两个容器里也照样成一套。`rank(S)` 的 `merged` 就是这一池。

**贪心最优性证明**：取满 `min(红,黄,绿)` 套恒为最优。拆掉 1 套最多使红、黄、绿各自损失 1 分的配对价值（合计 3 分），而成套本身值 5 分。故「尽可能成套」总是优于「留作散票凑对」。测试用例覆盖此结论的边界。

### 5.2 展示

- 排名榜（含名次、各玩家总分）。
- 每位玩家可展开**计分公式明细**（只列一池，标题里带两个容器各自的张数）：
  `全部车票（储物柜 19 张 + 背包 2 张） / 紫票 3×2=6 / 成套 2×5=10 / 散票 红2÷2×2=2 → 合计 18`
- 散票的两行写的是**两堆不相交的票**：配对行写配掉的那几枚、单张行只写剩下的那一枚
  （5 枚散绿 → 「4 枚 ÷ 2 × 2 分」+「1 枚，单张不成对」）。两行都写总数会被读成两堆 5 枚。
- 冠军着重演出（撒花、印章、光晕）。

## 6. 演出分级

| 事件 | 分级 | trauma | hitStop | 组合 |
|---|---|---|---|---|
| 车门关闭（无人光顾） | medium | 0.22（各节同步合门，整拍一次） | 50 | 多节同步 + 滑门双倍速缓动 + 「本轮无人光顾」状态药丸 |
| 抢空旋转 | small × k | 每个 0.08，最后停稳 0.18 | 首落 30 | 720° easeOutQuint + 双臂僵直 + 「空手！」 + 尘土 |
| 顺走成功 | medium | 0.30 | 60 | 车票列飞行 + 「得手」印章 + 闪屏 0.22 + 受害者背包抖动 |
| 存放 | small | 0.12 / 关门 0.1 ÷ 人数 | — | 多人同时开柜：柜门开合 + 带 lift 的车票飞行 + badgePunch；**同一步里**上一轮的存放者从柜子走回站台（纯走位 + 「回到站台」气泡，不加震屏 —— 那是别人存放的音效，不该记在他头上） |
| 最后一轮 | large | 0.45 | 90 | 横幅 + 闪屏 0.30 + 红色渐晕 + 吊灯 3 次闪烁 |
| 最终排名 | large | 0.60，冠军 0.90 | 冠军 120 | 逐人数字滚动 + 冠军三连跳 squash + 24 发四色彩带 + 「冠军」印章 |

**节奏（三个旋钮，别合并）**：
- `PACE.v` = **演出的基础节奏**，平时 1；结算四步期间 `SLOW = 0.4`（慢放 2.5 倍），由 `animResolve` 用
  `try / finally` 开关 —— 中途抛错也要把节奏还回去，否则整局卡在慢动作里。
- `SPEED.v` = **玩家按出来的绝对倍率**：1 / 3（快进 ⏩），跨轮保留。
- `rate() = SPEED.v > 1 ? SPEED.v : PACE.v`，乘在 `fxClock` 上（`frame` 的 `vdt`、`fxWait`、`bubble` 都走它），
  于是慢放/加速会一并作用于**已在飞**的补间与等待，不会把角色丢在半路。
  **玩家一按倍速就立刻夺回控制权**：一个变量既当档位又当播放率的话，按一下快进反而变慢。
- **同一把尺子**：`fxClock` 的单位是「演出毫秒」，`tween.dur` / `fxWait(ms)` / `bubble(ms)` / `hitStop(ms)`
  的参数**全是这个单位**，真实时长一律 = 演出毫秒 / `rate()`。参数在传进去之前**再除一次 `rate()` 就是双重缩放**：
  慢放时变成 1/rate² 的慢动作（0.4 → 6.25 倍），3 倍速时又短得看不见 —— 只有 `test-shot.js` 的
  节奏画像（`pace` 采样 + CSS 变量同步）能发现。

`fxWait(ms)` 是唯一等待闸门；`prefers-reduced-motion` → `fxOn = false`，`fxRunUntil` 立刻 resolve，
演出塌缩为状态更新。不吃 fx 时钟的 CSS 过场（车厢熄灯、无人光顾药丸、气泡弹出）统一乘 `--fx-pace`
（JS 写 = `1 / rate()`），跟着同一个节奏。

**走位速度是另一个旋钮**：`WALK_V`（§2.2）只决定「走多快」，与上面三个节奏旋钮无关 ——
每段演出的时长由走路时长自己算出来（还乘着 `rate()` 那层），所以调它只影响走位的观感与那一段的总长。
`test-shot.js` 的入场采样就是它的哨兵（每秒身长散布必须 < 25%）。

**音效同步**：合成器以「本发开始的那一刻」为锚点做线性时间映射
（`T(t) = base + (t - base) * stretch`，`stretch = 1 / rate()`，只在慢放时 > 1），
于是滑门、旋转这类**有持续过程**的声音跟放慢的动画同时收尾；`stretch = 1` 时 `T` 是恒等映射，等于没改。
⚠ **`T` 只吃绝对时刻，时长要用 `D(d) = d * stretch`**：锚定映射喂时长是没有意义的
（`T(0.13)` = 「起点 + (0.13 − 起点) × 5」这种鬼数会把整发声音排到过去）。
`SFX.play` 吞掉全部异常，混了这两个就是把慢放音效变成静音、且只有真机上才听得出来。
只拉长不缩短：快进时音效照原样，限流（同名 100ms 内 10 发）与声部上限（14）本来就挡得住重叠。

**上下文被挂起要能自己醒过来**：锁屏、来电、切后台被冻结、音频焦点被别的应用抢走，都会让
`AudioContext` 停在 `suspended`（Safari 还多一个私有的 `interrupted`）。`play` 撞上这种状态时
**先 `resume()`、把这一发挂到唤醒成功之后补上**，而不是直接 return —— 只在 `boot` 里做一次性解锁
（第一次点按之后就把监听摘掉）的话，挂起一次就是**此后永久静音**，而唯一的症状是「点了没声」。
挂起期间 `currentTime` 冻住不动，所以不能顺手排声：那些发声会攒到恢复那一刻一起炸。
唤醒必须落在手势里，而 `play` 的调用点全都来自手势，这就是最省事的唤醒时机。

**无障碍**：`--shake-scale`（默认 0.8）、`prefers-reduced-motion` 启动检测（命中即 `fxOn = false`）。

## 7. 技术方案

### 7.1 技术栈

纯前端 HTML/CSS/JS，**无框架、无构建、无 npm 运行时依赖、零二进制资源**。全部美术为内联 SVG + CSS。

选择内联 SVG 的理由：矢量任意缩放；**配色即 CSS 变量**，角色只需一份模板串、改 5 个变量换装，无需任何素材变体。PNG 在免费 Pages 上冷加载慢且需出几十张配色变体；base64 更差（体积 +33%、无法单独缓存、阻塞解析）。

变量约定（SVG 的表现属性不支持 `var()`，所以模板里的图元只打类名，颜色一律由样式表接管）：`.fig` 上写
`--top / --bottom / --shoe / --hat / --bag / --skin / --mark`；`.pack` 上写 `--bag`（外加 `--name-ink` /
`--name-halo` —— 包名墨色由 `inkOn(colors.bag)` 按包身亮度现算，白色包上写白字等于没写）；`.locker` 与 `.rank-mark`
上写 **`--cloth`**（= 主人衣服色 `colors.top`，取值见第 4 节决策表）。

### 7.2 坐标系

见第 2 节。要点：**透视烘进世界坐标**，因此世界 → 视口是一次相似变换（`ORIG + w*K`），
`fitStage()` 只在 resize / 每轮开始时测一次 `#stage` 的 rect，其余锚点全部是纯算术。

放弃「整块缩放 SVG」方案的原因：SVG 几何动画每帧重绘子树、低端安卓吃不消，
`stroke-width` 会随缩放变形，`<text>` 字体度量与点击目标也全都变麻烦。
拆成「HTML 层定位 + 每节车厢内部自己一个 viewBox」之后，仓库现成的视口坐标特效引擎原样可用。

### 7.4 状态结构

```js
S = {
  phase,        // 'lobby' | 'pick' | 'resolve' | 'over'
  round, N,     // 玩家数 3..6
  names: [str],
  players: [{ id, seat, name,
              colors:{top,bottom,shoes,hat,bag,skin},
              at:'platform'|'locker', pos:{x,y,d,s},   // 世界坐标 + 该纵深处的缩放
              bag:[r,y,g,p], locker:[r,y,g,p] }],
  cars:    [{ id, tickets:[r,y,g,p], closed:false }],
  pool:    [r,y,g,p],
  picks:   { [pid]: { type:'car'|'store'|'swipe'|'return', car?, target? } },
  submitted: [pid],
  lastRound: bool,
  resolved,     // 已完成结算的轮数
  hist: [],     // 逐轮存档，供对账与复盘
}
```

车票一律用 4 元计数数组 `[红, 黄, 绿, 紫]` 表示，不展开成个体对象——保证数量守恒易验证、序列化紧凑。

`at` 是**站位**而不是「是否有回合」：`'locker'` 的人下一回合照样轮得到（只是只有 `return` 一个动作），
所以 `canAct` 不能写回 `at === 'platform'`（那就退回「自动跳过」了）。

```js

  merged = 背包 + 储物柜 合成的那一池（**总分只从它来**，明细也照它列）

```

`resolveRound` 返回的事件表形状：

```js
{
  store:  [{ p, n, tokens:[r,y,g,p] }],
  close:  [{ car }],
  board:  [{ p, car, slot }],
  swipe:  [{ p, target, ok, reason, tokens:[r,y,g,p] }],   // ok=false 也要占位演出
  deal:   [{ car, winner|null, contested:[p], tokens:[r,y,g,p],
             steals:[{ from, to, tokens:[r,y,g,p] }] }],
  return: [p],          // 从储物柜走回站台的人（第 0 步改状态，演出挂在第 1 步的 backs 上）
```

`activePlayers(S)` = 所有 `canAct` 的人，**含站在柜前的那些**（他们也得提交「回到站台」才算走完选择阶段，
`allSubmitted` 因此不会被柜前的人卡住一半）。`return` 与 `store` 是**同一步的两股人流**，
不是两件事 —— 渲染层别把它们串起来演。

### 7.6 性能预算

最坏 6 人局 ≈ 540 个节点。必须守住的规则：

1. `#scenery` 只在开局写一次，之后只改属性与 CSS 变量；仅在人数变化或重开时重建。
2. **只动 `transform` 和 `opacity`**；`left/top` 只在 `spawn` 时写一次。禁止动 `width/height/filter/box-shadow/background` / SVG `d` / `stroke-dasharray` / `clip-path`；全局禁用 `backdrop-filter`。
3. 飞行中不用 SVG 滤镜；发光用 HTML `radial-gradient` 光晕 div。动画元素禁止 `drop-shadow`。
4. 同时存活 tween ≤ 24；带补间的并行操作 `chunked(list, 4)`。每个 `vanish()` 移除节点，每轮结束 `clearFx()` 兜底。
5. 飞行车票用 DOM 而非 canvas（同时 ≤8 张，元素内无文字）；`will-change` 由 `.fxc` 统一给，不内联。
6. **死锁红线**：`fxRunUntil` 的等待器只在循环终止分支 resolve，任何长生不死的 tween 会饿死所有 `await fxWait`。所有循环运动必须放在独立的大厅 rAF 循环里，`playRound` 前必须 `stopLobby()`。
7. **补间起点红线**：`tween({ t, dur })` 的 `t` 是**从当前时刻起算的延迟**，起手锚 `t0 = fxClock + (t || 0)`（与 `infiltraitors/render.js` 同一个契约）；`fxWait` 的 `end` 才是**绝对**时刻。两者混用不会报错也不会挂起 —— 锚错成绝对的 0 时，一轮跑到后面 `fxClock` 早已大于 `dur`，`p` 第一帧就 ≥1，于是**所有位移都会瞬移、终点却全对**：指纹比对、状态断言、控制台全部看不见，只有肉眼能发现。
   > 唯一能拦住它的是 `test-shot.js` 的行走采样（每 50ms 记一次世界坐标，只数 0.4~30 单位的小步；瞬移一大步会被上限滤掉）。
8. **`clearFx()` 的落点红线**：它清补间**也清等待器**，所以在它之后再起补间。反过来的写法（起补间 → 等一小会 → `clearFx`）在锚点正确时才会暴露：
   补间被打断在 `p` 那一刻，**终点全靠 `after()` 写**，于是只有数字类演出会留下错值 —— 结算页的分数滚动就是这样停在 75% 的。
   规则 7 修好之前，这一类 bug 被「第一帧就 p ≥ 1」意外掩盖着。

### 7.8 存档 / 日志 / 弹窗

#### 存档（localStorage，单键 `tc.save.v1`）

```js
{ v:1, t:Date.now(), stage:'setup'|'lobby'|'pick'|'show'|'over',
  seed, rng, speed, fx, S, draft, log }      // rng 是 mulberry32 的**内部状态**，不是种子
```

- **`stage` 是存档的核心**：`S.phase` 只描述对局内阶段，说不出「名单还没发车」「刚结算完但演出没播」这两件事，所以落盘时另记一层。
- **结果先落盘、演出后开演**：`runPicks()` 里 `resolveRound(S)` 一返回就 `saveNow('show')`，**然后**才 `await animResolve(rev)`。演出中途刷新/杀进程，这一轮也已经算完并落盘 —— 动画重放不了（演出前的视觉状态没存），但结果一枚都不丢。
- **`rng` 必须存状态而非重放种子**：只存种子的话读档后随机流从头再来一遍，第 2 轮的补票会与第 1 轮重复。`G.seeded` 因此补了 `state()/set()`。
- **读档行为**：`setup` → 回到名单屏（草稿行完整还原）；`lobby`/`pick`/`show` → 直接挂载对局屏继续；`over` → 直接出排名（分数用 `instant` 直写终值，不滚动）。`show` 不重演，直接推进到下一轮；若票池已空则立刻进结算。**`pick` 档恰逢全员都已提交**（闸门摆着、还没点）续玩时，`pickAll` 无人可问直接过，`waitSettle()` 照摆【开始结算】——闸门不写进存档也不丢，读回来还在。
- **本轮战报不占存档的一格**：它是演出与散场之间的一格停留，不是状态。`stage === 'show'` 的档里结算结果已经落盘，续玩走 `snapAll` + `playRound`，既不重演演出、也不重摊战报，更不会少补一次票 —— 战报确认后的两件事（`sweepHome` 与补票）里，只有**补票**是状态（`S.round`/票池），散场只是走位。
- **名单只有一份来源梯队（`rosterFrom`）**：发车前那份 `draft`（名字与配色都是用户定下的原样）→ 这一局的玩家（`beginGame` 补过空名与去重后缀）→ 全新三人。**非 `setup` 档的读档也要把名单补回来**：中途刷新过的那一局打完时内存里的 `draft` 是空的，「再来一局」照它铺名单就是一屏空白（名单少于 3 人还发不了车）。从玩家还原时配色拷一份，不与 `S` 共享对象。
- **切人续玩**：`pickAll()` 跳过 `S.submitted` 里已有的人 —— 读档不会把已提交的人再问一遍。
- **柜前的人得摆回柜前**：`snapAll()` 认 `at === 'locker'`（用 `lockerStand` 而不是 `homeSpot`）。
  一律摆回家的话，读档续玩时「下一回合从柜子走回站台」会变成「从站台走回站台」—— 状态还是对的，
  但那条动线就没了，而且只有肉眼看得出来。
- **写盘时机**：名单每次改动（含改名、换色、骰子）、发车、每次提交选择、结算前后、进入结算页。写盘失败（隐私模式 / 配额满）静默吞掉，绝不影响这一局。
- 逃生口：日志面板底部的「清空存档并回到封面」（`clearSave()`）。

#### 日志（`TC_UI.log()`）

- 环形缓冲 400 条，每条 `{ t:Date.now(), r:轮次, k:类型, s:文本 }`；类型 `sys`（读档/开局）、`act`（玩家动作）、`deal`/`store`/`swap`/`close`（结算）、`warn`、`err`（含全局 `error` / `unhandledrejection` 钩子）。
- **倒序查看**：面板从头往下就是最新一条（渲染时倒着遍历），滚动条钉在顶部。
- **"复制"** 走 `logText()`，格式 `HH:MM:SS [R3/act] 张三：存放 2 张`，方便整段贴出来排障。
- 面板 z 52，**高于传手机遮罩 z30**：任何时候都能喊出来。
- **隐私红线**：选择文案必须等 `resolveRound` 之后才写进日志 —— 日志面板随时能开，提前写就等于把别人未揭晓的选择亮出来；而且文案要在结算**前**抓下来（结算会清空背包，之后再取就成了「存放 0 张」）。
- **「回到站台」只记一条**：`pickText` 对 `type:'return'` 返回 `null`（`runPicks` 里 `.filter(Boolean)` 滤掉），
  文案改由 `logResolve` 的 `ev.ret` 那条承担 —— 那条顺带覆盖「没提交也被兜底放回去」的情况，两边都记会让人以为他做了两个动作。

#### 点遮罩关弹窗

- `rules` / `palette` / `logbox` 三处的弹窗都支持点背景关闭（`pointerdown` 命中判定 `e.target === box` 或 `.sheet` 包裹层）。
- **`#curtain` 与 `#summary` 故意不在此列**：前者是传手机关卡，"点背景就关"会把上一位的选择亮给下一个人看；
  后者是结算流程的一半（§4.3），"点背景就关"等于替玩家按了「确认」，把回站台与补票一并跳过。

### 7.9 联机版预留（本版本不实现）
