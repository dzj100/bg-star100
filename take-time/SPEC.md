# 时序谜局 (Take Time) 桌游助手 — 规格说明

移动优先的单页 HTML 联机桌游助手，零外部依赖（除本地 Supabase 库）。
支持 2~4 名玩家在各自手机上实时联机协作。

## 规则模型

- 钟面分为 **6 个区域**（1→6，从左到右/顺时针方向）。
- 牌库：日牌 ☀ / 月牌 ☾ 数字各 1~12，共 24 张；每局随机抽 12 张等量发给玩家（数字可能重复或缺号）：
  - 2 人局：各 6 张；3 人局：各 4 张；4 人局：各 3 张。
  - 其余 12 张为**备用牌堆**（`S.reserve`，随状态同步、UI 不展示内容），第 7 章「摸1张」区域从此摸牌。
- **眼标记**：基础数量 = 玩家人数；另可携带本关累计的赠送标记（失败+1，上限 +3，通关清零）。
- **关卡库 `CHALLENGE_LIB`**（game.js）：32 关（8 章 × 4 关），每关可配置：
  - `name`：关卡名；`desc`：规则展示文本（钟面上方横幅 `.clock-rule` + 等候室），**不标注硬规则**（每区域≥1张、总和递增等通用判定在规则弹层统一说明）；
  - `check(sums, segments)`：自定义通关判定（返回 `{ segOK, sumOK, ascOK, pass }`）。
  - 未收录的关卡使用 `defaultCheck` 通用判定：
    1. 每个区域至少 1 张牌；
    2. 每个区域总和 ≤ 24；
    3. 区域 1→6 总和非降序（递增或相等）。
  - 第 1 章 4 关自定义规则（已实现，仅标注本关特殊/例外规则）：
    1. **孤阳**：1 号位只能放 1 张太阳牌；6 号位必须有 3 张牌；本关无总和≤24 限制。
    2. **枢衡**：3 号位数字总和必须在 8~12 之间；4 号位必须有 3 张牌；本关无总和≤24 限制。
    3. **序引**：第 1 张牌必须放在 3 号位，第 2 张牌必须放在 2 号位（按全局放置顺序 `card.order`）；6 号位数字总和必须在 20~30 之间；本关无总和≤24 限制。
    4. **近六**：1 号位数字总和必须比其他位次更接近 6（严格最小）；4 号位必须是 1 张太阳牌 + 1 张月亮牌；保留 ≤24 限制。
- 第 3~7 章及第 8 章前 3 关为「转盘（`rotate`）选条件」关卡：每关 6 个区域条件（`conds`）固定，看牌前由房主用滚轮选定 1 号位条件，其余按原顺序循环顺延（`buildSegConds`），预览可反复覆盖、所有玩家实时可见，看牌后锁定（`S.segCond`）。第 8 章第 4 关「往复」（id 32）例外：`fixedConds: true`，开局即按固定顺序生效，房主不可调整、界面不显示条件选择器。
- **第 7 章 4 关（id 25~28：入侵 / 引泉 / 同辉 / 三汲；rotate + 新机制「摸1张」）**：
  - 「摸1张」（条件 key `draw1`）：每次向该区域放牌后，放牌玩家从未加入游戏的备用牌堆摸 1 张进手牌 —— 本人立即可见数字（2 人局锁定期间的第一次行动也一样；摸到的牌插在锁定牌之前、不受锁定影响）；其他玩家只知其日月颜色（玩家条 ☀/☾ 计数 +1 自然暴露），日志只记「从备用牌堆摸取1张牌」（不写颜色/数字）。
  - 连锁摸牌：摸到的牌之后再放入「摸1张」区域会继续摸牌；备用牌堆 12 张摸完为止（摸完后再放牌不再触发）。
  - 结算判定（`ch7Check`）仅对约束型条件生效：`no789`（不含7、8、9数字牌）、`last`（最后1张牌放这里）、`maxMoonMinSun`（同区域含全场最大月亮牌与最小太阳牌）、`sunMoon2`（恰好 2 张太阳 + 2 张月亮，共 4 张）；`draw1` 无结算约束，基础三项（≥1张 / ≤24 / 递增）照常。
  - 条件集：入侵 [摸1/无限制/不含789/不含789/无限制/无限制]、引泉 [摸1/无限制/无限制/摸1/最后1张牌/无限制]、同辉 [无限制×3/最大月亮+最小太阳/摸1/太阳月亮各2张]、三汲 [无限制/摸1/无限制/摸1/无限制/摸1]。
- **第 8 章 4 关（id 29~32：顺流 / 双锁 / 三旋 / 往复；新机制「顺时针/逆时针旋转」与「无法放牌」）**：
  - 物理区域与区域编号分离：`S.segments`/`S.segCond` 按钟面物理位置存放，`S.segOrder[i]` 记录物理位置 i 当前显示的**区域编号**（开局为 1~6）。
  - 「顺时针旋转」（`cw`）/「逆时针旋转」（`ccw`）：每次向该区域放牌后，6 个区域的**规则与区域编号一起**整体旋转 1 格——顺时针 = 位置 i→i+1（6 号位回 1 号位），逆时针 = 位置 i→i−1（1 号位回 6 号位）；**牌留在原物理位置不动，但其所属区域编号随之改变**。例：在编号区域 1（规则 cw）放一张月亮 1，旋转后该牌位于编号区域 6，该位置的规则变为原区域 6 的规则（ccw）。
  - 「无法放牌」（`blocked`）：该区域不能放置新牌，但已放入的牌永久保留；旋转会把封锁连同编号移到相邻位置，原区域随之恢复可放牌，而新封锁位置同样保留其中的牌。UI 三层拦截：拖拽命中检测排除、确认抽屉按钮禁用（标注「无法放牌」）、`pickSeg`/`placeCard` 逻辑兜底。
  - 结算判定（`ch8Check`）：约束型条件 `sum16_20`（区域总和 16~20）、`exact1`（恰好 1 张）、`exact2`（恰好 2 张）按物理位置内的牌判定；条件项标签使用当前区域编号。「区域1→6总和递增」按**当前编号顺序**（`segOrder`）比较，而非固定物理位置。`blocked`/`cw`/`ccw` 无结算约束，基础三项（≥1张 / ≤24 / 递增）照常。
  - 条件集：顺流 [无限制/无法放牌/无限制/总和16~20/无限制/顺时针]、双锁 [无法放牌/无法放牌/顺时针/无限制/无法放牌/顺时针]、三旋 [仅1张/顺时针/顺时针/顺时针/须2张/无限制]、往复 [顺时针/顺时针/无限制/无限制/逆时针/逆时针]（固定，房主不可调整）。
  - 旋转动画：放牌触发后写入 `S.rotAnim = { dir, seq, turn }`（随状态同步），各端 `render` 尾部按 `seq` 播放一次——条件标签与区域编号角标一起绕钟面中心沿圆弧（60°）转到相邻位置（Web Animations API，0.46s），中心闪现 ↻/↺；`startAt` 变化（新一局）时把已存在的 `seq` 标记为已播，避免刷新/中途加入时重播。
- **章节锁定**：等候室章节/关卡上限按关卡库自动推导（当前已实现第 1~8 章、共 32 关）；超出 → toast「敬请期待」。
- 进度（赠送标记/是否通过）按关卡 ID（1~40）存本地 localStorage，以房主设备为准；**退出房间时仅重置未通关的关卡进度**（`confirmExitRoom` → `_olResetProgress`，清除当前 `challenge.id` 的赠送标记；已通过（`passed:true`）的关卡记录长期保留，不受退出影响），重建房间后从未通关挑战重新开始（`eyeBonus=0`）；房主「重试本关」不重置。

## 流程

1. **等候室**：房主选择章节(1-8)、关卡(1-4)，按关卡库展示该关名称与规则；2~4 人齐后开始。
2. **发牌+讨论**（phase=discuss）：展示钟面，牌背面朝下发给每人；玩家通过外部语音讨论策略，不能看牌。
3. **看牌**（phase=reveal）：仅房主可点「看牌」，此后每人可见自己的手牌，并显示「已看牌，禁止交流」提示。
4. **聚光灯选先手**（phase=spin）：房主启动，高亮在各玩家间循环 3 圈后自动停止（房主可提前停止），停中的玩家为先手。
5. **轮流出牌**（phase=play）：从先手开始按座位顺序，**拖拽出牌** —— 按住手牌拖到任意区域（暗置），松开弹确认抽屉「是否将 XX 牌放置到 XX 号区域？」（含眼标记勾选，用完不可再勾）；确认放置 / 取消保持牌在手牌区。若目标区域条件为「摸1张」，放置后放牌玩家摸 1 张备用牌（手牌增加，牌库有限、摸完为止），回合照常轮转；若为「顺时针/逆时针旋转」，放置后 6 个区域的规则与编号整体旋转 1 格（牌不动、所属编号改变）并播放旋转动画；「无法放牌」区域不可作为落点。全部打完进入可结算状态。
6. **结算**（phase=result）：**仅房主**点「翻开结算」（成员侧显示「等待房主翻开结算…」，`settle()` 带 isHost 守卫），自动翻开全部牌、计算各区域总和并判定通关，展示逐项检查结果。
   - 通关：回收赠送眼标记；未通关：赠送 1 个眼标记（累计 ≤3）供下次挑战本关使用。
   - 房主：通关 →「重试本关 / 下一关」双按钮；未通关 → 仅「重试本关」（同关卡重发牌）。
   - 「下一关」按 `challenge.id + 1` 从 `CHALLENGE_LIB` 自动初始化（第 4 关 → 下一章第 1 关）；无下一关（id=40）→ 弹窗「已通关所有章节」。

## 2 人局特殊规则（手牌锁定）

- 看牌（reveal）时只展示手牌**前 4 张**，后 2 张以背面显示并标注「暂锁定」。
- 双方合计打出 **4 张牌**（每边 2 张）后，后 2 张自动解锁，双方各自追加看到自己的牌。
- 锁定期间拖拽锁定牌无效（`handLockedIndexes()` 守卫 `cardDragStart`/`selectCard`）。
- 3/4 人局无锁定。

## 状态结构

```js
S = {
  players: [{ name, hand: [{ v, color:'sun'|'moon', revealed, by }] }], // by 为座位号
  phase: 'discuss' | 'reveal' | 'spin' | 'play' | 'result',
  challenge: { chapter, test, id, desc },  // desc 来自关卡库
  segments: [{ cards: [] } ×6],        // 已放置的牌
  reserve: [{ v, color } ×12],          // 备用牌堆（第7章「摸1张」用）
  segCond: [{ key, label, short } ×6] | null, // 转盘关：各物理位置的条件（看牌前可反复预览；第8章旋转时整体移动）
  segOrder: [1~6 ×6],                   // 第8章：各物理位置当前显示的区域编号（编号与规则一起旋转，牌不动、所属编号改变）
  firstSeat: null, currentSeat: 0, turnNo: 0,
  eyeBase: n, eyeBonus: 0, eyeUsed: 0, // 剩余 = base + bonus - used
  spin: { running, seat, tick },
  allPlaced: false, settled: false, pass: null,
  rotAnim: { dir:'cw'|'ccw', seq, turn } | null, // 第8章：最近一次规则旋转事件（随状态同步，驱动各端动画）
  rotAnimSeq: 0,                        // 旋转事件序号（本局内单调，render 按 seq 只播一次）
  sums: [n×6] | null, check: { segOK[], sumOK[], ascOK } | null,
  settleStamp: number,                  // 进度防重
  startAt: number,                      // 本关挑战开始时间戳（发牌时记录，结算时计算用时）
  log: [], gameOver: false,
}
```

本地（非共享）：`pendingPlay = { cardIndex, seg, useEye }`、聚光灯定时器。

## 联机架构

- `net.js`：Supabase 房间 CRUD + Realtime 订阅（`ROOM_PREFIX='taketime-'`，`MAX_PLAYERS=4`）。`netUpdateGameState` 内置 3 次重试（指数退避 400/800ms）并返回成功与否，杜绝 iOS 网络切换（Wi-Fi↔蜂窝）时的静默推送丢失；`createClient` 注入 `global.fetch` 统一 `cache:'no-store'`，防止 iOS WebKit 复用缓存的 GET 响应读到旧数据。
- `online.js`：状态同步、回合锁定、房主接管、刷新重连（`SESSION_KEY='taketime-online'`）。
- 手牌随共享状态广播（朋友间信任模式），UI 层**只渲染自己的手牌**，绝不渲染他人手牌。
- 推送守卫：出牌 = 当前座位；看牌/聚光灯/重开/下一关 = 房主；结算 = 结算者（先把自己的座位写入 currentSeat 保证 canPush 通过）。
- **断线自愈（前台僵尸连接 / iOS 后台挂起 / 网络抖动）**：
  - 频道状态回调（`netSubscribeRoom` 第三参）：`CHANNEL_ERROR`/`TIMED_OUT`/`CLOSED` → 2s 后自动重订阅；`SUBSCRIBED` → 拉取最新房间状态重同步（Realtime 不重放断连期间的事件，必须主动补拉）。
  - 生命周期恢复：`visibilitychange`（回前台）/ `online`（网络恢复）/ `pageshow(persisted)`（BFCache 返回）→ 限流 1.5s 重建频道 + 重同步。恢复时无条件重建频道（僵尸 WebSocket 会自报 SUBSCRIBED，仅靠状态判断不可靠）。
  - **定时轮询兜底（对齐神探缉凶/fugitive 在产方案）**：等候室每 2.5s（`POLL_WAIT_MS`）、对局中每 5s（`POLL_GAME_MS`）拉取一次房间状态——WebSocket 静默死亡且不自报任何状态（僵尸连接）时，事件驱动的恢复会漏掉，轮询是最终兜底；未确认的推送也会被轮询自动补发。轮询**不按 visibility 跳过**（对齐神探缉凶/fugitive 的无条件轮询）：前台也会静默死 WebSocket（Wi-Fi 漫游/NAT 老化/低电量模式掐 TCP 流，无需切后台），而 `visibilityState` 一旦滞留 `hidden`（WebKit 偶发）会让轮询永久停摆；真后台时系统本就挂起页面定时器，浏览器天然节流，无需额外守卫。等候室按内容签名重绘（`_renderWaitingIfChanged`：座位/选关未变零副作用，不重置选关交互），席位跟踪（`_syncSeatTracking`）兜住漏收的成员离开（实时行丢失也能弹接管/提示）；房间状态无变化时不重复应用（`_lastAppliedPushId` 守卫，避免周期性重渲染打断进行中的拖拽/动画）。
  - **推送串行化 + 粘性状态（对齐神探缉凶）**：`_pushInFlight`/`_pushQueued` 串行化——并发 UPDATE 竞速会让旧快照后到覆盖对方刚应用的新进度；在途期间只记标记，完成后重新取最新本地快照补发。补发携带粘性状态 `_pushStatus`（开局时 `startOnlineGame` 的 `'playing'` 推送常被 `dealGame` 的 saveState 推送挡在队列外，status 必须随补发送达，否则房间卡在 waiting）。
  - **未确认推送补发**：每次推送记录 `_lastPushPayload`（含快照），收到房间更新比对 pushId 确认；恢复时若房间序号（`turnNo`，全局单调）仍落后于本地未确认快照 → 原样补发；若已被更新状态取代则视为已解决。补发后不应用刚拉到的旧快照（本地才是最新）。`turnNo` 排序天然免疫设备时钟偏差。
  - **乱序/陈旧快照防护**：`_ts` 时间戳（3s 时钟偏差余量）+ `pushId` 去重 + `force` 标志（重同步拉取时强制应用权威状态）。pushId 含时间戳（`座位-ts36-序号`），避免刷新重连后 `_myPushSeq` 归零与旧推送撞车。
- **等候室选关同步**：房主选择关卡后写入 `pendingChallenge`（非共享，仅房主设备），经 `window._olRefreshWaitingRoom` → `room.state.pendingChallenge` → 成员端 `window._olPendingChallenge` 实时同步到等候室界面。
- **成员离开接管**：成员退出（seats 减少）→ 房主弹「接管操作 / 重置游戏」抽屉。点接管 → 离席座位写入 `S.departedPlayers` 并推送全端。此后轮到离席玩家时，房主以 `actionSeat()`（= 离席座位）代其查看/拖拽/放置手牌：`isMyTurn()` 对房主放行、`handLockedIndexes`/`selectCard`/`placeCard`/手牌区渲染/确认抽屉全部按 `actionSeat()` 取手牌，牌归属（`card.by`）与日志均记录离席玩家；成员端 `_olIsActor`/`isMyTurn` 不放行，保持观战。

## UI 布局（移动端）

```
┌──────────────────────────────┐
│ 标题                  🚪退出 │
│ 日志（仅最后一行，点击后展开）  │
│ 规则横幅（当前关卡 desc）     │
│ ┌──────────────────────────┐ │
│ │      钟面（6区域环形）     │ │
│ │     中心: 眼标记/提示      │ │
│ └──────────────────────────┘ │
│ 玩家条（颜色点/名字/手牌数/高亮）│
│ 手牌区（仅自己；接管时显示被接管玩家手牌）│
│ 操作区（按阶段切换按钮）       │
└──────────────────────────────┘
```

- **着陆页**（简化）：居中 🕰️ 图标 + 标题 + 副标题 + 联机入口按钮 + 底部 `@imStar100`；右上角「📜 规则」按钮弹出规则弹层（`showRulesModal`，含游戏说明与通关判定）。
- **卡牌配色**：太阳牌正面米金底黑字 + 金边，月亮牌正面深蓝底白字 + 蓝边；正面与牌背同底色（仅数字/图标区分）；`card` / `card-big` / `mini-card` 三处一致。
- **牌背**：手牌背面与桌面暗置牌同一套 UI —— 按日/月显示 ☀/☾ 符号 + 对应底色（太阳米金底 / 月亮深蓝底），隐藏数字；2 人局锁定牌同样显示日/月牌背。
- **桌面牌展示**：区域内已放置牌与手牌同款样式（横置），明置/暗置混合横排，多张按比例缩放并自动换行（`.seg-cards` flex wrap，`aspect-ratio:2/3`），保留 ☀/☾ 图标与数字（暗置无数字）。
- **动效（game feel）**：
  - 聚光灯：命中玩家 chip 金色呼吸光环（`spotlight-pulse`），未命中玩家变暗聚焦；转动步进 170ms（3 圈约 1~2 秒）。
  - 出牌：新放置/翻开的牌 pop 入场（squash & stretch `card-pop`，`fresh` 标记驱动，全端同步；`fresh` 在 `render()` 末尾统一清除，**只在首次入场播放一次**，后续 render 不重放）。
  - 明置牌：金色微光（`.lit`）；轮到你的提示呼吸脉冲（`turn-pulse`）。
  - 结算：面板 slide-up 进场；失败附加轻微抖动（`shake-x`），成功附加绿色光晕（`glow-pass`）。
  - 第 8 章规则旋转：条件标签与区域编号角标一起沿钟面圆弧（绕中心 60°）从旧位置飞到新位置并轻微缩放（`playCondRotateAnim`，0.46s，飞行中金色高亮 `cond-rot-fly`），钟面中心闪现 ↻/↺（`rot-flash`）；「无法放牌」区域虚线红框 + 🚫 角标（`.seg-blocked`），条件标签红色（`.seg-cond.blocked`），旋转规则标签蓝色（`.seg-cond.rot`）。
  - 布局稳定：玩家标签（🎯/先手）绝对定位不占高度，聚光灯转动不挤压玩家条。
- **拖拽出牌（pointer 事件状态机）**：
  - 手牌 `.card { touch-action:none }`；`pointerdown` → 移动 >8px 阈值后创建 ghost（`cardDragStart` 缓存各区域圆心/半径，只挂一次全局 move/up 监听）。
  - ghost 为 `position:fixed; left:0; top:0` 的 64×96 浮层，`transform: translate(x,y) rotate(-4deg)` + `will-change:transform` 跟手（显式像素偏移，不依赖 left/top 与百分比 translate）；原卡缩放变暗（`.dragging`）。
  - 松手落点用**数学点圆检测**（缓存圆心 + 半径，`d <= r*1.1`）命中区域 → `.drag-hover` 金色高亮放大 → 弹确认抽屉；未命中任何区域则原样回弹（仅 render，无副作用）。
  - **性能策略**：ghost 用 transform（合成层）而非 left/top（避免 Layout），无 transition 跟随；每帧 hit-test 不查询 DOM（缓存 rects + 点圆数学），避免 `elementFromPoint`。
  - 确认抽屉（`.playSheet`）：slide-up 弹层 + 遮罩；标题含卡牌大图与「是否将 XX 牌放置到 XX 号区域？」；下方眼标记勾选 + 「确认放置/取消」；取消或遮罩关闭 → `closeSheet()` 清 `pendingPlay` 并 `render()` 清除 `sel` 高亮。
- **规则弹层**：`showRulesModal` 底部弹层 slide-up 进场，内含游戏说明与通用通关判定。
- 区域：圆形（`position:absolute; width:30%; height:30%` + `border-radius:50%`，显式等宽高保证正圆），显示编号、已放置牌（明置显示数值卡+微光，暗置显示日/月牌背）、可见总和；结算后显示最终总和与全部牌。
- **规则横幅**：`.clock-rule` 显示在 `.clock-wrap` 上方（居中，max-width 400px），内容为当前关卡 `desc`；钟面中心不再显示关卡规则。
- **日志折叠**：`.log-box` 仅显示最后一条日志，整行可点击弹抽屉（`showLogModal`，`.log-more` 箭头已隐藏）查看完整日志列表（`log-list` 纵向排列）；抽屉支持遮罩点击关闭。
- **结算隐藏手牌**：`action-box` 可见（结算环节）时隐藏 `hand-box`（此时必无手牌）。
- 看牌后各阶段显示「🔇 已看牌，禁止交流」提示；讨论阶段提示「💬 看牌前请用语音讨论策略」。
- 阶段操作：
  - discuss：房主「🔍 看牌」/ 他人提示等待
  - reveal：房主「🎯 启动聚光灯」
  - spin：房主「⏹ 停止聚光灯」
  - play：当前玩家**拖拽手牌**到区域 → 确认抽屉（确认放置/取消）；全部打完显示「🧮 翻开结算」（仅房主，成员侧显示等待文案）
  - result：逐项检查结果 + 房主「🔄 重试本关」/「⏭ 下一关」（仅通关后显示）
